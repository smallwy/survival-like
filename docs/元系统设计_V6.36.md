*2026-10-13 ｜ 方向已定：先补 L2 ｜ 配套：项目计划书 §5.4 / §11、深度玩法路线图 V6.34 §5*

## 0. 一句话结论

**L2 现在只有"记分板"，没有"解锁引擎"** —— 加一层跨局货币 + 解锁集 + 图鉴容器，把 `profile.ts` 从 v1 升到 v2，让"死一局 = 白玩"变成"死一局 = 攒了东西"。**这是把"几分钟吸引力"变成"再来一局"性价比最高的一刀，且不动任何局内战斗数值。**

## 1. 现状诊断（拿代码说话）

| L2 子系统 | 现状 | 证据 |
|---|---|---|
| 档案存储 | ✅ 有 | `shared/dive/profile.ts` v1 + `view/save.ts`（sys.localStorage，key `sgr.profile.v1`） |
| 纪录 | ✅ 有 | 6 字段：bestBiomass / bestLayer / bestWave / runs / cleared / lastSub |
| 结算合并 | ✅ 有 | `DiveGame.finishRun()` → `applyRun()` → `saveProfile()` |
| 标题屏战绩 | ✅ 有 | `Title.setRecords(depthLabel(...))` |
| **跨局货币** | ❌ **无** | 生物质出局即丢，只留 `bestBiomass` 一个数字 |
| **解锁集** | ❌ **无** | 3 台潜航器全解锁、武器/遗物从一开始就能抽 |
| **图鉴容器** | ❌ **无** | 没有"见过/拥有过什么"的记录 |
| **里程碑** | ❌ **无** | 只有 `cleared` 一个布尔 |
| 解锁查看入口 | 🟡 占位 | `Title.showDock()` 明确写着"尚未接入，点击任意处关闭" |

**结论：存储层是干净的（纯函数可测、读写分离、逐字段容错），扩字段的成本很低。缺的全是"往上盖的逻辑"。**

## 2. 数据模型：`profile.ts` v1 → v2

### 2.1 字段扩展（**只加不改**，旧的 6 个字段语义原样保留）

```ts
export const PROFILE_VERSION = 2

export interface Profile {
  v: number
  // ---- v1 原样保留（迁移时不丢）----
  bestBiomass: number
  bestLayer: number
  bestWave: number
  runs: number
  cleared: boolean
  lastSub: SubId
  // ---- v2 新增 ----
  bio: number                      // 跨局货币（沉淀生物质），持久
  totalBanked: number              // 累计沉淀（用于条件判断，如"累计上浮 10 次"）
  surfaced: number                 // 成功上浮兑现的局数（溺水不计）
  unlocks: string[]                // 已解锁项 id 集合（UnlockId，见 §3）
  seen: Record<string, number>     // 图鉴：id → 遇见次数（>0 即"已见"）
  milestones: string[]             // 已达成的里程碑 id
  normalClears: number             // 通关次数（将来难度阶梯用）
}
```

**为什么 `unlocks` / `milestones` 用 `string[]` 而不是 `Set`**：JSON 不认 Set，序列化会变成 `{}`（静默丢数据）。存数组、用时 `includes`，档案量级只有几十条，无性能问题。

### 2.2 迁移策略（v1 → v2）

`normalizeProfile()` 已经是"逐字段回退"的，扩字段后天然兼容：
- v1 存档读进来 → 新增字段全走默认值（`bio: 0` 等），**旧纪录一个不丢**。
- `KEY` 从 `sgr.profile.v1` → **`sgr.profile.v2`**，且读档时**先读 v2、没有再回落到 v1 并迁移**。
- 迁移只在内存里做，第一次 `saveProfile` 落盘成 v2。**旧 key 不删**（回滚保护）。

```ts
// save.ts
const KEY = 'sgr.profile.v2'
const KEY_V1 = 'sgr.profile.v1'   // 只读，用于迁移；不写、不删
```

**红线**：迁移函数必须是**纯函数、可测**（`migrateV1toV2(raw)`），因为"存档迁移写错"是唯一会让老玩家进度全灭的错误。

## 3. 解锁设计（对齐计划书 §5.4 四类）

计划书 §5.4 已定四类解锁。逐条落成**可判断的条件**：

### 3.1 潜航器（`sub:*`）

| id | 条件 | 依据 |
|---|---|---|
| `sub:lumen` | 默认解锁 | 起始艇 |
| `sub:raia` | 累计 **上浮兑现 ≥ 5 次** | "会用上浮的人"才解锁机动艇 |
| `sub:bathy` | 最深抵达 **L4**（layerIdx ≥ 3） | 深层玩家才解锁"少氧多槽"的硬核艇 |

### 3.2 武器（`weapon:*`）

7 族基础武器。默认开 3 族（gun / harpoon / echo），其余按**图鉴解锁**（计划书原话"击杀特定敌人"）：

| 武器 | 条件 |
|---|---|
| `weapon:gun` `harpoon` `echo` | 默认 |
| `weapon:torpedo` | 图鉴集齐钙壳族（击杀 tank ≥ 20） |
| `weapon:arc` | 用回声武器击杀 ≥ 80 |
| `weapon:sonar` | 图鉴集齐胶质族 |
| `weapon:acid` | 抵达 L3 |

⚠️ **落地风险**：武器锁定 = 从商店抽池里**移除**。必须改 `pool.ts` 的抽取逻辑吃一个"已解锁集"参数，否则锁了也照抽。**这是本方案唯一动到局内的地方，要小心**。（也可选：只锁"商店出现"，不锁"进化分支"。）

### 3.3 遗物（`relic:*`）

12 个遗物：默认 6，其余 6 按里程碑解锁（例：`导体缠绕` ← 累计回氧 ≥ 5000；`过载核心` ← 单局满级武器 ≥ 3 把）。

### 3.4 永久强化（`perk:*`）—— **bio 购买，上限受控**

计划书红线："上限受控，避免破坏局内随机性"。定死：

| 项 | 每级 | 封顶 | 满级总增幅 | 价格（bio/级） |
|---|---|---|---|---|
| 装填效率 | 攻速 +2% | 5 级 | **+10%** | 40 / 60 / 80 / 100 / 120 |
| 结构强化 | 氧上限 +3 | 5 级 | **+15** | 40 / 60 / 80 / 100 / 120 |
| 声呐调校 | 拾取 +4% | 5 级 | **+20%** | 40 / 60 / 80 / 100 / 120 |

**设计依据**：单局内武器伤害升级是 +35%/级、遗物是 +12%~+50%，所以永久强化**满级总增幅必须 ≤ 单局单件装备的量级**，否则"氪金感"就出来了（计划书 §11 第一条差评来源）。上面三项满级合计约等于"白送两个遗物"，是"起步更顺"而不是"变强"。

### 3.5 图鉴（`codex`）

记录四类：**敌人 / Boss / 武器 / 遗物**。只记录 `seen[id]++`，**绝不产生战力**。

- 敌人：每次生成敌人时 `seen['enemy:'+kind]++`
- Boss：击杀时记录
- 武器 / 遗物：装备或出现过就记

| 行 | 内容 | 字号 / 色 |
|---|---|---|

| **解锁提示行** | `解锁：刺鳐` 或 `新标本 ×3` | 16px `TXT.jade`（无则整行不画） |

**位置**：接在"新纪录"行下方（H/2+82），公式行与层波行不动。**不画 = 不留空行**（沿用现有"record 为 null 就不画"的惯例）。

⚠️ **溺水时的沉淀语义**：溺水 = 生物质全损（`finalBio = 0`）→ **沉淀也是 0**。结算屏要显式写"无沉淀"，否则玩家不知道"浅捞一点上浮"和"全损"的区别，反而削弱 §10 那条止损线。

## 5. 三条红线（跟计划书 §11 对齐）

1. **绝不做局外氪金直加局内强度**。永久强化满级总增幅 ≤ 单局单件装备量级（§3.4 已定死数字）。
2. **沉淀率 ≤ 25%**。带出生物质 × 0.25 进 bio，其余 75% 是"这一局的成绩"。太高会杀死"下潜 vs 上浮"的取舍（§10 止损线的命脉）。
3. **图鉴只记录、不产生战力**。图鉴完成度**不能**变成隐性加成，否则就变成"收集换战力"，与红线 1 同源。
