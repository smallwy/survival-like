# 局内暂停菜单 · 规格（v6.39）

> 生成日期：**2026-10-13 晚** · 依据版本：Cocos Creator **3.8.8**
> 实现位置：`cocos/assets/scripts/view/DiveGame.ts`（状态与输入）＋ `cocos/assets/scripts/view/Hud.ts`（绘制）

## 0. 先讲清：这是一个可用性缺陷，不是「加个功能」

改前的事实（`DiveGame.ts` 战斗分支）：

```ts
if (k === KeyCode.ESCAPE) this.restartRun()   // ← 把「退出」写成了「重开」
```

而 `toTitle()`（回主界面）**只被结算屏调用**。两件事叠起来的后果：

| 玩家的意图 | 实际发生 |
|---|---|
| 打得顺，想退出 | **没有任何路径** —— 只能自杀，或者硬撑到死 |
| 按 ESC 想退出 | **白打一局重开**（更糟） |
| 触屏玩家想退出 | **一个出口都没有**（ESC 是键盘专属） |

所以这份规格要解决的是「**局内必须有出口**」，顺带把「ESC = 重开」这个反向行为纠正掉。

## 1. 入口（两条，缺一不可）

| 入口 | 触发 | 为什么必须有 |
|---|---|---|
| **ESC 键** | `KeyCode.ESCAPE` | 桌面玩家的习惯路径 |
| **暂停按钮**（HUD 右上角常驻） | 点击 / 触摸 | **触屏的唯一出口** —— 只做 ESC 等于没解决 |

### 1.1 暂停按钮尺寸

| 项 | 值 | 依据 |
|---|---|---|
| 视觉尺寸 | **38 × 38** | 再大就压到鱼骨与生物质（HUD 右上角本来已排满） |
| 圆角 | **9** | 与 HUD 其它按钮同族（装备槽也是 9） |
| 热区 | **64 × 64** | **视觉与点击区分离**。38px 在触屏上够不着；触屏推荐下限 88 做不到（会压鱼骨），**64 是"能不误触的最小折中** |
| 中心位 | `(W − 32, 30)` | 贴右上角，留 13px 内边距 |
| 图形 | **矢量两条圆角竖杠**（`UI.cyan` α0.92，5.5 × 18，间隔 4） | 暂停是个**纯 UI 符号**、要随状态换色；做位图反而多一层。与"沉淀货币留矢量"是同一条分工线（§7.2） |

**连带改动（必须一起做，否则重叠）** —— 鱼骨与生物质整组左移让角：

| 元素 | 原位置 | 新位置 |
|---|---|---|
| 鱼骨图标 | `W − 106` | **`W − 150`** |
| 鱼骨数值 | `W − 88` | **`W − 132`** |
| 生物质（右对齐） | `W − 24` | **`W − 64`** |

> 三处仍是左 / 右对齐，**位数变化时整组不左右抖动**（原有约定不变）。

## 2. 暂停菜单（两态）

### 2.1 公共部分

| 项 | 值 | 依据 |
|---|---|---|
| 遮罩 | **`scrim(0.74)`** | **半透明压暗，不是实黑** —— 暂停时背后的战场要看得见，玩家才知道自己停在哪一帧 |
| 面板底 | `MENU.page` α **0.96**，圆角 **16** | 与商店 / 结算同一套弹窗语汇（不新开皮肤：同一个游戏里的弹窗要长得一样） |
| 面板描边 | `MENU.edge` α0.95 / **1.5px** | 同族 |
| 标题栏分隔线 | `UI.cyanDim` α0.7 / 1px，位于 `py + 62` | 同族（商店、结算都有这条） |

### 2.2 菜单态（面板 **440 × 344**）

| 元素 | y（相对面板顶 `py`） | 规格 |
|---|---|---|
| 标题「已暂停」 | `+32` | 26px · `TXT.cyber` |
| 副标「氧气 x / y · 敌人与计时已冻结」 | `+84` | 14px · `TXT.dim` |
| 按钮 1「继续游戏」 | 屏心 `−14` | **288 × 50** |
| 按钮 2「重新开始」 | 屏心 `+56` | 288 × 50（节距 **70** = 50 高 + 20 间隙） |
| 按钮 3「返回主界面」 | 屏心 `+126` | 288 × 50 |
| 底部提示「ESC 继续游戏」 | `py + 344 + 28` | 13px · `TXT.mute` |

- **「继续」排第一**：ESC / 再点按钮都是"继续"，默认动作应该在最容易点到的地方。
- **「重新开始」收进菜单**：原来它绑在 ESC 上（一按就重开），是最容易误触的位置。
  挪到菜单里当第二项 = **多一层确认，也少一次误触丢局**。

### 2.3 二次确认态（面板 **440 × 292**）

| 元素 | y | 规格 |
|---|---|---|
| 标题「返回主界面？」 | `py + 32` | 24px · **`TXT.warn`**（琥珀 = 警示，不是错误红） |
| 主句「本局进度将丢失」 | `py + 84` | 16px · `TXT.main` |
| 说明「本局带出的生物质按 0 计 · 已沉淀的部分不受影响」 | `py + 112` | 13px · `TXT.dim` |
| 按钮「取消」 | 屏心 `+58`，x `−104` | **188 × 50** |
| 按钮「确认返回」 | 屏心 `+58`，x `+104` | 188 × 50 |

> **为什么必须二次确认**：一局可能已经打了几分钟，误点一脚回标题 = 白打。
> 而且这句说明要说清"**损失的是什么**"（本局带出的）与"**不受影响的是什么**"（已沉淀的）——
> 只说"进度将丢失"会让玩家以为**沉淀也一起没了**，反而不敢退出。

## 3. 状态机与交互规则

```
战斗中 ESC / 点右上角 ──▶ 暂停菜单 ──┬─ 继续游戏 ──▶ 战斗
                                    ├─ 重新开始 ──▶ 新一局
                                    └─ 返回主界面 ──▶ 二次确认 ──┬─ 取消 ──▶ 暂停菜单
                                                                  └─ 确认返回 ──▶ 主界面
```

| # | 规则 | 为什么 |
|---|---|---|
| 1 | 暂停时 **`world.update()` 完全不调用** | 敌人不动、氧气不掉、技能冷却不走、特效不衰减 —— 这才是"暂停" |
| 2 | 暂停时 **仍然绘制**（只跳过"推进"） | 画面停在上一帧的样子，而不是被清成黑屏。`Graphics` 是累积顶点，不 clear 会一直留在屏幕上（标题界面注释里记过同一个坑） |
| 3 | 开暂停时 **清空 `keys`**（left/right/up/down/burst + `burstEdge`） | 否则暂停时按住的 W/A/S/D 会留在表里，**恢复后机体自己一直往那个方向漂** |
| 4 | 暂停时 **按键整体接管，只认 ESC** | 比"逐个屏蔽"省事且不会漏（标题界面用的是同一套路，注释里写了原因） |
| 5 | `ESC` 在 **`result` 阶段无效** | 结算屏已经结束，没有"暂停"可言 |
| 6 | 商店 / 补给站阶段 **也能叫出菜单** | 那是玩家最想退出的时刻（"这局开局崩了，想重来"） |
| 7 | `toTitle()` / `restartRun()` / `startRun()` 都要 **清 `paused` 与 `pauseConfirm`** | 不清的话回到主界面还带着暂停态，开局直接是"暂停中" |

## 4. 与现有系统的边界

| 关系 | 说明 |
|---|---|
| `toTitle()` | **复用，不新增**。之前只有结算屏调它，现在多一个调用方 |
| `restartRun()` | **复用**。从 ESC 挪到菜单第二项 |
| 弹窗语汇 | **复用**商店 / 结算的 `MENU.page` 实底 + 描边 + 标题栏线，**不新建面板样式** |
| 绘制位置 | `drawPause()` 写在 `DiveGame.update()` 的四个阶段分支**之外**（末尾追加）—— 四个分支一行没动，暂停只是"多盖一层" |
| 与图鉴弹窗 | 两者都可以打开，但**不同时**：图鉴只在标题界面开，暂停只在局内开 |

## 5. 待定 / 未做

| 项 | 状态 |
|---|---|
| 暂停菜单里的「设置」（音量 / 画质） | **未做** —— 项目当前没有音量与画质系统，放进去是个空壳 |
| 「放弃本局结算」（按已完成进度结算一次沉淀） | **未做** —— 需要额外的结算规则（算不算这一层的波次？算不算 boss？），属数值策划，不是 UI |
| 触屏 88×88 点击区下限 | **已让步**（实际 64）。要在移动端上架时，右上角需要重排（把鱼骨/生物质挪到别处），才能做到 88 |
