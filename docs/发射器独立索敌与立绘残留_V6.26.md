# V6.26 — 发射器独立索敌 + 商店立绘残留

用户报了两条：

1. 「选择发射器之后 场景中还有遗留」
2. 「现在发射器好像不会选择就近射击 会受上下左右移动影响。发射器和装置器是独立的，
   发射器自己选择目标射击 是很自然的。现在我发现我移动上面 就一直射击上面」

两条都是**真 bug**，根因都在代码里，下面各写清楚。

---

## Bug ① 商店立绘离开商店后没被收走（残留）

### 现象与证据
用户截图红框里漂着一件武器 —— 放大后确认是**商店中卡那张武器的立绘**
（`item_*.png`，透明底，跟着镜头漂、还压在战斗画面上）。

### 根因
`shopArt`（3 个常驻 `Image`，depth **95** —— 比鱼 40 / 机体 60 / 炮塔 62 都高）的
"全部隐藏"只写在两个地方：

| 位置 | 执行条件 |
|---|---|
| `drawShop()` 第一行 | 只在 `phase === 'shop'` 时跑 |
| 渲染主流程的弹窗分支 | 只在 `phase === 'shop' / 'decide' / 'result'` 时跑 |

而**离开商店**走的是 `leaveShop() → startWave()`，`phase` 直接变成 `'wave'`
—— 这一帧两个隐藏路径**都不执行**。上一帧（商店的最后一帧）刚被点亮的立绘
就永远停在 `visible = true`，从此冻在世界里。

这解释了为什么截图里只有 **一张**：卡片是随机牌面，只有带立绘的卡才点亮，
另外两张本来就是隐的。

### 修法
显隐归**相位**管，不归 `drawShop` 管 —— 把"全隐"提到相位分派之前：

```ts
if (this.phase !== 'shop') for (const im of this.shopArt) im.setVisible(false)
if (this.phase === 'shop') this.drawShop(this.g)
```

`shop` 这一帧仍是例外（由 `drawShop` 自己逐卡点亮），其余任何相位都强制全隐。
顺带删掉了弹窗分支里那句重复的隐藏。

## Bug ② 发射器被"移动方向"绑架

### 根因（一句话）
炮塔角写成了 **`机体朝向 + clamp(目标角 − 机体朝向, ±70°)`**。

`this.aim` 就是**移动方向**（`movePlayer` 里 `atan2(dy, dx)` 直接赋值）。
所以"打谁"这件事被"往哪走"限死在一个 ±70° 的扇面里：

- 往上游 → 全船炮只能在上方 ±70° 里挑目标，下方的鱼**看得见打不着**；
- 停在原地不动 → `aim` 冻结，炮口就跟着冻在那个方向。

实测（验证脚本 T2，敌人在正下方 300px、船舵朝上）：

| 武器 | 旧公式误差 | 新的误差 |
|---|---|---|
| gun | **1.862 rad（107°）** | 0.000 |
| torpedo | **1.862 rad** | 0.000 |
| harpoon | **1.789 rad** | 0.000 |
| arc | **1.789 rad** | 0.000 |

即：旧代码在任何情况下都**不可能**打到那个目标，偏了 100° 以上。

### 修法
发射器改成**自己索敌的独立部件**，与装载器解耦：

1. `Weapon` 新增 `aimAng`（弧度）—— 这座塔**自己的世界朝向**。
2. 新增 `slewTurretAims(dt)`，每帧执行（`movePlayer` 之后、`autoFire` 之前）：
   - 以**自己的座圈坐标**为原点（新增 `nearestEnemy(range, ox, oy)` 支持指定原点），
     找射程内最近的敌人；
   - 目标方向与当前角度的差做**指数逼近 + 角速度上限**（`TURRET_SPIN = 16 rad/s`，
     180° 掉头约 0.2s）→ 炮口是**转**过去的，不是"啪"地弹过去；
   - 射程内没目标 → 回到艇首方向待机。
3. `turretPose()` 与 `drawSub` **都直接读 `w.aimAng`**，不再各算一套限幅公式。
   （原来两处各写了一遍同样的式子，属于"改一处必须手动同步另一处"的隐患。）
4. 删掉 ±70° 限幅 —— 旋回部现在可以转到任意角度，装载器（座圈）仍随艇身转。

结果就是用户要的那个语义：**装载器 = 座圈，跟着艇身转；发射器 = 旋回部，自己找鱼**。

### 可调参数（还没定稿，用户玩过再定）
`TURRET_SPIN = 16`（rad/s）：嫌转头太"飘"可以降到 10~12；嫌跟不上鱼可以提到 20+。

## 验证（`tools/verify_v626.py`，7/7 通过）

无头 Chrome + CDP 实机跑，不是"看起来对"：

```
=== T2 发射器独立索敌（敌人正下方 300px，船舵朝上）===
   gun        新误差 0.000 rad | 旧公式误差 1.862 rad
   torpedo    新误差 0.000 rad | 旧公式误差 1.862 rad
   harpoon    新误差 0.000 rad | 旧公式误差 1.789 rad
   arc        新误差 0.000 rad | 旧公式误差 1.789 rad
  [通过] 每座塔都转到了自己最近的敌人（误差 < 0.15 rad）
  [通过] 旧公式在同一输入下被限幅绑架（至少一座偏 > 1.0 rad）
  [通过] 画塔与出弹共用同一角度源（turretPose == aimAng）

=== T1 商店立绘残留（离开商店后必须全隐）===
  [通过] 商店里立绘是亮的（说明这一帧确实走过 drawShop）  亮着 1 张
  [通过] 离开商店后进入战斗相位  phase=wave
  [通过] 战斗相位下商店立绘全部不可见  仍亮着 0 张
```

两处断言设计上的小心思：

- T2 不只断言"新代码对"，还**同时算出旧公式在同一输入下的误差**并要求它 > 1.0 rad
  —— 证明这确实是个被修掉的真 bug，而不是"改了个写法"。
- T1 的前置条件是"商店里确实有立绘亮着"。第一次跑失败过一次，原因是随机牌面
  恰好翻到三张没立绘的卡 —— 那测的是随机数不是代码，已改成先重抽到有立绘再断言。
