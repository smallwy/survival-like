## 2. 适配模型：fitHeight + 锚点重排（最要紧的一条）

### 2.1 现状为什么不行

`fitWidth=true / fitHeight=false` + 内容框写死 1304×749 ⇒ **可见设计高 = 1304 ÷ 实际宽高比**：

| 窗口宽高比 | 可见设计高 | 相对 749 | 后果 |
|---|---|---|---|
| 21:9（2560×1080） | **550** | −199 | 上下各裁 **≈99px** ⇒ 菜单末行 + 面板被切 |
| 16:9（1920×1080） | 733 | −16 | 上下各裁 8px（擦边，尚未伤内容） |
| 16:10（1920×1200） | 815 | +66 | 上下多 33px 空白 |

⇒ 见基准图左半：红色区就是被裁掉的部分。

### 2.2 新模型：**保高、宽度用锚点吸收**

`fitHeight = true`（高度永远完整可见），横向元素一律**锚到视口边**，不用"距左边固定 x"。

| 元素 | 锚点 | 规则 |
|---|---|---|
| 顶栏（头像 / 按钮 / 货币） | 上 + 左 / 右 | 头像锚左、按钮组锚右，纵向贴顶 |
| 底栏（提示行） | 下 + 左 / 右 | 贴下边，左右各自内缩 |
| 菜单左右列 | 左 / 右 + 垂直居中 | 贴左右边；**垂直中心 = 视口高的中心**（不再写死 y=392） |
| 中央主形象（船坞） | 居中 | 视口中心 |
| 右下「开始游戏」 | 右下 | 贴右下角，内缩 = 安全区 |
| 「出击准备」面板 | 居中 | 固定尺寸居中；视口不足时按 §2.3 收缩 |

### 2.3 最小窗口（**由面板反推，不是拍脑袋**）

面板宽 1040，两侧各留安全区 32 ⇒ 需要可视设计宽 ≥ **1104**。
在 720 高的窗口上（fitHeight，scale = 720/749 = 0.961）⇒ 最小物理宽 = 1104 × 0.961 ≈ **1061**。

⇒ **最小窗口定为 1280×720**（16:9，留余量）。低于此值时面板按 `k = min(1, 可视宽 / 1104)` 等比收缩。

## 3. 设计基准：**建议保持 1304×749 不动**

你说"允许改"，但我建议**不改**——理由三条：

| 理由 | 说明 |
|---|---|
| 它其实是"1× 窗口"基准 | 749 ≈ 720p。窗口在 720–1080 高的区间里，缩放系数 0.96–1.44，**字号绝对值 ≈ 屏幕 px**，与你「正文不低于 12px」的规约天然对齐 |
| 它是 **sim 坐标系** | `DiveGame.designW/designH` 同时是**世界与 UI** 的坐标空间。改成 1920×1080 = 全部世界/美术/挂点常量重导（`SUB_D`/`HULL_H`/`SEAT_MOUNTS`/所有 `px` 常量…）⇒ 高风险，且**改漏不报错** |
| 收益不成立 | 改基准想换的是"整数缩放"，但只要窗口可自由缩放，**任何基准都会遇到非整数系数**（1366×768 之于 1920 是 0.711）⇒ 换不来确定性收益 |

⇒ **只改适配模型与字号阶梯，基准不动。**（若你坚持要换，我按 §7 给一份"全局重导清单"再评估。）

## 4. 字号阶梯：13 个 → **5 档**

### 4.1 现状的问题

`FS` 声明 6 档（12/13/15/17/20/26），但 `Title.ts` 实际用了 **13 个字号**；
且 **12→13 只差 1px，直接违反 `Hud.ts:79` 自己写的"相邻档差 ≥2px"**。
12–17 这 6 个字号按项目判据只有 2–3 档可辨识 ⇒ **玩家读不出"谁更重要"**。

### 4.2 新阶梯（5 档，相邻档差 ≥3px）

| 档 | 设计px | 用途 | 合并自 |
|---|---|---|---|
| `display` | **64** | 游戏标题（唯一） | 64 |
| `h1` | **28** | 面板标题 / 主按钮 / 货币数值 | 26 · 28 · 24 |
| `h2` | **22** | 卡片主名（艇名 / 武器名） / 次按钮 | 22 · 20 · 18 |
| `body` | **16** | 菜单入口标签 / 档案行 / 卡片副名 / tag | 16 · 17 · 15 · 14 |
| `small` | **14** | 说明行 / 特性行 / 底栏提示 / 「沉淀」 | 14 · 13 · 12 |

**`small = 14` 的依据（★ 相对本文件初稿从 13 上调）**：
① 最小窗口 720 高时 scale = 0.961 ⇒ 14 × 0.961 = **13.5px**（守住 12px 下限）；
② `theme.ts:275` 写死「**14px 以下的中文会糊成一团 —— 禁用**」⇒ **中文的下限就是 14**，13 会违反这条既有规则；
③ 顺带修一处**现存矛盾**：当前 `FS.micro = 12` / `FS.body = 13` / 武器说明 `12` **都低于 14**，与 `theme.ts:275` 打架 —— 新阶梯把**中文一律抬到 ≥14**，`micro 12` 只留给**纯数字/符号角标**。

> ★ **架构建议**：`FS` 目前被**战斗 HUD 与主界面共用**（`Hud.ts:81`）。为让两边**能分批改**，本规格给主界面/出击准备单开一套 `TitleFS`（§8），`FS` 暂不动 —— 否则改主界面会连带动战斗内 UI。

> ⚠️ `FS` 同时被战斗 HUD 使用（`Hud.ts:81`）⇒ 改它会**连带改战斗内 UI**，需一并确认（HUD 另有自己的占用率核算，见 `docs/UI规格_赛博霓虹.md`）。

## 5. 点击区：统一到一档下限

| 元素 | 现状 | 改为 | 依据 |
|---|---|---|---|
| 面板关闭叉 | **44×44** | **48×48** | 现状**低于项目自定下限 48** |
| 顶栏按钮 | 视觉 40 / 点击 48 | 48 / 48 | 视觉 = 点击，少一层映射 |

| 主按钮 / 菜单块 | 62 / 80–96 | 不变 | 已达标 |

⇒ 桌面口径 **48×48**；若将来上触屏，全部提到 **88×88**。

## 6. 栅格与安全区（新增，现状缺失）

| 项 | 值 | 依据 |
|---|---|---|
| 栅格基数 | **8px** | 现有常量几乎都是 4 或 8 的倍数（32/80/88/96/160/236/312），只有 749 与 132 不是 ⇒ 统一到 8 |
| 安全区 | **四周 32** | 与现有 `BAR_PAD = 32` 同源；顶栏/底栏/面板全部内缩 32 |
| 层级 | 背景 / 内容 / 浮层 / 弹窗 / 引导 | 现有 `modal` 机制已实现弹窗层，其余沿用 |
