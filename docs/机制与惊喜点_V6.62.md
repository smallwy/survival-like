## 0. 一句话

**V6.49 §3/§4/§5 的全部内容都已落地 —— 但真正花时间的不是"加机制"，是三处"静默死锁/静默无敌"的坑，和六处"状态读不出来"的表现。**

这一轮改的是**反馈通道**，不是加系统：网和雷本来就有，从"软控 + 被动"改成"硬控 + 可预判"；敌人从"3 类 + 1 Boss"补到"4 类 + 2 Boss"；收益从"完全可预测"加了两条随机通道。

## 2. 撒网定身（§3.1）

### 2.1 数值与依据

| 项 | 值 | 为什么是这个值 |
|---|---|---|
| 定身时长 | **1.2s** | 够把火力倾泻上去，又不至于把敌人钉死。网 `iv` ≈ 1.1s ⇒ 2 张网能覆盖 2.4s，是"控场"的合理上限 |
| 免疫窗口 | **3.0s** | **配平红线**。无它 ⇒ 单体被定时间 ≥40%（1.2 / 3.2 周期），一屏 150 敌定住 40 只 = Bullet Heaven 变靶场。3.0s = "被定一次后至少要过 2 个网周期才能再被定" |
| 网速 | **420**（不变） | 必须保持**弹道**。改"命中即定"的瞬时判定 ⇒ 退化成被动光环，**"要打得准"是网值这个武器位的唯一理由** |

三族网共用 `applyNet`，只参数不同：

| id | 定身 | 灼烧 | 策反 |
|---|---|---|---|
| `net` | 1.2s（+3.0s 免疫） | — | — |
| `net_el` 电网 | **1.6s**（+3.0s 免疫） | 6 dps × 3.0s | — |
| `net_cv` 驯化网 | 1.2s（+3.0s 免疫） | — | **4s 内讧** |

⚠️ **两条独立**：电网的灼烧**不吃定身免疫**。否则玩家在免疫窗口内打网 = 白打，读作"武器时好时坏"。
⚠️ **Boss 允许被定身**（这是"打得准"该有的回报），但**免疫策反**（否则"网住 Boss 让它帮你打小怪"直接摧毁关卡设计意图）。

### 2.2 视觉语汇（必须换，否则与减速打架）

| 状态 | 形状 | 代码 |
|---|---|---|
| 减速（旧 `slowT`，保留给其它来源） | **断续**弧环（6 段）+ 3 条缠索 | `DiveGame.ts:3543` |
| **定身（新 `rootT`）** | 收紧的**实环** + 一道「禁止」斜杠 | `DiveGame.ts:3558` |

**为什么不靠颜色区分**：深海会把亮度整体压掉，颜色是最先失真的通道；**形状不会**。所以三种控制状态（减速 / 定身 / 灼烧）各用一套形状，不共用色相。

## 3. 定时爆破（§3.2）

| 项 | 值 | 依据 |
|---|---|---|
| 引信 | **1.8s** | 典型敌人速度 68 ⇒ 1.8s 走 122px ≈ "一颗雷管住半屏外的一条线"。再长变"随机埋雷"，再短玩家来不及算 |
| 爆炸半径 | **110**（原 88） | 定时雷的价值全在**预判** —— 半径太小则"算准了也炸不到"，预判无意义 |
| 连锁半径 | **118** | **必须 ≥ 爆炸半径**，否则相邻两枚不互引（连锁雷名存实亡） |
| 上限 / 存活 | `MINE_CAP 6` / `MINE_LIFE 12s`（不变） | — |

⚠️ **不能同时保留踩触发**（V6.49 §3.2 已定）：双重触发会让玩家读不出"它为什么现在爆"。**已删 `MINE_TRIG`。**

### 倒计时可读性（区别踩触发的**全部**来源）

| 通道 | 规格 | 代码 |
|---|---|---|
| 闪频 | 周期 `0.08 + 0.42·k` s（k = 剩余比例）⇒ **0.50s → 0.08s**，12 倍频差 | `DiveGame.ts:3204` |
| 颜色三档 | `k>0.5` 氧青（安全）→ `k>0.2` 琥珀（过半）→ 危险红（临爆） | `DiveGame.ts:3207` |
| 本体 | 呼吸幅度随倒计时增大（`swell = 1 + (1-k)·0.5`）—— 越接近越"鼓" | `DiveGame.ts:3212` |
| 爆炸范围圈 | **画出来**（`r=110`）—— 玩家要能预判"算好它 1.8 秒后游到哪"，这需要有边界可参照 | `DiveGame.ts:3209` |
| 连锁连线 | 连锁雷把射程内的伙伴连起来 —— "它们是一串"必须画出来 | `DiveGame.ts:3221` |

> **踩触发靠"敌人靠近"传达，定时靠"自己的心跳"传达。** 所以倒计时是它区别于旧机制的全部可读性来源，不能省。

## 4. 第 4 类「重甲」（§4.1）

| 项 | 值 | 依据 |
|---|---|---|
| HP | **×6**（base 40 × 层 hpMul） | — |
| 速度 | **×0.4**（68 → 27） | — |
| 半径 | **30** | — |
| 护甲 | **减伤 60%**，**爆炸 `blast` / 穿透 `pierce` 无视** | 这是它**逼玩家换武器**的唯一手段。没有护甲的重甲只是"血厚的杂兵" |
| 行为 | **不索敌**：沿出生时定死的方向**直线漂移** | 区分度来自**行为**（它不理你 ⇒ 你得主动去打它），不是外形 |

### ⚠️ 死锁陷阱（本项目新踩的坑，必须记住）

**不索敌 + 直线漂移 ⇒ 若不反弹，它会飘出屏幕，而清波条件是 `enemies.length === 0` ⇒ 这一波永远结束不了。**

这不是崩溃、不是报错 —— 是"画面上没敌人了，但波次卡死不动"。**静默死锁。**

修法：撞到任一边界就**反射**（`dirX/dirY` 取反），让它在屏内**巡逻**。

```
if (e.x < e.r) { e.x = e.r; e.dirX = Math.abs(e.dirX) }
else if (e.x > W - e.r) { e.x = W - e.r; e.dirX = -Math.abs(e.dirX) }
```

### 视剪影（必须与鱼的三角**完全不同**）

- **六边形装甲壳**（起始角 0.35）+ **横中缝**（"拼出来的壳"，无缝就只是一块多边形）
- **航向刺**（沿 `dirX/dirY`）—— 顺便告诉玩家"它往哪走"，因为**它不朝你**，光看不出来它要飘向哪。这是"不索敌"这个行为语汇的**可见化**。
- 颜色 `UI.steel = 0x9aa7b8`（低饱和冷灰）—— 刻意**脱离生物发光色系**，它是"金属"，不是"生物"。

### 反馈层落点

命中被护甲格挡时，**火花换成钢灰**（`hitCol = blocked ? UI.steel : ...`）。玩家第一次打重甲就能从颜色学到"这玩意抗弹、该换武器"，**不用先去看图鉴**。

## 5. 第二 Boss「鮟鱇女王」（§4.2）

**与守望者的区分全在行为语汇，不在体型**：

| | 深渊守望者（L5） | **鮟鱇女王（L3）** |
|---|---|---|
| 压力来源 | **逼近**（追 → 蓄力 → 砸地） | **诱捕**（在远处等你来） |
| 做法 | 靠近你、砸你 | 亮诱饵光 → 张口吞 |
| 玩家解法 | 走位躲冲锋 | **忍住不靠近光** |
| HP / 速度 | 1500 · 46 px/s | **1100 · 30 px/s**（更慢 —— 它不靠速度施压） |
| 颜色 | `UI.violet`（紫） | `UI.amber`（琥珀 = 诱饵光的颜色，与机制同源） |

### 三段相位

| 相位 | 行为 | 数值 |
|---|---|---|
| `chase` | 缓慢靠近（30 px/s） | 进入 `LURE_R` 触发张口 |
| `charge` | **停住不动 + 诱饵灯全亮**（预警窗口） | `FLARE_T = 1.6s` |
| `dash` → `rest` → `chase` | 咬合结算后的收招 | 0.5s / 1.2s |

| 项 | 值 | 依据 |
|---|---|---|
| 诱饵范围 | `ANGLER_LURE_R = 320` | — |
| 咬合半径 | `ANGLER_BITE_R = 190` | 玩家要知道"退到哪才安全"，否则"忍住"变成盲猜 |
| 咬合伤害 | `ANGLER_BITE_DMG = 26` | 比守望者砸地（18）**更疼** —— 被诱捕的代价该比被砸一下更疼（因果不同：砸地是"它打你"，咬合是"**你被自己的贪心带进去**"） |

### ⚠️ 诱捕要成立，光必须**真的能把玩家拽过去**

**没有牵引，玩家站远点打就完胜，Boss 退化成"一个不动的大血包"。**

所以张口期有一道**朝向它的水流**：`ANGLER_PULL = 130 px/s²`，越近拉力越强（`(1 - dd/LURE_R)` 线性衰减）。玩家移速约 200 ⇒ 130 可抗衡但费力 —— 这才是"忍住别贪"。

### ⚠️ 两个 Boss 共用 `charge` 相位名，表现**必须分开**

| | 守望者 `charge` | 鮟鱇 `charge` |
|---|---|---|
| 含义 | 蓄力砸地 = **危险的兆** | 诱饵全亮 = **诱捕的诱** |
| 表现 | 危险红 | 诱饵亮 + 咬合半径圈 |

两者共用 `charge` 只是**复用相位机**。渲染层用 `e.bossKind !== 'angler'` 分流（`DiveGame.ts:3427`）。

### 不新增第五个 `Kind`

`angler` 与 `watcher` 共用 `kind: 'boss'` —— 掉落 / 图鉴 / 震屏 / 清场全按 `'boss'` 走。区分只在 `bossKind` + AI 分支。**新增 `Kind` 会让每一处 `e.kind === 'boss'` 都要审一遍，是纯粹的返工风险。**

## 6. 战斗惊喜点 A + B（§5）

### 6.1 A 精英标记怪

| 项 | 值 |
|---|---|
| 每波数量 | `ELITE_MIN/MAX = 1/2` |
| 血 | ×3 · 掉落 ×4 · **必掉一个「囊」**（大骨 + 一大口氧 18） |
| 表现 | **脉冲光晕**（复用"发光 = 值得"的既读法，与鱼骨同一套 ⇒ 玩家不用学新符号） |

⚠️ **同一只不能既是重甲又是精英**（两者都是"值得打的"，叠加读作数值失控）。抽签时 `if (kind !== 'armor')` 才判精英。

⚠️ **精英整体绕过 `dropCap`** —— "必掉"就是必掉，不能被波预算吃掉。否则**"打得好的那一波反倒没掉落"，正好把奖励设计反了**。

### 6.2 B 连杀骨雨

| 项 | 值 |
|---|---|
| 触发 | `COMBO_WINDOW 3.0s` 内连杀 ≥ `COMBO_N 8` 只 |
| 奖励 | 玩家周围撒 **6–10 块**骨（`COMBO_SPREAD = 150` 散布），**绕过 `dropCap`** |
| 反馈 | 飘字 `连杀 ×8 · 骨雨` + 轻震屏 |

设计意图：**奖励"打得好"而不是"走得远"** —— 把爽感从**位置轴**挪到**操作轴**。

⚠️ **Boss 不计入连杀**：否则打 Boss 过程中混进来 7 只小怪就白送一次骨雨，读作"随机发钱"。

⚠️ **连杀窗口放主循环而非 `updateWave`**：`updateWave` 在 `descending` 相位不跑，而连杀窗口是**按真实时间**计的 —— 下潜途中不该"冻结"连杀。

## 7. 状态标记形状语汇总表

**为什么必须做标记**：控场型武器的**全部手感**都在"我怎么知道它生效了"。打伤害的武器不需要（掉血条自己在说），但网 / 诱饵 / 策反**不改血量** —— 没有标记时玩家的判断只能是"这条鱼好像慢了？"，那等于没做。

| 状态 | 形状 | 语义 | 代码 |
|---|---|---|---|
| 减速 `slowT` | **断续**弧环 + 3 条缠索 | 被缠住、还能动（松） | `3543` |
| **定身 `rootT`** | **实环 + 禁止斜杠** | 完全不动（紧） | `3558` |
| 灼烧 `burnT` | 外圈橙弧（**不填充**）+ 双环 | 正在烧 | `3597` |
| 策反 `charmT` | 青色实环 + 两段**反向**品红弧 | 它在朝同伴去 | `3605` |
| 精英 | 琥珀**脉冲光晕** | 值得先打 | `3570` |
| 重甲 | 六边形壳 + 中缝 + 航向刺 | 打不动、不追你 | `3489` |
| 鮟鱇诱饵 | 琥珀灯（平时微亮 / 张口全亮 + 咬合圈） | 该忍住了 | `3580` |

**三条硬约束**（沿用本项目既有规约）：
1. **不靠颜色区分** —— 深海会把亮度压掉，形状不会。
2. 状态标记一律**不填充**（实心圈会把鱼盖成一坨亮斑）。
3. 灼烧的橙弧**按 18Hz 闪**（`sin(w.t * 18)`）—— 频率本身就是"火在跳"的信息。

## 9. 待实机确认（必须你在 Creator 3.8.8 里看）

**静态验证（`verify_cocos.py` 7/7 + `web tsc` 0）只能证明"可编译、资源齐、类型对" —— 证明不了"手感和观感"。**

| # | 待确认 | 判据 |
|---|---|---|
| 1 | **撒网定身的"回报感"** | 网住一群时，是不是"该我打靶了"的爽，而不是"哦它不动了" |
| 2 | **定身是否过强**（配平） | 一屏 150 敌时被定住的占比是否 ≤ 免疫窗口算出的上限 |

| 7 | **精英光晕在 150 敌里找得到吗** | 满屏时能否一眼锁定精英 |

## 10. 可复用铁律（本轮新增）

1. **"不索敌"必须配"撞墙反弹"**：不索敌 + 直线漂移 ⇒ 飘出屏幕；而清波条件是 `enemies.length === 0` ⇒ **该波永不结束**。静默死锁，不是 bug 报错。
2. **诱捕型 Boss 必须有"牵引"**：光只是装饰的话，玩家站远点 = 完胜，Boss 退化成大血包。**压力源必须物理可感**（这里是朝向它的水流）。
3. **"必掉"必须绕过"预算"**：`dropCap` 是波预算（防通胀），但"精英必掉囊"是**承诺**。被预算吃掉 ⇒ "打得好的那波反倒没掉"，**奖励设计反了**。
4. **免疫窗口必须独立于附加效果**：电网的灼烧不该吃定身免疫。否则免疫期内打网 = 白打，读作"武器时好时坏"。
5. **计时逻辑放主循环，不放相位分支**：连杀窗口按真实时间计；`updateWave` 在 `descending` 不跑 ⇒ 放那里会在下潜途中"冻结"连杀。
6. **同一相位名 ≠ 同一表现**：`charge` 在守望者是"危险的兆"、在鮟鱇是"诱捕的诱" —— 复用相位机可以，**复用表现不行**。
