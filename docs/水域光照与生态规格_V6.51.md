# 水域光照与生态规格 V6.51

> **修订 V6.50**。V6.50 只解决了「水域在动」，没解决「水域是活的、有光的」。
> 本轮的判断：**V6.50 的方向对了一半 —— 把「深」做成了「黑」。**
>
> **V6.51a 追加**：定死「介质」与「俯视角度下下潜如何被读出」两件事（见 §0-A、§0-B）。

---

## §0-A 介质决定：**不做视频**（定死，不再讨论）

「往下游」这种感觉**不是视频**，是引擎里逐帧程序化渲染的。四条理由，任一条单独成立即否决视频：

| 维度 | 视频 | 引擎内程序化（本方案） |
|---|---|---|
| **深度连续性** | 锁死在片子里，第 3 分钟永远是第 3 分钟 | 跟 `depthM` 实时变 —— 玩家在哪一米，画面就是哪一米 |
| **可被玩法驱动** | 不能。探照灯半径、下探节拍、连杀加速、换带时机全都动不了 | 全都能改。开火亮一下 / 下探节拍提速 / 换带，都是同一套参数 |
| **循环** | 首尾必须无缝，否则周期跳帧 | 无需循环，颗粒是无限流 |
| **体积 / 分辨率** | 10s 1080p 循环 ≈ 8–15MB，且分辨率固定 | **零新增资源**，一条 `drawAtmo()`；分辨率无关 |

**核心一条**：这游戏的深度是**玩家行为决定的连续量**。用视频 = 把"画面"换成"只能按片子节奏走的画面"，等于放弃了下面所有玩法耦合。

⇒ 落地形态与现有海雪 / 鱼骨 / 特效**同一条管线**（Cocos `Graphics` + 精灵池），不引入任何视频资源。

## §0-B 俯视角度下，「往下游」靠什么被读出（本轮设计主命题）

**俯视看不到"下"，所以"下"必须由别的通道翻译过来。** 这四个通道按权重排序：

| # | 通道 | 俯视屏幕里长什么样 | 权重 |
|---|---|---|---|
| ① | **相对运动** | 悬浮物 / 海雪**向上掠过**（＝开车时路边景物向后跑） | ★★★ |
| ② | **换带** | 颜色 / 亮度 / 生物群整体换一次（阳光→弱光→荧光→热泉→深渊） | ★★ |
| ③ | **生物群变化** | 鱼群种类、大小、密度随深度换 | ★★ |
| ④ | **HUD 深度计** | 左侧竖条游标持续下移 | ★ |

**现状缺的就是 ①**：海雪 `vy = -6~-20 px/s`（方向对，**慢一个数量级**）、只有一层、**无视差**。
⇒ 主修 ①：`SCROLL_BASE` 提到 **46 px/s**、换波峰值 **220（4.8×）**、加 **三层视差**（视差本身即深度线索）。

### 生态两层（对应「看到向下的生物 + 周围的鱼群」）

俯视里**唯一能表达深度的是大小 + 明暗**（近大亮、远小暗）。据此分两层：

| 层 | 内容 | 大小 | 明暗 | 可交互 |
|---|---|---|---|---|
| **远景剪影层**（深 / "向下的生物"） | 小鱼群横游、深渊巨影 | ≤ 敌人 0.6× | alpha ≤0.35，**无发光核** | ⛔ 不可瞄准、不碰撞 |
| **同层实体层**（浅） | 现有敌人 | 基准 | 带 2px 发光核心 | ✅ 战斗目标 |

⚠️ **远景鱼群绝不能带那枚 2px 发光核心** —— 那是敌人的定位铁律（`DiveGame.ts:563-568`），破了它玩家会朝打不到的鱼开火。

## §0 病根（实测数字，不是感觉）

用 PIL 量化五张 `cocos/assets/resources/env/L*.png`（无遮挡、无压暗层的原始图）：

| 图 | 尺寸 | 均值亮度 | 峰值亮度 | **近黑像素(<22)** | **亮像素(>90)** | 均值饱和 |
|---|---|---|---|---|---|---|
| L1 阳光带 | 1536×984 | 86.8 | 216 | 0.0% | **39.9%** | 0.41 |
| L2 弱光带 | 1536×984 | 63.5 | 102 | 0.0% | 10.6% | 0.65 |
| **L3 午夜带** | 1536×984 | **21.6** | 104 | **79.4%** | **1.2%** | 0.44 |
| L4 热泉带 | 1536×984 | 42.9 | 181 | 8.4% | 2.4% | 0.26 |
| **L5 深渊带** | 1536×984 | **14.6** | 104 | **89.5%** | **0.4%** | 0.35 |

**再叠加运行时的两层压暗**（`DiveGame.ts:1663` / `1669`）：

```
压暗 = UI.abyss(0x04070d) × (1 - vis) × 0.42      # L5: 0.9 × 0.42 = 0.378 alpha
暗角 = 同心环带 × (0.16 + (1 - vis) × 0.72)         # L5: 0.81
```

⇒ **L5 屏幕中央的实际亮度 ≈ 14.6 × (1−0.378) ≈ 9**，边缘被暗角归零。
**这不是「深」，这是黑屏。** 用户说的「太黑了」「不完全漆黑吧」是有数字支撑的。

### 三条结构性病根

| 病根 | 证据 |
|---|---|
| ① **色彩阶梯是「去饱和到黑」** | tint 链 `0x2a6f8a → 0x1d5a5a → 0x14203c → 0x3a1a10 → 0x0a0614`，越走越暗越灰 = 物理正确、游戏上死路 |
| ② **没有任何光源** | 全链路只有海雪 60 颗（`0x9fe1cb @0.16 alpha`，0.16×230 ≈ 37 亮度，黑底上不可见）。**没有光，只有暗** |
| ③ **背景里没有活物** | 背景层只有背景图 + 海雪两个元素。**玩家看不到任何「水里还有别的东西」的证据** |

## §1 设计原则：**光的主权转移**（本轮核心）

> **不要做「越深越黑」。做「每一带换一个光的主角」。**

玩家的感知不是「亮度在下降」，而是**「光的来源在变」**。这是 Subnautica / 深海迷航 那一类作品的做法 —— 深渊之所以吓人不是因为它黑，是因为**唯一的光源是你自己**。

| 带 | 光的主角 | 玩家的心理 | 亮度走向 |
|---|---|---|---|
| L1 阳光带 | **太阳**（丁达尔光柱 + 水面焦散） | 安全、熟悉 | 最亮 |
| L2 弱光带 | 残光 + **玩家探照灯登场** | 「我得靠自己看了」 | 略降 |
| L3 午夜带 | **生物荧光**（水母群 / 荧光浮游） | 陌生、美丽、危险 | **回升** |
| L4 热泉带 | **热泉本身**（橙红烟柱 + 化能生物） | 灼热、狂暴 | **再升（第二亮）** |
| L5 深渊带 | **探照灯 + 深渊呼吸点阵** | 孤独、压迫 | 最小，但**对比度最高** |

**关键反转**：L4 热泉带比 L3 亮。物理上也成立（热泉有自身热辐射 + 密集化能合成生物群），玩法上打破「单调递减」的节奏疲劳。

**关键区分：提高对比度 ≠ 提高环境亮度。**
画面的**平均亮度可以低，但必须有明确的亮点**。这就是下面那条可验收红线的由来。

### 可验收红线（本轮唯一的硬指标）

> **每张 env 图必须有 ≥6% 的像素亮于 90。**

现状 L3 = 1.2%、L5 = 0.4%，**都不合格**。「均值」不重要 —— 均值低但有几处亮，读作「黑暗中有光」；均值低且没有亮点，读作「一团黑」。

## §2 五带亮度 / 色彩重定

### 2.1 亮度目标（env 图重出时的验收表）

| 带 | 现状均值 | **目标均值** | 现状亮像素% | **目标亮像素%** |
|---|---|---|---|---|
| L1 | 86.8 | 86（维持） | 39.9 | ≥35 |
| L2 | 63.5 | **72** | 10.6 | ≥18 |
| L3 | 21.6 | **46**（+113%） | 1.2 | **≥8** |
| L4 | 42.9 | **58**（+35%） | 2.4 | **≥10** |
| L5 | 14.6 | **34**（+133%） | 0.4 | **≥6** |

### 2.2 色彩重定（`tables.ts` `LAYERS[].tint`）

规则从「**去饱和到黑**」改为「**转色相保饱和**」：

| 带 | 现状 tint | **目标 tint** | 依据 |
|---|---|---|---|
| L1 | `0x2a6f8a` | 维持 | 青蓝，正确 |
| L2 | `0x1d5a5a` | **`0x1d6b7a`** | 别提前变灰，蓝绿要亮一档 |
| L3 | `0x14203c` | **`0x352f6b`** | **青紫 = 生物荧光带的定调色**，不是蓝黑 |
| L4 | `0x3a1a10` | **`0x7a3a16`** | 硫化物橙红，必须**暖且饱和** |
| L5 | `0x0a0614` | **`0x1a1740`** | 靛蓝，**不是黑** |

**tint 覆盖 alpha `0.10 → 0.16`** —— 0.10 太淡，色相跳变根本读不出来。

### 2.3 压暗与暗角减半（光改由 `gAtmo` 提供，压暗层必须让位）

| 项 | 现状 | 目标 |
|---|---|---|
| 压暗 | `(1-vis) × 0.42`（`DiveGame.ts:1663`） | **`(1-vis) × 0.24`** |
| 暗角强度 | `0.16 + (1-vis) × 0.72`（`:1669`） | **`0.10 + (1-vis) × 0.42`** |
| `vis` L1 | 1.00 | 1.00 |
| `vis` L2 | 0.80 | **0.92** |
| `vis` L3 | 0.40 | **0.68** |
| `vis` L4 | 0.25 | **0.60** |
| `vis` L5 | 0.10 | **0.46** |

⚠️ **改 `vis` 前必须全目录搜一遍**：`vis` 同时被机制层读（涌流/热泉/压力的表现），
确认没有机制依赖它的绝对值（只当表现用才可改）。

## §3 新节点 `gAtmo`（光照与生态层）

### 3.1 层序（这是本轮最容易做错的地方）

现有节点顺序（`DiveGame.ts:546-574`，**顺序即绘制顺序**）：

```
gBase  →  bg(Sprite)  →  gBg  →  gVeil  →  gBack  →  fishLayer  →  gEnt  →  sub  →  gPlayer  →  gFront  →  hud
```

**`gVeil`（压暗 + 暗角）在 `gBack`（实体）之下** —— 所以：

> ⛔ **光照层必须插在 `gVeil` 与 `gBack` 之间。**
> 插在 `gVeil` 之下 = 光会被自己的压暗层吃掉（做完全部白工）。
> 插在 `gBack` 之上 = 光会盖住敌人和子弹（战斗可读性崩溃）。

```
                    ┌─ gAtmo 插在这里 ─┐
gBase → bg → gBg → gVeil ──────────────→ gBack → fishLayer → gEnt → sub → gPlayer → gFront → hud
```

`gAtmo` 装六个元素（§4），**全部是纯表现，不参与任何模拟**。

### 3.2 为什么不能让光躲在暗角里

暗角的作用是「把注意力收向中央」。有了光源之后，**光必须能穿透暗角** —— 否则屏幕边缘的光柱会被掐掉一半，看起来像渲染 bug。

但也不能完全不收。取值折中：**暗角只作用于「雾」（§4.6），不作用于「光源本体」。**
即：远处有光柱 = 看得见；远处的水体 = 被雾压平。这既保住了「能看远」，又保住了「深水看不远」。

## §4 六个表现元素规格

> **图元预算硬上限：`gAtmo` 每帧 ≤ 130 个 Graphics 图元**（约 V6.48 基线 ~1100 的 +12%）。
> 超出就按 §8 的 `ATMO_QUALITY` 降档。

### 4.1 远景鱼群剪影 ★ 用户点名要的

**这是最高性价比的「水是活的」信号。** 不参与战斗、不可攻击、不碰撞 —— 纯生态背景。

| 带 | 形态 | 数量 | 速度 | 尺寸 | alpha |
|---|---|---|---|---|---|
| L1 | 银亮小鱼群 | 18–24 | 快（140 px/s） | 14–20 px | 0.34 |
| L2 | 暗中鱼群 | 12–16 | 中（95 px/s） | 18–26 px | 0.30 |
| L3 | 大单体 + 荧光眼点 | 2–3 | 慢（55 px/s） | 54–80 px | 0.26 |
| L4 | 厚重畸形群 | 6–9 | 中慢（70 px/s） | 26–40 px | 0.28 |
| L5 | **巨大半透幽灵** | 1–2 | 极慢（22 px/s） | 150–220 px | 0.14 |

- 每条鱼 = **1 个 `fillPoly`**（三角身体 + 尾鳍并成一个多边形）+ 可选 1 个眼点 ⇒ 1–2 图元。
- 鱼群转向用 **boids-lite**：领头鱼转向，其余按距离延迟跟随（**不做避障、不做群内分离**，那是纯开销）。
- 整群从屏幕一侧游入、另一侧游出，离场后回收重生；**换带时全部清空重生成**（避免「深海出现浅海鱼」）。

> ⛔ **可读性红线（做错就是致命 UX）**：远景鱼群**绝不给 2px 发光核心**。
> 敌人有那枚核心，它是「每条鱼都能被定位」的铁律（`DiveGame.ts:563-568`）。
> 远景鱼必须：**没有核心 + alpha ≤0.35 + 尺寸 ≤ 敌人的 0.6× + 不可瞄准 + 不参与碰撞**。
> 否则玩家会朝打不到的鱼开火 —— 这比「背景不好看」严重得多。

### 4.2 丁达尔光柱（**仅 L1 / L2**）

从屏幕上方斜射下来的光柱。**这是「浅水」的视觉签名**，也是「太阳还在上面」的唯一证据。

- 数量 4–6 条，宽度 40–120 px 不等（**必须有宽窄差，等宽会读作栅栏**）。
- 每条 = 3 层不等宽平行四边形，alpha `0.05 / 0.08 / 0.12`，最宽最淡、最窄最亮。
- 倾斜角 **14°–22°**，随时间缓慢摆动（周期 11s，幅度 ±2°）—— **不能静止，静止读作贴图**。
- **随 `depthM` 淡出**：`depthM > 900` 起线性衰减，1200 归零。
- 图元：6 条 × 3 = **18**。

### 4.3 生物荧光群（**仅 L3**）

L3 的光的主角。**不是「更亮的点」，是「会呼吸的链」**。

- 形态：**链状**（3–7 个点串成一串，间距 8–18 px），成串缓慢下沉 + 微微摆动。
- 数量：6–8 串，共约 36 个点。
- 颜色：`0xa88cff`（青紫）为主，20% 用 `0x6ff0d0`（青绿）打破单一。
- 呼吸：每串有独立相位，亮度在 0.35–1.0 之间做 2.4–3.6s 的正弦（**取非整数比，避免整屏同步读作脉动 bug**）。
- 图元：36 点 × 1 = **36**（不给每个点画光晕环，靠 alpha 呼吸表达）。

### 4.4 热泉烟柱（**仅 L4**）

**这是全场最暖、最亮的地方** —— 深渊题材里最反直觉的视觉反转点。

- 形态：从屏幕下方升起的**橙色絮状柱**，6 条，宽度 30–90 px。
- 每条 = 4 段逐渐放大 + 变淡的椭圆（模拟扩散），alpha `0.16 → 0.04`。
- 颜色：核心 `0xff8a3c`，外缘 `0x8a3a18`。
- 运动：**向上**（与海雪的「向上是下潜」方向一致，但速度更快、更浊）。
- 与 V6.50 §4 的热泉反向颗粒配合：**烟柱向上 + 颗粒被顶住** = `ventPush 190` 的完整视觉证据。
- 底部微加一圈橙红辉光（同心环带 3 环），让「热源」有实体感。
- 图元：6 × 4 + 3 = **27**。

### 4.5 深渊呼吸点阵（**仅 L5**）

L5 的光的主角。**全场点阵同步明灭，周期 3.2s。**

- 数量：48 个点，分布在全屏（**避开中央 260px 半径**，给战斗留出干净区域）。
- 每个点 = 1 个 `fillCircle`，半径 1.4–2.8 px。
- 同步呼吸：`alpha = 0.10 + 0.55 × (0.5 + 0.5·sin(2π t / 3.2))`。
- 20% 的点给一个 3 环渐隐光晕（制造「大的东西在深处」的错觉，成本只 3 图元/个）。
- ⚠️ **周期 3.2s 与主循环 14.4s 取非整数比**（14.4/3.2 = 4.5）—— 避免与其它周期同步读作「画面在闪」。
- 图元：48 + 10×3 = **78**（L5 时其它元素大多归零，见 §8 互斥表）。

### 4.6 能见度雾（**全带，取当前带 tint**）

> **能见度靠「雾」，不靠「黑」。**
> 关键差异：**雾是「亮的暗」，黑是「暗的暗」。**
> 玩家看到黑幕会认为「我瞎了」；看到浑浊的同色雾会认为「我看不了太远」—— 后者才是潜水感。

- 颜色 = **当前带的 tint**（不是黑）。
- 作用：以玩家为中心，「能见度半径外」降对比度（叠同色低 alpha），**不是挡黑**。
- 半径随深度收：L1 无限 → L2 640px → L3 480px → L4 380px → L5 **300px**。
- ⛔ **禁用径向渐变**（项目已有教训：渐变被反复叠加成死黑），用**同心环带**（复用 `drawVeil` 的写法）。
- **不作用于光源本体**（§3.2）：光照层在雾之上画，雾只压背景图与水体物质。
- 图元：8 环 = **8**。

### 4.7 玩家探照灯（**L2 起，L5 最强**）

**「我能看见」的因果来源。** 没有它，深水就是「环境本身很亮」，有了它才是「我在照亮环境」。

- 形态：以 player 为中心的**同心环带亮斑**（6 环，向外衰减），中心 alpha 0.20 → 外圈 0.02。
- 半径：基础 `LAMP_R = 140px`，按带递减 L5 = 96px（越深越聚焦）。
- 颜色：`0xbff4ff` 冷白，**不要纯白**（纯白在深色水里像 UI 元素）。
- 随 `depthM` 从 0（L1 无灯）线性升到满 —— L1 是白天，不需要灯；L2 开始逐渐登场。
- 图元：6 = **6**。

> ⚠️ 与 V6.42 删掉的「探照锥」不冲突：那个是**主界面中央区的装饰性锥形**，已删；
> 这个是**战斗内的功能性环带光晕**，语义与位置都不同，不复活旧设计。

## §5 创新点（把「光照」变成玩法）

> 以下 4 条是本轮的**游戏设计新增**，不属于纯表现。
> ⚠️ 全部标注了落地分段：**v1 只做视觉，机制挂 P1**，避免又一次「一次改太多」。

### 创新 1：探照灯 = 双向暴露 ★ 本轮最大创新

**光让你看得见，也让你被看见。**

- 玩家自带光环半径 `LAMP_R` 决定两件事：
  - **好处**：`LAMP_R` 越大 → 雾的能见度半径越大 → **能看见更多远处的东西**
  - **代价**：趋光生物额外生成概率随 `LAMP_R` 上升（`attractR = LAMP_R × 2.2`）
- 可做成**武器位 / 遗物**：「增大探照灯」= 看得更远但更危险。**把一个纯表现参数变成了一次取舍。**
- ⚠️ **v1 只做视觉**（光环 + 雾半径）。吸引机制动生成器，**挂 P1**，等 P0 再说。

### 创新 2：光的颜色 = 情报语言（零学习成本）

玩家不需要 UI 告诉你什么是什么，**用光表达**：

| 光的形态 | 含义 | 复用自 |
|---|---|---|
| 青绿单点 | **鱼骨（资源）** | 现有鱼骨辉光 `0x4fe8ff` |
| **紫青点链** | 生物荧光 / 敌对生物的荧光 | 本轮新增 §4.3 |
| **橙红絮状柱** | 热泉（增益或危险） | 本轮新增 §4.4 |
| 冷白环带 | 你自己（探照灯） | 本轮新增 §4.7 |
| 白色同步点阵 | 深渊环境本身 | 本轮新增 §4.5 |

「发光 = 值得注意」这个读法**已经在鱼骨上建立过了**（`DiveGame.ts:1771` 注释：「光晕不是装饰，是功能」）。
把它扩成一套**颜色语言**，玩家不用学新符号。

### 创新 3：深渊的呼吸

L5 的点阵同步明灭（3.2s）。**用极低成本制造「底下有个巨大的东西」的压迫感。**
深渊之所以是深渊，不是因为它黑，是因为**你感觉有东西在看着你**。比任何怪物都便宜。

### 创新 4：温跃层扫带（换带的仪式感）

换带时，一条**横贯屏幕的波纹带从下往上扫过（0.6s）**，它扫过的区域色相**瞬时切换**为下一带。

- 物理依据：潜水员穿过温跃层/盐跃层时，界面会「抖」一下 —— 这是真实存在的视觉现象。
- 与 V6.50 的 `bgNode` crossfade **2.0s 叠加**：**图是慢慢化的，气氛是被「扫」过来的**。
  （一个是背景图的软过渡，一个是有方向的物理事件，两者叠加不冲突，反而互相解释。）
- 图元：3（一条波带用 3 段叠 alpha）。
- **这一条是本轮最便宜的「高级感」** —— 只加 3 图元，但换带从「切图」变成「穿过了一层水」。

## §6 交互光反馈（解决「战斗与背景两张皮」）

现在的问题：**战斗打得再猛，背景一点反应都没有** —— 所以背景读作「贴纸」。

| 触发 | 环境反应 | 图元 |
|---|---|---|
| 武器开火 | 枪口位置一圈冷白亮斑（0.12s 衰减） | 3 |
| 爆炸 | 爆炸点一圈**暖白**光晕向外扩（0.28s，半径 1.0→2.4×） | 4 |
| 拾取鱼骨 | 鱼骨周围 300px 内**同色**环境亮一下（0.20s） | 4 |
| 受击 | 已实现（方向性暗角 `:1696`），不动 | 0 |

⚠️ 与既有「爆炸环」（`gBack`）的区别：那个是**冲击波**（几何环，硬边），这个是**环境反光**（亮斑，软边、大范围、低 alpha）—— 两者叠加才是「炸了一下，整个水都亮了」。

## §7 环境图 v2 重出规格（转插画岗）

> 我的边界：**出结构与数值规格，插画本体归 `cocos-game-artist`。**

| 项 | 规格 |
|---|---|
| 尺寸 | **1536×1180**（上下各留 20% 滚动余量，保边缘无缝） |
| 格式 | PNG-24（无 alpha 需求，满幅图） |
| 每张 **≥6% 像素亮于 90** | 硬指标，见 §2.1 |
| 均值亮度 | 按 §2.1 表 |
| 色相 | 按 §2.2 重定后的 tint 定调，**不要继续往黑里画** |
| 每张画清「光的主角」 | L1 阳光+水面焦散 / L2 残光+远光斑 / L3 荧光点链 / L4 热泉烟柱+橙红辐射 / L5 稀疏点阵 |
| ⛔ 不含 | **文字 / UI 元素 / 战斗实体（鱼、敌人）** —— 画进图里会与引擎画的实体打架 |
| ⚠️ 压包 | **`L1.png` 现 2.46 MB**（其余 0.25–0.67 MB），首屏第一张，必须 **≤0.8 MB** |
| 命名 | 不变（`L1..L5.png`），**代码零改动** |

**建议顺序**：先做 `gAtmo`（程序化光）+ §2 参数重定 → 看实机 → **再决定要不要重出图**。
程序化光照能补很大一部分，先出图可能白花周期。

## §8 性能预算

### 8.1 图元预算（V6.48 基线 ~1100 图元/帧）

**关键：光柱 / 荧光群 / 烟柱 / 点阵是「按带互斥」的 —— 同一时刻只开一组。**

| 元素 | 出现条件 | 图元 |
|---|---|---|
| 远景鱼群 | **全带** | 18–42 |
| 玩家探照灯 | L2+ | 6 |
| 能见度雾 | 全带 | 8 |
| 丁达尔光柱 | **仅 L1/L2** | 18 |
| 生物荧光群 | **仅 L3** | 36 |
| 热泉烟柱 | **仅 L4** | 27 |
| 深渊点阵 | **仅 L5** | 78 |
| 交互光反馈 | 瞬时 | 0–11 |

**最坏情形 = L5**：鱼群 1×2 + 探照灯 6 + 雾 8 + 点阵 78 + 反馈 11 = **≤105 ≈ +9.5%**。
（L5 鱼群只有 1–2 条，这是它反而便宜的原因。）

**最坏的第二档 = L3**：鱼群 3×2 + 探照灯 6 + 雾 8 + 荧光 36 + 反馈 11 = **≤67 ≈ +6%**。

✅ 全部在 ≤130 的硬上限内。

### 8.2 降级旋钮（必须有，放文件头常量区）

```ts
/** 大气层质量档：2 全开 / 1 关光晕环与呼吸环 / 0 只留鱼群 + 探照灯 + 雾 */
const ATMO_QUALITY = 2
```

- 档 1：省下石阵光晕环（L5 -30）、烟柱外段（L4 -12）、荧光串的光晕 —— 约 **-45 图元**
- 档 2：只保留「水是活的」最低要求 —— **≈ -160 图元**

⚠️ **降级不许动鱼群与探照灯** —— 它们是用户直接点名要的东西，是这一层的存在理由。

### 8.3 禁止事项

- ⛔ 禁止每帧 `new` 数组/对象生成粒子（V6.48 已证明尖刺来自分配/GC）
- ⛔ 禁止为每个元素开新 `Graphics` 层（一个 `gAtmo` 全装，顺序靠绘制先后）
- ⛔ 禁止径向渐变（同色环带替代）
- ⛔ 禁止让远景鱼群参与任何模拟（不进 `world.enemies`，不参与碰撞与索敌）

## §9 落地顺序（**修订 V6.50 §9**）

V6.50 的顺序只覆盖了「动」，本轮的「光与活」要**插进去**。串起来是：

| # | 步骤 | 依赖 | 风险 |
|---|---|---|---|
| 1 | **`gAtmo` 节点 + 玩家探照灯** | 动 `Dive.scene` 节点结构 | 低（层序已验证） |
| 2 | **远景鱼群剪影层** ← 用户点名 | 1 | 低（但**可读性红线**要守） |
| 3 | **`tint` / `vis` 重定 + 压暗暗角减半**（§2） | 无 | **中（先搜 `vis` 的机制依赖）** |
| 4 | 水体物质分层（海雪 → 五带物质） | 2 | 低 |
| 5 | 光柱（L1/L2）+ 荧光群（L3）+ 烟柱（L4）+ 点阵（L5） | 1 | 中（图元预算） |
| 6 | 能见度雾 | 5 | 低 |
| 7 | 交互光反馈（§6） | 1 | 低 |
| 8 | 温跃层扫带（创新 4） | 3 | 低（只 3 图元） |
| 9 | **全部接 `depthM` 连续曲线** | 8 | 低（与 V6.50 §9 合并） |
| 10 | 颗粒分组提速 + 三层视差 | 4 | 低（V6.50 已有） |
| 11 | 双 `bgNode` crossfade | 9 | 中（动节点结构） |
| 12 | 深度计 | 9 | 低（V6.50 已有） |

**1–3 步做完就是「肉眼可见的质变」**（有光、有鱼、不黑），建议以这 3 步为第一个可验收节点。
