## 怎么换一张机体图

1. 出图（提示词见规格文档，**逐字复用**）；
2. ```bash
   python tools/prep_sub_art.py <新图> --out docs/shots/sub_art/sub_new \
     --expose 2.0 --sat 1.15 --derim-src 2 --derim-cv 4 --derim-target 1.03 --diag
   ```
   看打印的几行：`ratio`（长高比）、`sy/sx`（垂直拉伸倍数）、`hull`（轮廓内透明占比）、
   **`[derim]·src` / `[derim]·cv` 两行**（各应削掉 20%~40% 的平均亮度；只剩 1.0× = 环带没取到）；
   ⚠️ `--expose` 的**脚本默认值也是 2.0**（V6.77 从 1.35 提上来）：判据是**成品本体 p50 落在 90~100**。
   1.35 时实测只有 **61**，而浅海背景 L1 的 p25 就有 74 ⇒ 开局机体读作"一块黑板"（用户原话）。
   提到 2.0 后 p50 = 93；对比图 `docs/shots/hull_bright_ab.png`（1.9 档在深海开始发白 ⇒ 别超）。
   ⚠️ `--derim-*` 的**脚本默认值也是开的** —— ⛔ 不要关：AI 出图**必然**带一圈 rim light。
3. 判据：**拉伸倍数 ≤ 1.8** 且 **轮廓内透明占比 ≤ 2%**（否则炮座会浮空）
   且 **最外圈/内侧亮度 ≤ 1.15**（`de_rim` 是否生效，见规格第 8 节）；
4. 复制到 `web/src/assets/sub/sub_hull.png` → `python tools/sync_art.py`；
   ⚠️ **顺手把 `02_对齐成品/<新目录>/` 和根目录的 `sub_hull_采用.png` 一起更新**，
   否则归档又和真源对不上（2026-10-15 踩过一次）；
5. **同步 `DiveGame.ts` 的 `SUB_HULL` 常量**（抄 `.json`）+ `preview_hull_side.py` 的同名常量；
6. `python tools/verify_cocos.py`（7/7）+ `python tools/preview_hull_side.py --combat` 目视
   + `python tools/ab_sub_rim.py --a <改前> --b <改后>` 出改前改后对照图。

## 为什么有「拉伸倍数」这个判据

游戏里机体的显示尺寸被 `SUB_D × HULL_H = 88 × 56`（长高比 **1.571**）钉死 ——
因为 `SEAT_MOUNTS` 的挂点就是按它归一化的，而且炮座外缘直径 ~30px 必须坐得进艇高。
但**模型先验极强，怎么要求都出「细长潜艇」（实测长高比 2.6~3.8）**
⇒ 只能本地做**各向异性缩放**。实测：倍率 ≤ 1.8 时在 1× 实机尺度下看不出失真；
到 2.4 倍就明显变成「馒头」（见 `02_对齐成品/01 和 02`）。

## V6.76 开槽这一步（判据）

`bake_slots()` 在裁剪影**之后**、曝光补偿**之前**执行（放补偿之后画，槽会比艇身暗一档、
读作"贴了块黑胶布"）。三层明暗缺一不可：

| 层 | 系数 | 作用 |
|---|---|---|
| 槽内（由外向内） | ×0.16 → ×0.46 | 凹腔本身。**只做这一层读不出凹坑** —— 暗斑在深海里到处都是 |
| 槽底翻边 | ×1.08 | "到底了" |
| **槽口整圈亮边**（膨胀 1.7px 取环带） | ×1.30 | ★ **"这里有洞"的主力**：人眼认洞口靠的就是这一圈亮边 |
| 槽口内沿（最近光源一侧） | ×0.10 | 唇口投影 |

⚠️ 两个踩过的坑：
① **逐列求艇缘**，不要整窗取极值 —— 0 号槽的窗口右端搭到指挥塔底边，
   "艇缘"被抬到塔顶 ⇒ 算出 9.2px 深（实际 6.4），槽会挖穿甲板；
② **不改 alpha**：机体剪影是被 `HULL_OUTLINE` 裁出来的，那是**挂点基准** ——
   挖真缺口会同时改掉"座心到艇缘"的距离，还会把 tuned 好的梭形啃成锯齿。
   槽的"外缘"就是艇缘本身，靠明暗读作凹坑。

## V6.77b 削硬亮边这一步（判据）

用户 2026-10-15 第三次报"白色描边"（原话「还是有白色的划线」）。按实机截图逐处核对后，
"划线"有**两个叠加来源**：**渲染层 ③/③b 挂载导轨**（亮主题色粗线，已改暗缝）
+ **位图自带的 rim light**（主因，本步处理）。

`de_rim()` 在**源域**（缩放到 88×56 之前）与**画布域**（裁剪影之后、开槽之前）各削一道。
判据：**最外圈 / 内侧 ≤ 1.15**。

| 距边界 | 0 | 1 | 2 | 3 | 内侧 3~5 | 比值 |
|---|---|---|---|---|---|---|
| 削边前 | **143.9** | 132.2 | 111.9 | 100.0 | 95.0 | **1.52×** ✗ |
| 削边后 | 93.0 | 91.9 | 85.5 | 84.2 | 86.2 | **1.08×** ✓ |

* 做法是**自适应**的：把最外 `r` 圈的亮度**只往下**拉向"**局部内侧**亮度 × 1.03"
  —— 艇背受光段削得少、艇腹背光段削得多；⛔ 全局压暗会把边缘真实的高光一起抹掉。
* `r` 的单位是**各自域**的像素：源域 `2`（原稿上 rim 是 1~2px，这里削得最准）、
  画布域 `4`（K=4 ⇒ 4px = 1 实机 px，收掉 LANCZOS 缩放留下的振铃过冲）。
* 两次调用是**安全的**：`g` 会随亮度收敛到 1 ⇒ 第二次几乎没有可削的量。
* ⛔ **不改 alpha**（剪影 = 挂点基准）。
* **新基线**：机体位图 = 侧视梭形 + 6 槽 + **不带硬 rim**。下次重出图不要关 `--derim-*`。

对照图：`docs/shots/hull_rim_ab.png`（`tools/ab_sub_rim.py` 出）。
