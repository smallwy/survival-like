## 0. 为什么现在这版不成立（先诊断，再改）

现在 `Title.ts` 的构成是：**居中标题 + 三张并排潜航器卡 + 一个主按钮 + 两个次按钮**。
它是一张**启动页（splash）**，不是**主界面（hub）**。差在哪：

| # | 症状 | 现状 | 造成的结果 |
|---|---|---|---|
| 1 | **没有常驻框架** | 所有元素居中堆叠，无顶栏、无分区 | 玩家看不出"这是一个有多个系统的游戏" |
| 2 | **货币藏在角落** | 「沉淀生物质」14px 标签 + 22px 数值挤在右上 | 局外核心资源不显眼，玩家不知道"钱"存在 |
| 3 | **入口是一排按钮，不是图标** | 装置坞 / 图鉴 两个 180×48 文字按钮并排 | 无图标、无分类、无层级，看不出是两种不同性质的功能 |
| 4 | **主形象是"卡"不是"角色"** | 3 张 268×124 并排卡 | 没有视觉焦点，读起来像商店货架，不像"我选的是这艘船" |
| 5 | **系统不可枚举** | 全部混在一处 | 玩家无法一眼说出"这游戏有哪些系统" |

**参照物的结构（只借结构，不借视觉）**：土豆兄弟把主菜单拆成三层——
① 顶部常驻资源条；② 边缘一排**带图标的功能入口**（商店 / 会员 / 礼包…）；③ 中央一个**大角色 + 一个主按钮**。
这是品类通用的 hub 范式，不是某一家独有的版式。**我们只借用"常驻条 + 图标入口 + 中央主形象"这套信息架构，配色、图形、九宫格全部按本项目自己的赛博霓虹深海重做。**

## 2. 栅格与安全区

| 项 | 值 | 依据 |
|---|---|---|
| **设计基准** | `1304 × 749` | `cocos/settings/v2/packages/project.json`（**已确认，不改**） |
| 适配策略 | `fitWidth = true` | 同上。**宽度锁定 1304，可见高度随屏幕比例变** |
| **基准栅格** | **12 列**，边距 `32`，栏距 `20`，列宽 `85` | `12×85 + 11×20 = 1240`，`+2×32 = 1304` ✅ 正好铺满 |
| 安全区 | 左右 `32`，上下 `24` | 横屏刘海在侧边，左右各留 32 |
| 元素对齐 | 尺寸与位置一律为 **4 的整数倍** | 避免半像素造成的描边模糊与缝隙 |

### 2.1 高度安全带的算法（这是 fitWidth 侧最容易踩的一条）

`fitWidth` 下：**可见高 = 1304 ÷ 屏幕长宽比**，且以设计中心 `y=374.5` 为轴对称裁切。

| 屏幕比例 | 可见高 | 可见 y 区间 | 顶栏(0–72) | 主按钮(578–646) | 底栏(664) |
|---|---|---|---|---|---|
| 4:3 (1.333) | 978 | 全见 | ✅ | ✅ | ✅ |
| 16:10 (1.600) | 815 | 全见 | ✅ | ✅ | ✅ |
| **16:9 (1.778)** | **733** | **[8, 741]** | ✅ | ✅ | ✅ |
| 19.5:9 (2.167) | 602 | [74, 676] | ⚠️ 裁 2px | ✅ | ✅ |
| 21:9 (2.333) | 559 | [95, 654] | ❌ 裁 23px | ✅ | ❌ |

**结论**：**主目标 16:9 桌面（键盘操作 + `.bat` 启动，本来就是桌面定位）**，顶栏贴顶、底栏贴底都安全。
**若日后要出手机横屏**：把顶栏整体下移到 `y 96` 起、底栏上移到 `y 660` 前，**中央三个区块（标题 / 主形象 / 主按钮）一律不用动** —— 它们已经落在 21:9 也可见的 `[95, 654]` 带内。

### 3.2 左右分类栏（**自适应 N 个入口**）

> **本节是 V6.38 修订点**（2026-10-13 晚）。原版按"每列 2 项"写死坐标；
> 现改为**按入口数 N 自动布局** —— 后续新增系统入口（任务 / 更多）**只改数据、不改版式**。
>
> 触发原因：用户原话「一定要为后面功能扩展留余地，后面可能还有**任务** ICON 的布局，
> 可能有可能会**换位置**」。

**布局公式**（一侧列内 N 个入口，元素自上而下 = 块 → 16 → 标签 20）：

```
整列高 H = (N − 1) × 节距 + 块边长 + 16 + 20
块 1 顶部 y = 392 − H ÷ 2          // 392 = 中央主形象中心（§3.3），整列与之垂直对齐
```

| N | 块边长 | 节距 | 整列高 H | 块 1 顶部 y | 末标签底 | 判定 |
|---|---|---|---|---|---|---|
| **2**（现状） | 96 | 184 | 316 | 234 | 550 | ✅ 舒适 |
| **3**（加"任务"后） | **88** | **164** | 452 | 166 | 618 | ✅ 舒适（16:9 与 21:9 均可见） |
| 4 | 80 | 140 | 536 | 124 | 660 | ⚠️ **仅 16:9 可行**，21:9 裁尾 |

**→ 每列舒适上限 3 个，物理极限 4 个。左右合计舒适 6 个入口。**

**列标题（收藏 / 成长）取消**。理由：N=3 时块 1 顶到 y166，与标题带冲突；
且"左右分列"本身已表达分组语义，标题冗余。**概念图（`docs/ui_concept/`）里本就没有。**

**列容器虚线框取消**，改为按实际内容高度绘制（虚线只作分区暗示，写死 400 高会与实际内容错位）。

**坐标速查**：

| N | 左栏 x | 右栏 x | 各块顶部 y | w | h | 标签中心 y |
|---|---|---|---|---|---|---|
| 2 | 32 | 1176 | 234 / 418 | 96 | 96 | 356 / 540 |
| 3 | 32 | 1176 | 166 / 330 / 494 | 88 | 88 | 280 / 444 / 608 |

## 4. 层级与遮罩

| 层 | 内容 | 输入拦截 |
|---|---|---|
| **L0 背景** | 峡谷轮廓 / 探照灯锥 / 水母 / 微粒 / 舱窗网格 / 扫描线 | 不接收 |

> 新版沿用同一机制，**新增的图标入口一并纳入该判断**（否则点浮层会顺手触发底层入口）。

> 与"补质感"方向相反，**已作废**。新版是**位图出图规格**：A 表是给 AI 出图时的**逐字锚点**，
> B 表是出图后**必须满足**的技术约束，C 是负面清单，D 划清了图标与框架的边界。
>
> ⚠️ **与 §8 的冲突（本轮未消解，已登记）**：§8 现写"当前不需要任何位图切图"，那是 A 全矢量时代的结论。
> 本节转位图后 §8 需同步重写 —— 本轮按"只改 §7 章内"执行，**§8 保持原样**，冲突见 §10.2 末尾。

**A. 提示词锚点（每张图标出图时逐字复用，一字不改）**

| # | 要素 | 规格 |
|---|---|---|
| 1 | **载体 / 画布** | 位图 png，**512 × 512 正方形**，纯色底（近白 `#f2f6fa`，**四角必须同色**） |
| 2 | **笔法** | **粗描边具象**：画成它本来的样子（书就画书、螺母就画螺母）。**实底填充，不镂空、不线框**。描边宽 ≈ 图形外接圆的 **6–7%** |
| 3 | **基底色** | **高亮冷白单色**（≈ `#e8f4ff`）。**全图只允许一个色相**，明暗只能用同一色相的明度差表达 |
| 4 | **明暗阶梯** | **四档固定**：受光面 `100%` / 中间面 `74%` / 暗面 `48%` / 描边与投影 `24%` |
| 5 | **体积四件套** | `⓪外投影（右下偏移）→ ①侧壁 → ②受光面 → ③暗弧`，**缺一条就平**。光源固定在**左上**，不随物体旋转 |
| 6 | **留白率 / 等大** | 图形外接圆直径 ≤ 画布 **72%**（512 → ≤ 368px），四边留白 ≥ 14%。**多图标同图时，各图标外接圆直径必须相等** —— 实测不写这句，同一张图里会一大一小 |

**B. 落地技术约束（出图后必须满足，逐条可验）**

| 约束 | 值 | 为什么 |
|---|---|---|
| **四角同色** | 四角必须同一纯色，饱和度 ≤ 5 | 抠底走**四边泛洪**（`tools/process_item_art.py`），参考亮度取自四角 |
| **图内投影** | 外投影**必须画在画布内**，不得溢出边缘 | 投影溢到四边会被泛洪当背景吃掉，或裁成硬切边 |
| **可染性** | 基底**明度 ≥ 90%** | 染色是**乘法**（`sprite.color` 只能压暗、不能提亮）。基底不够亮 ⇒ 染不出饱和青 |
| **单色化兜底** | 生成图若带多色相，**由管线强制"取明度 → 映射到单色阶"** | AI 对"只用一个色相"的服从度低；让它的自由度服务于**形状**，色相统一交给管线 |
| **可辨识性** | 缩到 24px 涂成纯黑剪影，仍能认出语义 | 与旧版同一条守则，**保留** |

**C. 负面清单（⚠️ 实测：前两条必须写成**独立硬约束段**，混在负面词清单里会被完全忽略）**

> ⚠️ **硬约束（违反即作废 —— 2026-10-13 打样 V1 实测翻车点）**
> 1. **禁止给图标加任何底衬** —— 方形 / 圆形底板、卡片底、圆角矩形衬托、浅色方块**全都不许**。
>    图标外轮廓之外必须**立刻就是背景纯色**。
>    *翻车现象*：模型把"图标"理解成"图标组件卡"，给每个图标自己加了一块白色圆角方块底。
>    这直接违反 §7.1 D（只出图形本体），且会让抠底泛洪把方块当主体保留下来。
> 2. **禁止任何文字** —— 汉字 / 字母 / 数字 / 标签 / 标注 / 签名 / 水印。
>    *翻车现象*：模型自己给每个图标下方写了名称（"图鉴 / 装置坞 / 海域"）。
>
> **软约束（常规负面词，写进 prompt 末尾）**
>
> 不要多色相 / 不要渐变彩虹 / 不要细线（缩到 24px 会消失）/ 不要 3D 渲染 /
> 不要扁平纯色块 / 不要镂空线框 / 不要透视缩短 / 不要卡通表情大眼睛 / 不要背景装饰与分隔线

**D. 图标位图的边界（重要）**

> 图标位图**只出图形本体，不含槽位底**。槽位底（四态的底槽 + 描边 + halo）是**框架元件**，归 §8，按状态换色。
> 理由：一块图形要在 24 / 48 / 88 / 96 四档复用；把底槽烘焙进图里，四档尺寸就得出四套底槽。

### 7.5 出图流程（三阶段，**批量前必须过一次确认**）

| 阶段 | 做什么 | 通过判据 |
|---|---|---|
| **① 打样** | **一张图里画 3 个不同语义的图标**（书本 / 螺母+手柄 / 定位针），同底同光同笔法 | ①三个图标看起来像**同一套**（一致性）②能**切分**成 3 张独立图（复用性） |
| **② 确认** | 打样图交用户过目 | 用户点头后才进批量 |
| **③ 批量** | 按 §7.4 工单出剩余图标 → 走抠底管线 → 落地 | §7.1 B 表五条约束逐条过 |

> **为什么要打样**：概念图里的图标是 AI 顺手画的**示意物**，不是"图标家族的锚点"。
> 整套图标要逐一出图，真正的风险不是"单个好不好看"，而是"**凑一起像不像一套**"。
> 打样同时验证"能否一次出多个再切分" —— 若可行，6 张能压到 **2 次出图**。
>
> **打样不合格的处置**：不是重出单个，而是**回头改 §7.1 A 表** —— 锚点没锁住，出多少张都是返工。

**抠底管线要注意的两点**（`tools/process_item_art.py` 当前是**为 2:1 立绘写的**，吃 UI 元件必须先改）：

1. **画布比例**：立绘是 2:1（`CANVAS 1200×600`、`FILL=0.86`）；图标是 **1:1**，需新增方形分支。
2. **泛洪判据要重标**：立绘靠"外周一圈深色描边"挡住泛洪；图标描边更粗（6–7%）但**内部暗面明度仅 48%**，
   与背景反差比立绘小，`BG_STEP` 等阈值必须重新标定，否则泛洪会吃进图形内部。

## 8. 九宫格与切图

> **V6.40 更新（2026-10-13 深夜）**：本节原为 A 全矢量时代的结论（"当前不需要任何位图切图"），
> **已过时**。主界面现在有**两类位图**：① 背景整图 ② 6 个功能图标。
> 两者都**不做九宫格**（理由见下），但九宫格规格仍需为"面板底 / 主按钮"预备。

### 8.1 现状：哪些是位图、哪些仍矢量

| 素材 | 形态 | 是否九宫格 | 依据 |
|---|---|---|---|
| 主界面背景 | **位图整图** 1536×1024 | ❌ | 固定尺寸铺满，按 **cover** 缩放（见 `主界面深海化_V6.40.md` §1） |
| 6 个功能图标 | **位图** 512×512 单色可染 | ❌ | **固定正方形**，缩放后整块贴上，没有"可拉伸区"的概念 |
| 顶栏底 / 槽位底 / 主按钮 / 标题 / 货币菱形 | **仍是矢量**（`GLASS` 色板） | — | 连续变化的动态层或纯装饰，切图反而要处理多分辨率对齐 |
| 面板底（装置坞 / 图鉴） | **仍是矢量** | — | 同上一行 |

**为什么"背景整图"和"图标"不用九宫格**：九宫格存在的意义是**同一个底板要适配多种尺寸**
（按钮有长有短、面板有大有小）。而这两者的尺寸都**唯一确定**：
背景按屏幕 cover，图标固定正方形。给定尺寸的图**不该切九宫格** —— 切了反而多一层
"边界值算错就接缝"的风险。

### 8.2 为"面板底 / 主按钮"预备的九宫格规格

> 现在还是矢量；下列值**现在就定死**，将来换成位图素材时直接照做，不重画。

| 素材 | 尺寸 | 圆角 | 具名边界值（左 / 上 / 右 / 下） | 依据 |
|---|---|---|---|---|
| 主按钮底 | 340×68 | 11 | **16 / 16 / 16 / 16** | 角块 ≥ 圆角 11 + 描边 2×2 = 15 → 取 16（4 的倍数） |
| 装置坞 / 图鉴面板 | 880×660 | 14 | **24 / 24 / 24 / 24** | 角块 ≥ 圆角 14 + 描边 2×2 = 18 → 取 24（4 的倍数，且留有 6px 余量） |
| 深青玻璃槽底（若日后出图） | 96×96 | 12 | **20 / 20 / 20 / 20** | 角块 ≥ 圆角 12 + 高光带溢出 4 → 取 20 |
| 顶栏底 | 1304×72 | 0 | — （纯横向填色，不切） | — |

**四引擎顺序差异（写具名值，不写序列）**：

| 引擎 | 参数名 | 顺序 |
|---|---|---|
| Unity | Sprite `Border` | **左 / 下 / 右 / 上** |
| Unreal | Slate Brush `Margin` | 左 / 上 / 右 / 下 |
| Godot 4 | `NinePatchRect.patch_margin` | 左 / 上 / 右 / 下 |
| **Cocos Creator 3.x** | SpriteFrame `Border`（绑在**图片资源**上） | **左 / 右 / 上 / 下** |

⚠️ Cocos 的 border 绑在 SpriteFrame 上 —— **一个 SpriteFrame 只有一套九宫格参数**。同一个底板要两种边界时必须出两张图。

### 8.3 图集分组与尺寸预算

| 分组 | 内容 | 上限 | 说明 |
|---|---|---|---|
| HUD 常驻 | 战斗内 HUD 元件 | 2048×2048 | `AutoAtlas` 上限（见项目记忆） |
| 主界面 | 6 图标 + 槽位底 | 2048×2048 | 图标 512×512 ×6 = 单张图集够放 |
| 主界面背景 | `title_bg.png` | — | **单独不打包**（1536×1024 单张，进图集反而浪费） |
| 特效 | `fx/sh_*.png` ×3 | 2048×2048 | 512×512 ×3 |

**2 的幂约束**：图标与特效源图都是 512×512（2 的幂）；背景 1536×1024 的宽不是 2 的幂，
但**它不进图集**，单独作为 Texture 使用，不受此约束。

```
Title (UITransform 1304×749, anchor(0,0), pos(-652,-374.5))
├─ tBack       背景色带
├─ tCanyon     峡谷轮廓
├─ tCone       探照灯锥（节点 x 摆动 + UIOpacity 呼吸）
```

> **层序的两条硬约束**（实装时踩点）：① `tTop` / `tSlots` / `tHero` **必须晚于背景层**
> （否则水母会飘在槽位上面）；② 它们**必须早于其上的图标与文字**（节点顺序即绘制顺序，
> 晚建会把图标整个盖住）。槽位底与顶栏底因此被拆成**两段**插在中间。

### 9.3 命中区写法（**必须遵守**）

锚点 `(0,0)` 的矩形节点，**位置点是它的左下角**。sim 坐标（左上角）转 Cocos：

```ts
n.setPosition(x, H - y - h)     // ← 漏了 H-y-h 不会报错，只会得到一个错一格的透明热区
```

本项目已有统一封装 `Title.hitRect(parent, x, y, w, h)`，**新的 4 个图标入口一律走它**，不要手算。

### 9.4 立绘缩放（**必须遵守**）

潜航器贴图带突出件（刺鳐有撞角 + 散热鳍，K≈1.55；灯艇几乎无突出件，K≈1.06），
按"贴图整体"缩放会让三台在屏幕上差一倍。**一律按圆盘半径缩放**：

```ts
const k = DISC / (2 * SUB_ART_R)   // DISC = 168（主界面）/ 72（旧卡面）
art.node.setScale(k, k, 1)
```

### 9.5 颜色引用（**不引新色**）

图形色走 `UI.*`（number），文字色走 `TXT.*` / `TXT_LIGHT.*`（`'#rrggbb'` 串）。
`shared/theme.ts` 已写死这条规则，**混用会得到黑字黑底**。
新增的顶栏梁色沿用 `UI.panelHi`（`MENU` 里没有 `header`，`header` 属于 `BRIGHT`——V6.37 已踩过这个坑）。
