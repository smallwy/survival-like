# 机体位图（sub_hull）规格 · V6.75 / V6.76

> 立规矩的日期：2026-10-15。用户原话：
> 「机体是 `drawBody()` 纯矢量实时绘制 **这个不行**，还是要做个**实体**，立体的哈……
> 位图机体，不要用矢量画，要有**立体感、真实美感**，**挂点要对**，符合现在的逻辑实现。」
>
> 这条结论**推翻了 2026-10-13 的"方案 A"**（当时用户拍板机体改矢量）——
> 半年内同一个问题来回一次，原因写在下面第 0 节，**别再翻回去**。

---

## 0. 为什么这次必须换位图（判据，不是偏好）

`Cocos Graphics` 的硬天花板是**无渐变 / 无模糊 / 无笔触 / 无 ADD 混合**。
矢量机体试了三轮（V6.54 侧视剖面 → V6.57 镜面亮痕 → V6.71 六炮位），
最后能给的只有「一块有明暗的板 + 一条集中的高光」——
`HULL_H` 只有 56px，**任何贯穿艇身的结构线都只可能读作"这条船被切开了"**
（竖板缝⇒铁笼、窗框⇒一排黑洞、明暗斑⇒锈渍，三版全被预览图否掉）。

⇒ 判据：**"金属质感"在 56px 量级上无法由矢量合成**，必须位图。
这与 `env` 那条"承不承认边缘是模糊的"是同一个判据的另一面 ——
位图负责质感，矢量只负责**几何精度**（挂点 / 孔位 / 炮座）。

## 2. 出图提示词（**逐字复用**，改一个字都会漂移）

> 正交侧视图（orthographic side view），一个**粗短的胶囊形深海装甲潜航舱**
> （不是鱼雷、不是长潜艇），水平放置，主体居中。
>
> ★外形比例：整体是一个**圆润光滑的胶囊 / 蛋形**，两端圆头，中部最粗，
> 总长与总高之比约 8:5（1.6:1）。千万不要细长的鱼雷形。
>
> ★表面要求（最重要）：**极简光滑**——只要大块的弧形装甲面，
> **不要铆钉、不要密密麻麻的细钉、不要细密的金属纹理、不要噪点、不要锈迹、不要划痕**。
> 舱段之间的分界只用**几道很宽的浅色带子**表示，全图表面细节总量很少。
>
> 结构：壳体由 3 段光滑弧形装甲带拼接。背脊顶部有一个低矮的半圆形凸包
> （舷盖 / 观察穹顶），上面有一扇横向长条观察窗和一根短天线杆；艏部有一个小圆形观察窗；
> 腹部下方有一道窄的条状承座。
>
> ★关键：背脊沿艇身全长有一条**平直、连续、同宽、微微凸起**的金属挂载导轨；
> 腹部有一条与之**大致对称**的挂载导轨。两条导轨上都【空无一物】——
> 没有炮管、没有炮塔、没有开孔、没有安装任何武器。
>
> 质感与光：哑光深海青蓝金属（明部 #3f6b7d / 暗部 #1e3a47，不要死黑），
> 表面一道集中的镜面高光带（光源来自左上方），外缘一圈薄薄的青蓝色霓虹描边 #4fe8ff。
> 干净的硬边填充质感，不要手绘卡通风。
>
> 不要出现：细长鱼雷形、细长潜艇、炮管、炮塔、导弹、圆形舷窗一排、脚手架、桁架、
> 密集铆钉、细密纹理、贯穿壳体的竖直线条、暗色方块、文字、水印、签名、边框、
> 投影阴影、接触阴影、透视变形。素材图要求：单一主体居中、正交视角、背景纯白。

尺寸 `1536×1024`、`quality=high`。**`background=transparent` 无效**（返回 alpha 全 255 的白底，
与 `tools/process_sub_variants.py` 头注记载一致）⇒ 出纯白底 + 本地抠。

### 出图的三条经验（四张废图换来的）

1. **"潜艇"这个词必须避开**：写了"潜艇 / 潜航器"就出细长鱼雷形（实测 3.3~3.8:1）；
   改叫"**胶囊形装甲潜航舱**"才出到 2.62。**比例靠措辞，不靠数字**
   （在提示词里写"8:5"，四张图没有一张听）。
2. **"少细节"是硬要求**：拉伸 1.67× 会把铆钉压成竖椭圆、把板缝拉粗 ——
   细节越密，失真越显眼。**56px 量级上细节本来就看不见**（见第 0 节）。
3. **图生图改比例不生效**：拿好图 + "垂直拉高 1.7 倍" 的 i2i 提示，模型原样返回
   （见 `01_出图原稿/06_…_废.png`）。比例只能靠本地各向异性缩放。

## 3. 后处理工序（`tools/prep_sub_art.py`）

```bash
python tools/prep_sub_art.py <出图.png> \
    --out docs/shots/sub_art/sub_new \
    --expose 1.35 --sat 1.15 --diag
```

脚本做四件事（每一步都对应一类"不报错的失败"）：

| 步 | 做什么 | 不做会怎样 |
|---|---|---|
| ① 抠底 | 去角标水印（复用 `dewatermark.suppress`）→ 亮度/饱和阈值 + **最大连通域** | 白底留下 ⇒ 屏幕上是个白方块 |
| ② 量躯干 | 逐列高度 `colH` 的**众数** = 躯干厚度（塔/鳍只占少数列，天然排除） | 拿含塔的"最厚列"当厚度 ⇒ 缩放错 ⇒ 挂点整体偏 |
| ③ 对齐 | **各向异性**缩放到「躯干 == `SUB_D × HULL_H`」 | 挂点与机体错位（本节最贵的一条） |
| ④ 裁剪影 | `alpha &= (HULL_OUTLINE 多边形 \| y 在躯干矩形之外)` | 位图比轮廓胖的地方会让炮座"飘"；不裁则剪影与挂点基准不一致 |
| **④c 削硬亮边** | 沿 alpha 边界把最外 `r` 圈亮度**只往下**拉向"局部内侧亮度 × 1.03"（V6.77b 新增，见第 8 节） | AI 出图**必然**带一圈 rim light ⇒ 实机上是"白色的划线" |
| ⑤ 曝光 | `out = 255·x^(1/g)` 逐通道（单调 ⇒ 色相不变） | 机体在深水里与背景糊成一片 |
| ⑥ **开槽** | 按 `SEAT_MOUNTS` 挖 6 个**发射槽**（V6.76 新增，见第 7 节） | 机体"没有孔"，安装件只能画在艇身外面 ⇒ **"你画上去的突兀感"** |

⚠️ 顺序（三条都是硬约束）：
* **④c 在 ④ 之后** —— 边界必须已经是最终剪影（否则削的是将来会被裁掉的部分）；
* **④c 在 ⑥ 之前** —— 槽口那圈 ×1.30 亮边是"这里有洞"的**主力**，削边会把六个槽一起削平；
* **⑥ 在 ⑤ 之前** —— 槽是用原像素乘系数画的，要跟着一起过 gamma；
  放到 ⑤ 之后画，槽会比艇身暗一档，读作"贴了块黑胶布"。

### ④ 的两条子规则（踩过）

* **保留 `y` 在躯干矩形之外的像素** = 保住指挥塔（背脊之上）与尾鳍（艇腹之下）这两处
  突破剪影。⛔ **不要改成"保留躯干外的所有连通大块"** —— 位图若比轮廓胖，
  多出来的那一圈本身就是个大连通块，会把裁切整个抵消掉。
* **mask 的多边形尺寸必须乘超采样倍率 `K`**（V6.75 踩：漏乘 ⇒ mask 只有躯干 1/4 宽
  ⇒ 机体被裁得只剩上下两条，而脚本一路打印"✅ 覆盖良好"）。

## 4. 曝光补偿（`--expose 2.0 --sat 1.15`）—— 是工序，不是调色

依据与 env 完全相同：**`drawVeil` 会吃掉一半亮度** ⇒ 素材要按"被压暗之后"配。
机体是**暗青金属**，不给补偿在 L3–L5 的深水里会与背景同色糊成一片
（`preview_hull_side.py --combat` 合成图能直接看出来）。

* `out = 255 · (x/255)^(1/g)`，**逐通道** ⇒ 单调 ⇒ 色相不变，白点仍保 255；
* `--sat 1.15` 让机体比水体"更青一点"（同色系靠饱和度拉开，不靠亮度）。
* ⚠️ **`--expose` 从 1.35 提到 2.0（V6.77）**：1.35 时成品本体 `p50` 只有 **61**，
  而浅海背景 L1 的 `p25` 就有 74 ⇒ 机体一半以上的像素比背景最暗的 1/4 还暗
  ⇒ 开局读作"一块黑板"（用户原话「机体本体是黑的」）。2.0 之后 `p50 = 93`。
  **判据：成品本体 `p50` 落在 90~100**（对比图 `docs/shots/hull_bright_ab.png`；1.9 档在深海开始发白）。

## 5. 渲染层接入（`DiveGame.ts`）

* **节点**：⛔ **不再有 `subShadow`**（V6.77c 已整体删除，理由见 §9）。
  → `subNode`（机体位图）直接接在 `gEnt` 之后、`gPlayer` 之前 ⇒
  矢量画的导轨 / 插座 / 炮**自然压在位图之上**。
* **摆放**（`syncSub`）：`setContentSize(SUB_HULL.w, SUB_HULL.h)`、
  `setScale(faceX, 1)`、位置由 `cx/cy` 反推。
  ⚠️ **y 必须取反**：`Gfx` 的世界 y 是 `H - simY`，Sprite 是裸节点不经 `Gfx` 包装。
  ⚠️ **镜像只翻 x**（船不翻身，只掉头）。
* **朝向**：`faceX` 的更新**上收到 `updateFace()`**，由 `syncSub`（同一帧更早）统一调用 ——
  位图朝向与炮位朝向必须用同一个 `faceX`，两处各更新一次会差一帧。
* **`drawBody` 只剩压在位图之上的部分**：背脊/腹部安装导轨（**主题色唯一落点**，
  三台潜航器靠它区分）、6 个炮位插座（只剩"空座内孔 / 未解锁齐平封板"两态，
  槽本身在位图上）、炮、炮口照明、受击泛红。
  ⚠️ **"霓虹外轮廓（兜底清晰度）"已于 V6.85g 整段删除**（见第 8.6 节）——
  它画在 `HULL_OUTLINE` 上，而位图比轮廓瘦 ⇒ 端部跑出机体外。
  ⛔ 艇身本体 / 塔 / 尾鳍 / 舷窗 / 艉推进器 / 铆钉 / 高光带**全部删除** ——
  位图里本来就有，再画一遍就是**两套塔叠在一起**（错位、重影，比缺更糟）。
* **贴图 `.meta` 必须 `trimType: "none"`**（⚠️ `auto` 会把 `rect` 裁成内容 bbox，
  而塔在上方 ⇒ 内容 bbox 不居中 ⇒ 铺到 `originalSize` 时躯干整体偏移 ⇒ 挂点错位，**不报错**）。

## 7. 发射槽（V6.76）—— 「开孔在图里，发射器插进去，只露发射头」

用户原话：
> 「我要的是你机型图自带开孔的发射槽，发射装置是直接装上去的，漏出发射头，
>   不是你画上去的突兀感。」

### 7.1 症结不是"画得不好看"，而是**画在了艇身外面**

V6.74 的插座是一块 `MOUNT_BASE_R = 15` 的**梯形悬臂台** + 台面上的孔，
台面（`dOut = 15.75px`）**整个伸在 `HULL_OUTLINE` 之外** ⇒ 六座读作"贴在艇上的六块积木"。
`Graphics` 无渐变 / 无模糊 / 无笔触 ⇒ **在艇身外面画任何零件都必然是贴纸**。

⇒ 判据（长期成立）：**一个安装件只要超出 `HULL_OUTLINE`，它就读作"画上去的"**。
   要么进图（位图承担），要么沉进机体（不破剪影）。

### 7.2 三个数字（`shared/dive/tables.ts`）

| 常量 | 值 | 约束 |
|---|---|---|
| `SLOT_HW` | 6.5 | `2×6.5 = 13px < 相邻座间距 0.46×44 ≈ 20px`（六槽之间留得住缝，否则连成一条长沟） |
| `SLOT_HD` | 6 | `≥ 发射器机匣尾部入槽量 4.1px`（否则机匣尾巴压在艇身皮肤上 = "炮躺在甲板上"） |
| `SLOT_EDGE_OFF` | 0.8 | ≈ 座心到艇缘的距离（六座实测 0.8~1.0px）。⛔ 取 1.8 时封板会**浮在艇缘之上**变成小舌片 |

### 7.3 渲染层：从"四级台阶"收敛成"插槽"

| V6.74 | V6.76 |
|---|---|
| ① 安装底板（梯形悬臂台，伸在轮廓外） | **删除** |
| ② 炮口开孔（矢量画的大圆） | **删除**（槽底内孔 + 图上自带槽承担） |
| ③ 转座，外移量 `MOUNT_BASE_R×0.58 ≈ 8.7` | ③ 转座，外移量 **`MOUNT_RING_R×0.90 ≈ 6.3`** |
| ④ 炮管 | **新增**：从槽底长到转座的**柱脚**（`2×SEAT_PORT_R = 8px` 宽）+ 槽底暗口 |

* **"插进去"的机械依据**：机匣尾端落在 `rOut − 0.58×EMITTER_SIZE = −4.1`，
  槽底在 `−SLOT_HD = −6` ⇒ **尾巴在槽内**（不是靠遮挡演的）。
* **"插在槽里"的可见证据**：柱脚 8px < 槽 13px ⇒ 槽左右各露 **~2.5px 暗腔**，
  整条槽深都有。试过 `PR+0.5`（9px）：只剩 2px 且被柱脚描边吃掉，实机上看不出来。
* **空座**：槽底一个内孔（`SEAT_PORT_R`）+ 翻边弧。⛔ **不给"可装"加呼吸光** ——
  那是又一层画上去的东西，3.2× 验收图里读作"艇身上糊了一块灰斑"。
* **未解锁**：**齐平封板**（正好填掉那个槽，外缘只溢 0.5px）+ 十字焊缝 + 暗缝描边
  （⛔ 不用主题色描边：亮边是"UI 框"的语汇，会给封板加一圈亮边 ⇒ 又变"贴上去的"）。

### 7.4 开槽的两条铁规（`bake_slots`）

1. **绝不改 alpha**。机体剪影是被 `HULL_OUTLINE` 裁出来的，那是**挂点基准**；
   挖真缺口会同时改掉"座心到艇缘"的距离，还会把 tuned 过的梭形啃成锯齿。
   槽的"外缘"就是艇缘本身 ⇒ 靠**明暗**读作凹坑。
2. **艇缘要逐列求**，不能整窗取极值 —— 0 号槽的窗口右端搭到指挥塔底边，
   "艇缘"被抬到塔顶 ⇒ 算出 9.2px 深（实际 6.4），槽会挖穿甲板。

### 7.5 验收

```bash
python tools/preview_hull_side.py --slots    # ★ 本轮主验收图：全空 / 4装1空1封 / 全装 / 1.6×
python tools/preview_hull_side.py --combat   # 实机合成（真实背景 + 6 炮）
```

`--slots` 四格，每格判一件事：① 六个孔必须**都在图上**；② 三种状态同框；
③ 每根柱脚插进自己的槽、槽在柱脚左右各露一条暗边；④ 1.6× 实机尺度还读不读得出。

## 8. 削硬亮边（V6.77b）—— 位图自带的那一圈"白描边"

### 8.1 用户报了什么

### 8.2 量化（判据）

沿 alpha 边界由外向内逐环量平均亮度（`sub_hull` 408×339，前景 69103px）：

| 距边界 | 0 | 1 | 2 | 3 | 4 | 5 | 内侧 3~5 |
|---|---|---|---|---|---|---|---|
| **削边前** | **143.9** | 132.2 | 111.9 | 100.0 | 94.2 | 90.5 | **95.0** |
| **削边后** | 93.0 | 91.9 | 85.5 | 84.2 | 83.8 | 90.8 | 86.2 |

* 削边前**最外圈比内侧亮 1.52×**（在 1536×1024 的**原稿**上更极端：167 vs 93 = **1.8×**）；
* 亮环**沿剪影成一整圈**（ASCII 分布图见 `docs/shots/hull_rim_ab.png`）—— 这正是
  "描边"而不是"受光"的判据：真实机体的边**不该整圈一样亮**；
* ⇒ **判据：最外圈 / 内侧 ≤ 1.15**。削边后 1.08× ✓。

### 8.3 做法（`de_rim()`，两处各调一次）

```
① 反复腐蚀求"距边界深度" d（0 = 最外圈）
② 参考场 ref = 只用内侧（d ≥ r+1）的亮度做**归一化 box 模糊**
   （= 边界处的"局部内侧亮度"；边界自己的高频不参与，不会被自己污染）
③ d ≤ r 的环带里把亮度**只往下**拉向 ref × target：
   g = clip(ref × target / luma, 0, 1)   ←  >1 截回 1 = **只削不补**
④ 逐通道乘同一个 g ⇒ 色相比值不变（与 ⑤ 曝光同一条"不偏色"的理由）
```

* **自适应，不做全局压暗** —— 全局压暗会把边缘真实的高光细节一起抹掉；
  `ref` 是**逐像素的局部内侧亮度**，所以艇背受光段削得少、艇腹背光段削得多。
* `g` 随 `luma → ref×target` 自然收敛到 1 ⇒ **环带边界无硬台阶**（不需要额外羽化）
  ⇒ 本函数**可以安全地连续调用两次**（源域 + 画布域），第二次几乎没有可削的量。
* 参数：`--derim-src 2`（源域，1536×1024 上 rim 是 1~2px，这里削最精确）、
  `--derim-cv 4`（画布域，K=4 ⇒ 4px = **1 实机 px**，收掉 LANCZOS 各向异性缩放在
  "不透明艇身 / 透明背景"强边界上留下的**振铃过冲**）、`--derim-target 1.03`。
  ⛔ `target > 1.2` 会留回一圈描边；`< 1.0` 边缘反比艇身暗 ⇒ 变成另一种描边。

### 8.4 两条不改

* **绝不改 alpha** —— 剪影是挂点基准（与 `bake_slots` 同一条铁规）。
* **不删 ③/③b 挂载导轨，只把它压暗** —— 它是"炮座为什么坐在这一列"的机械依据，
  整条删会让六座失去横向基准。改暗缝（色相仍是艇种色，明度压到艇身之下）后
  读作"凹进去的一条槽"，仍能读，且不再是"有人拿白笔画了一道"。

> ★ **新基线**：机体位图 = 侧视梭形 + 6 槽 + **不带硬 rim**。
> 下次用 AI 重出图，`--derim-*` 是**默认开**的（脚本默认值），不要关。

## 9. 机体投影（`subShadow`）—— V6.77c **整体删除**

用户 2026-10-15 连着两轮报它（先叫「黑底遮罩」，再指着实机截图说「我说的是截图这块的黑色」）。

### 9.1 它原来是什么

`syncSub` 里一个**独立 Sprite 节点**：**同一张机体贴图**染成 `col(0x040d14, 0.5)`，
位置 = 机体 + (5, 8)（右下），压在 `subNode` 之下。用的是同一张图的 alpha
⇒ 形状与剪影完全一致，露在剪影之外的那部分就是所谓"投影"。

### 9.2 为什么它读作"黑胶布"而不是"投影"（判据）

**贴图 alpha 直接乘 0.5 ⇒ 边缘是硬的。** 而"投影"要成立，边缘必须比它所投射的物体
**更模糊**。这是一条通用判据：

> ★ **投影的边缘必须比物体更模糊。等硬度的偏移副本 = 第二个物体，不是影子。**

📏 实机截图实测（对照图 `docs/shots/sub_shadow_ab.png`，屏幕缩放 1.386）：

| 量 | 值 |
|---|---|
| 右端露出的暗带 | 6~8 px |
| 腹下露出的暗带 | **11 px**（= 8 × 1.386 ✓ 与偏移量吻合） |
| 暗带 luma | **59** |
| 同一处水体 luma | **148** ⇒ 反差 **2.5×** |

（反推验证：`0x040d14` @50% 叠在水色 `(22,138,148)` 上 = `(13,76,84)`，实测 `(10,72,77)` ✓）

### 9.3 为什么不"改柔和"而是直接删

* 潜航器**漂在水中**，不存在"地面投影" —— 有投影反而暗示它悬在某个面上；
* 水下是漫射光，本来就不给方向性硬阴影；
* 机体位图自己已经有"暗腹 / 受光背"的体积（§8 削掉硬 rim 之后更干净）。

**若以后真要"托一下"机体**：做一张**高斯模糊过**的软阴影位图，
⛔ 不是把贴图副本加回来。预览里已留提案档 `--shadow=soft`
（`preview_hull_side.py` 的 `paste_hull`），**先看它像不像阴影再决定是否实装**。

### 9.4 预览的单一真源

`preview_hull_side.py` 的模块级常量 **`SHADOW`**（默认 `'none'`）= 实机在画什么；
`paste_hull(shadow=None)` 跟随它（⛔ 调用点别写死 `'hard'`，那是"预览比实机差一层"的老坑）。
出对照图：

```bash
python tools/preview_hull_side.py --shadowab     # ① 硬边副本  ② 删除  ③ 软提案
```

⚠️ 它用 **L1 原亮度**背景，不是 `--combat` 的 L2×0.55 —— 投影的可见度**完全由背景亮度决定**，
在 L2×0.55 上"硬边"与"删除"只差 7 luma（70.4 → 93.6 在 L1 上是 23），等于白出图。
