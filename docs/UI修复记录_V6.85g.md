## 二、第 1 条：机体立绘比武器小

### 定位（实测量化）

| 项 | 数值 |
|---|---|
| `sub_hull.png` 画布 | 408 × 339 |
| **机体内容**（不透明 bbox） | x 28..379 → **352** × 225，纵向中心 `cy = 0.5928` |
| 旧缩放 | `k = SUB_DISC_CARD / SUB_HULL_ART_W = 78 / 408 = 0.1912` |
| ⇒ 旧**画布**显示 | 78 × 69 |
| ⇒ 旧**机体**实际 | **67.3 × 43.0** |
| 武器立绘 | 框 `WPN_CARD_W − 44 = 186`，2:1（画布 600×300 同比例）⇒ 内容 **93 × 80** |

⇒ 机体宽只有武器的 **72%**、高只有 **54%**。用户感受正确。

### 根因

**缩放基准取错了口径**：`SUB_HULL_ART_W = 408` 是**画布**宽度，而画布里有一圈留给
鳍 / 撞角 / 统一几何的**留白**（机体只占 352）。按画布宽缩放 = 把留白也算进"机体有多大"。

⚠️ 武器那边**没有**这个问题：`item_*.png` 是统一 2:1 画布、内容按 `FILL=0.86` 居中，
留白比例小得多 —— 两个口径混在一起比，才会出现"配角比主角大"。

### 改法

```ts
// 新增同源常量（来源：normalize_sub_art.py 的统一画布实测）
const SUB_HULL_CONTENT_W = 352

// 卡片：基准从"画布宽 408"换成"内容宽 352"
const k = SUB_DISC_CARD / SUB_HULL_CONTENT_W   // 100/352 = 0.2841
```

| | 旧 | 新 |
|---|---|---|
| `SUB_DISC_CARD` | 78（画布口径） | **100（内容口径）** |
| 画布显示 | 78 × 69 | 115.9 × 102.6 |
| **机体内容** | 67 × 43 | **100 × 64** |

改成 100 的依据：**略大于武器的 93px** —— 语义上"潜航器是主角、武器是配角"。
卡片高 132，内容 100 宽 ⇒ 画布 116×103，上下各留 ~15px；再往上加会顶到卡片边框。

⚠️ **主形象 `HERO_DISC` 一行没动**：它是画布口径（`116/408`），等效内容宽**恰好也是 100**，
和卡片的新口径**结果一致**。所以这轮只改了卡片，没动用户没提的地方。

## 三、第 2 条：机身上的「黑点」

### 定位（实测量化）

对你的截图做像素分析：

| 实测 | 值 | 代码预测 | 结论 |
|---|---|---|---|
| 机身宽 | **99 px** | `HERO_DISC / SUB_HULL_ART_W × 352 = 116/408 × 352 = 100` | ✅ 吻合 |
| 黑圆盘暗核 | **41 px** | `CORE_R × 2 = 20 × 2 = 40` | ✅ 吻合 |

⇒ 截图是你**主界面中央区域 1:1 裁**的，那个"黑点"**就是 `drawCore` 的核心穹顶**。

### 根因

V6.85b 立了 `HULL_SHELL_OFF = true`，理由是「要让界面 = 实机，最忠实的做法就是不画」，
但它**只关了三处**：`drawHull` / `drawRing` / `drawLight`。

而 `drawCore` 的底盘是 **近黑** `0x08161f`。它本来嵌在**同为暗调**的外壳（`0x1b3243`）正中，
读作"舱盖上的能量核心"；外壳一关，近黑盘直接压在**浅青白**的机身上，
明度差从 ~15 拉到 ~130 ⇒ 观感从"核心"翻转成"机身上糊了个黑洞"。

⚠️ **改暗 / 改小都治不好** —— 几何位置就不对，只能一起关（同铁规 30 的同类）。

### 改法：`HULL_SHELL_OFF` 从"外壳开关"升级为"圆盘机构总开关"

一并收掉的 4 处（都是**按圆盘几何算出来的零件**）：

| 零件 | 为什么必须一起关 |
|---|---|
| `drawCore` | 用户圈出的黑点本身；底盘近黑、位置在圆盘圆心 |
| `drawScanArm` | 以**圆盘圆心**为轴画的（`SCAN_R0 → SCAN_R1`），圆盘没了就是一根悬空杆 |
| 推进器喷流 ⑥ | 沿 `THRUST_R = 68` 的**圆环**均布 6 处，是"环向推进器"的排气口 |
| 声呐环 ⑦ | 椭圆压扁 = **3/4 俯视口径**，是给俯视圆盘读的 |

⚠️ 喷流 / 声呐是**每帧重画**的 ⇒ 必须**先 `clear()` 再跳过**，不能提前 `return`
（否则上一帧的火苗会永久留在屏上）。

## 四、第 3 条：商店 UI 错乱 / 不齐 / 字会穿

### 定位（硬证据，不是"感觉挤"）

V6.83 把上架数 3 → `OFFER_N`（5），同时把卡宽从 **204 一刀砍到 122**。代价：

**类型标签与锁定按钮在物理上重叠了 14px。**

| 元素 | x 区间（相对卡片左边缘） |
|---|---|
| 类型标签（左对齐 `x+42`，2 字 × 13 号） | `x+42 … x+68` |
| 锁定按钮（中心 `x+cw-40`、宽 56） | `x+cw-68 … x+cw-12` |

| `cw` | 按钮区间 | 与标签重叠 |
|---|---|---|
| 204（V6.83 之前） | `x+136 … x+192` | 无 |
| **122（报错版）** | `x+54 … x+110` | **14 px** ⛔ |
| 176（修后） | `x+108 … x+164` | 无 ✅ |

而且两者 **y 区间也重叠**（标签 `y+13…y+33` / 按钮 `y+8…y+38`）⇒ **「器械」被按钮压住**。

### 附带发现：一句写错的注释

> 原文：「代价：卡宽 204 → 122，`fitText` 会把描述字号自动缩一档。」

**`fitText` 不缩字号** —— 它只**截断加省略号**（`Hud.ts:126`）。
所以描述 / 状态行全变成「新装备 · 占 1 座…」，这才是"字会穿"的实感来源。

另一处：**`up.name` 是全卡唯一漏网的裸字符串**（没有 `fitText`）。
当前最长的升级名 5 字（`脉冲机关枪` ≈ 85px @17）侥幸放得下，但**下一个更长的名字就会穿出卡片**
（`Label` 默认不裁剪、也没有 maxWidth）⇒ 已补上 `fitText(up.name, 17, cw - 24)`。

### 关键账：卡宽压根不必砍到 122

| `cw` | 面板宽 `pw = cw×5 + 10×4 + 26×2` | 占设计宽 1304 |
|---|---|---|
| 122 | **702** | **54%**（两侧各空 **301px**） |
| 176 | 972 | 75%（两侧各空 166） |

⇒ V6.83 那句「卡宽必须由面板可用宽反推」**从没算过账**。面板一直只用了 54%，白白空着 301px 两侧。

### 改法

| 项 | 旧 | 新 | 依据 |
|---|---|---|---|
| `cw` | 122 | **176** | 占设计宽 75%，两侧仍留 166 |
| `cardH` | 251 | **278** | 见下 |
| `ph`（面板高） | 429（57%） | 456（61%） | |

**卡高必须同量反推**（强联动）：

```
立绘框 ah = (cw - 28)/2          ⇒ cw 122→176 ⇒ ah 47 → 74（框底 y+122）
名称中心 = y + ch - 134           （下半区全部从卡底往上排）
两者间距要保住 22px（V6.83 卡宽 204 时的原始间距）
⇒ ch ≥ 48 + ah + 22 + 134 = 278
```

⚠️ 别再靠"减上架数"腾空间 —— **上架数 = 经济系统的取舍强度**（铁规 22），该动的是面板尺寸。
