## 一、基准画布与断点

### 1.1 画布基准

| 项 | 值 |
|---|---|
| **设计基准** | `1280 × 720` |
| 渲染方式 | Phaser Scale `FIT` + DPR 适配（见 `main.ts` `installDprScale`） |
| 最小支持 | `960 × 600` |
| 安全区 | 四周内缩 **32px**（HUD 不得越界） |

> **注意**：所有 UI 坐标**以中心为原点**（Phaser 容器 + `setScrollFactor(0)`），
> 中心点位 `(0, 0)`，左上为 `(-640, -360)`，右下为 `(640, 360)`。
> 这与本 EtOH 之前的 `-404, -286` 写法保持一致，不要改成左上角原点。

| 层 | 允许色 |
|---|---|

| **生物 / 资源** | jade / magenta / amber / violet |
| **致命预警** | `danger`，且**全场仅此一处** |

## 三、字体规范

```ts
export const FONT = "'Noto Sans SC', 'PingFang SC', 'Microsoft YaHei', sans-serif"
export const MONO = "'DIN Alternate', 'Roboto Mono', ui-monospace, monospace"
```

| 级别 | 字号 | 字重 | 描边 | 用途 |
|---|---|---|---|---|
| **H1** | 64px | 900 | 5px `#04070d` | 标题「深海回响」 |
| **H2** | 32px | 700 | 3px | 区域标题 / 结算标题 |
| **H3** | 22px | 700 | 2px | 面板标题 |
| **Body** | 16px | 400 | 无 | 正文 |
| **Small** | 14px | 400 | 无 | 次要信息 |
| **Num** | 20px | 700 | 1px | 数值（MONO，等宽对齐） |
| **NumLg** | 36px | 700 | 2px | 关键数值（深度 / 电量） |

### 3.1 文字清晰度规则

> 这是回应"字体很糊"的直接措施。

| 规则 | 值 |
|---|---|
| 中文**必须**带描边 | 描边色 = 面板底色，宽度 ≥ 字号 / 12 |
| 14px 以下**禁用**中文 | 太小的中文会糊成一团，改用图标 |
| 数值使用**等宽字体** | 避免跳动的数字导致视觉抖动 |
| Phaser Text 的 `resolution` | **固定为 3**（见 `main.ts` 的 monkey-patch） |

## 四、发光绘制系统

> 实现文件：`src/render/neon.ts`（新建）

### 4.1 三层发光公式

```ts
neonStroke(g, shape, color, opts)
// 内部依次绘制：
//   g.lineStyle(w + 24, color, 0.12)   // bloom
//   g.lineStyle(w + 8,  color, 0.35)   // halo
//   g.lineStyle(w,      color, 1.0)    // core  ← 清晰感的来源
//   g.strokeShape(shape)
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `w` | 2 | core 线宽（保证锐利） |
| `alphaCore` | 1.0 | 不可调低——低了就糊 |
| `alphaHalo` | 0.35 | |
| `alphaBloom` | 0.12 | |
| `pulseHz` | 0 | >0 时开启呼吸，`alpha *= 0.8 + 0.2*sin(t)` |

### 4.2 为什么必须有 core 层

纯柔光 = 一团糊光，没有"清晰"可言。
**1-2px 的 100% 实色描边是整个画面锐利感的锚点** —— 即使 halo/bloom 因缩放变形，core 始终锐利。

### 4.3 禁止

- ❌ `setBlendMode(ADD)` 直接用于主视觉（Canvas 下崩，见 §8）
- ❌ `fillGradientStyle()` 用于大面积（Canvas 下填单色）
- ❌ 无描边的发光 entity（会糊成一团）

## 五、HUD 版式（精确坐标）

> 原点 = 屏幕中心。所有 `setScrollFactor(0)`，Depth = 100+。
> **V3 版式总表**（对应《项目计划书》V6 §3，美术计划 V4 §8）

| # | 区域 | 位置 | 状态 |
|---|---|---|---|
| ① | 深度层指示 | 左侧竖贯 | 保留 |
| ② | **氧气条（主 HUD）** | **顶部居中** | **取代电量环** |
| ③ | **波次进度** | 氧气条右侧 | **取代声呐盘** |
| ④ | **生物质** | 右上角 | **取代货舱** |
| ⑤ | **装备槽 ×3 + 被动槽 ×6** | 底部 | **取代捕捞蓄力条** |
| ⑥ | **层末：补给站 / 下潜决策面板** | 全屏中央 | **取代暴露度条** |

### 5.1 ① 深度柱（左侧竖贯）

| 项 | 值 |
|---|---|
| 位置 | `x = -604`，`y` 从 `-290` 到 `290` |
| 宽 | `28px` |
| 背景 | `UI.panel` α .55 + `UI.line` 1px 边框 |
| 5 层刻度 | 按深度比例分段，每段顶部一条 `UI.line` |

```ts
// 层的颜色随深度变化，让玩家用余光也能知道在哪一层
// 注意：这是「UI 可读版」色，比《美术资源计划》V3 §4.2 的环境主色提亮了 30-40%
// —— L3/L5 的环境主色接近纯黑，直接用在 HUD 上会看不见。环境色与 UI 色解耦。
const ZONE_COLORS = [
  0x4fe8ff, // L1 阳光带 · 青蓝
  0x3d6fd6, // L2 暮光带 · 靛蓝
  0x7a4fff, // L3 无光带 · 紫蓝（环境主色为近黑，此处提亮）
  0xff8a3c, // L4 热泉带 · 琥珀橙
  0xa06bff, // L5 深渊带 · 紫
]
```

| 子元素 | 位置 | 字号 |
|---|---|---|
| 当前深度数值 | `(-604, -318)` 居中 | **NumLg 36px** MONO，单位 `m` 20px |
| 下一层标签 | `(-604, 330)` | Small 14px，`TXT.dim` |
| 当前指示箭头 | 沿柱移动，指向当前深度 | 三角形 + `UI.cyan` |

### 5.2 ② 氧气条（顶部居中 · **主 HUD**）

> **氧气是本作唯一的死亡判据**（归零 = 溺水 = 本局全损），必须占据最显著位置。
> 对应 V6 §3.2、V4 美术 §8.2。

| 项 | 值 |
|---|---|
| 中心 | `(0, -318)` |
| 尺寸 | `420 × 18`，圆角 `9` |
| 底槽 | `UI.panel` α .7 + `UI.line` 1px 边框 |
| 填充 | 按下表取色 |
| **上限刻度** | 条体右侧有一段**灰色余量区**，表示「本层氧气上限被压缩了多少」 |
| 数值 | 条体中央，`Num 22px` MONO，`72 / 100` 格式 |

| 氧气 | 填充色 | 附加效果 |
|---|---|---|
| > 50% | `UI.cyan` `#4fe8ff` | 无 |
| 20-50% | `UI.amber` `#ffd166` | 缓慢脉动（2Hz） |
| **< 20%** | `UI.danger` `#ff2e63` | **呼吸脉冲 4Hz** + 全屏边缘泛白色气泡 α `.15` |

**上限压缩的视觉化（关键）**：下潜时氧气上限从 100 → 85 → 70 → 60，条体**物理性地变短**，灰色余量区变长。
这条必须做得可见——它是玩家理解"越深容错越小"的唯一显式信号。

### 5.3 ③ 波次进度（氧气条右侧）

| 项 | 值 |
|---|---|
| 中心 | `(248, -318)` |
| 文字 | `第 7 / 20 波`，`Num 18px` MONO |
| 层内点 | 4 个圆点（半径 `4px`），已完成填 `UI.cyan`，未完成填 `UI.line` |
| 层标签 | 文字下方，当前层名，`Small 14px`，**用该层主色**（见 §5.1 `ZONE_COLORS`） |

### 5.4 ④ 生物质（右上角）

| 项 | 值 |
|---|---|
| 中心 | `(560, -318)` |
| 图标 | 左侧 20×20 单线几何图标，`UI.jade` |
| 数值 | `Num 24px` MONO，`UI.jade` |
| 增量反馈 | 获得时数字跳动 + 短暂 `UI.jade` 辉光 0.3s |

| 状态 | 表现 |
|---|---|
| 有空位 | 静态 |
| 剩 ≤2 格 | 空框缓慢呼吸 `UI.amber` |
| **已满** | 整体 `UI.danger` 边缘闪 2Hz + 文字提示「货舱已满」 |
| 上限外（超额） | 不可达 |

**样本总数**：右下角小字，**Num 20px**，格式 `样本 12`。

### 5.5 ⑤ 装备槽 / 被动槽 / 技能（底部）

| 项 | 值 |
|---|---|
| 装备槽 | **3 个**，`44 × 44`，间距 `8px`，左下角起 `(-560, 300)` |
| 被动槽 | **6 个**，`28 × 28`，间距 `6px`，右下角起 `(360, 306)` |
| 空框 | `UI.line` 1px，α `.5` |
| 已装 | 武器图标 + `UI.cyan` core 描边；**已进化的加一圈 `UI.jade` 外环** |
| 技能冷却 | 底部中 `(0, 300)`，圆环 `r=22`，冷却时逆时针填充 `UI.cyanDim` |

> 装备槽显示的是**武器形态**不是数值；进化后图标必须变化（V6 §5.2 质变密度原则）。

### 5.6 ⑥ 层末：补给站 与 下潜决策面板

> **这是本作唯一的"非 survivors"画面，也是差异化的门面**（V6 §3.3）。

| 项 | 值 |
|---|---|
| 面板 | 居中，`720 × 420`，`UI.panel` α `.92` |
| 标题 | 当前层名 + 「补给站」，`H3` |
| 商品区 | 3-4 个卡片（氧气罐 / 武器 / 被动），横排 |
| **决策区** | 面板底部两个大按钮，并排 |

| 按钮 | 尺寸 | 颜色 | 内容 |
|---|---|---|---|

## 八、Canvas 降级规则

> **这是本项目踩过的最贵的坑，必须无条件遵守。**

### 8.1 问题

无头验证环境（`--disable-gpu`）下 Phaser 走 **Canvas 渲染器**（`renderer.type === 1`）：

| API | Canvas 下表现 |
|---|---|
| `setBlendMode(BlendModes.ADD)` | **画成实心白 / 青色块** |
| `fillGradientStyle()` | **忽略渐变，填单一色** |

### 8.2 强制规则

| # | 规则 | 替代写法 |
|---|---|---|
| **1** | 禁止直接用 ADD 混合 | 用**同色多层半透明叠加**模拟发光（见 §4.1 三层公式） |
| **2** | 禁止大面积渐变填充 | 用 **N 条纯色横带** `lerpColor` 模拟（已有实现：`TitleScene.buildBackdrop`） |
| **3** | 标题发光不用 ADD | 用 `setStroke(color, 10)` + `setAlpha(.3)` 叠加副本 |
| **4** | 粒子不带 blendMode | 直接 tint + alpha |

### 8.3 验收

```bash
python3 tools/shoot_game.py docs/shots   # 无头 = Canvas 渲染器
```

通过标准：**画面不得出现任何大面积实心白 / 青色块。**
