## 3. 两个必须记录的坑

### 3.1 `w.dmg` 是缓存值 —— 遗物买得晚就必须重算
`Weapon.dmg` 是在**装备武器那一刻**由 `weaponStats()` 算好存进对象的。过载核心会改这个值，
所以如果玩家**先挂武器、后买过载核心**，先挂的那把武器**不会吃到加成** —— 不报错，只是数值悄悄不对。
→ 已在 `equipRelic()` 末尾调用 `refreshWeaponDmg()` 重算所有武器。

### 3.2 破血锚**刻意不走 `hurt()`**
如果破血锚的补刀走 `hurt()`，每次都会命中 `resonance_core` 的暴击溅射分支，
两个遗物同时装会互相引爆（`resonance_core` 的溅射本身调 `hurt()`，理论上存在递归）。
→ `rendTick()` 走**独立轻量结算**（固定伤害、不吃随机暴击、不触发共振核心），
但**复用 `tryKill()`** 做死亡结算，保证掉骨 / 回氧正常。

> 为此把 `hurt()` 尾部的死亡结算抽成了 `tryKill()` —— 这也让 `hurt()` 更短、职责更清楚。

## 4. web 原型：本次**未跟**（重要）

**决策**：这一刀只落在 Cocos 侧。

**原因**：web 原型（`web/src/scenes/DiveScene.ts`，自带副本、不吃 `shared/dive`）**自 V6.29 起就已落后于真源** ——
证据：它的 `explode(x,y,r,dmg)` **没有 `o2per` 参数**（V6.29 的氧耦合成都没进），
进化武器（`harp_cb`/`echo_mu`/`acid_fd`/`acid_ra` 等）在 web 里也不存在。

在这基础上只补 4 条遗物，会造出"有的跟了、有的没跟"的**半对齐**新混乱。
→ **web 追平应作为独立一轮整体处理**（一次性把 V6.29 → V6.33 的差距补齐），不要夹在机制刀里。

> 已给 `web/.../drawRelicIcon` 加注释说明此事，避免后来者误加。
> **验证**：web `tsc --noEmit` 退出 0（即 web 现状未被破坏）。
