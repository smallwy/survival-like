## 一、项目定位

### 1.1 一句话

> **在无光的深海里，你是一束光。敌群成建制地从黑暗里列阵逼近——你只有一张战前情报表，和一次选择武器的机会。**

### 1.2 基本信息

| 项 | 内容 |
|---|---|
| **品类** | Survivors-like / Bullet Heaven（Steam 官方标签） |
| **题材** | 深海 · 生物发光 |
| **视觉** | 程序化像素 + 深色 + 自发光（Bio-luminescent pixel art） |
| **参照** | Brotato（结构）× 军事推演（信息战）× 深空恐惧（氛围） |
| **平台** | PC（Steam）优先，可打包桌面 |
| **开发** | 单人（Phaser 3 + Go） |
| **时长** | 一轮 run 15-18 分钟；一周目约 16 小时 |

### 1.3 设计支柱

| 支柱 | 含义 | 落地 |
|---|---|---|
| **一束光** | 玩家是画面唯一光源 | 光即视野、即生命、即货币 |
| **成建制** | 敌人不是随机刷怪，是有编制的军队 | 6 军团 × 6 阵型 × 5 种真实行为 |
| **有情报** | 战前就能看到敌军构成 | 敌情预告 5 区块 |
| **需破阵** | 玩家有主动战术手段 | 脉冲 Q / 诱饵 E |

### 1.4 不可动摇的入场券

以下四项是品类入场券，**开发中一个字都不改**：

1. 移动（WASD / 方向键）
2. 自动攻击（无需瞄准）
3. 波次制（20 波 × 45 秒）
4. 波间商店（用局内资源购买）

> 其上叠加的是本作的差异层。**入场券保证"能玩"，差异层保证"是我们的"。**

## 二、市场判断：品类还有空间吗

### 2.1 品类现状（2026年10月）

| 事实 | 数据 |
|---|---|
| 品类三巨头 | `Vampire Survivors` / `Brotato` / `DRG: Survivor` 占据 **75%+ 份额**（2025年5月数据，持续一年多） |
| 破局案例 | `Megabonk`（2025.10，$10）**2 周 100 万份**，峰值 8.8 万同时在线，**94% 好评**（5.4万评测） |
| Megabonk 的做法 | 复制动画帧 + 顶点着色器做出"定格动画式 3D"；地形有**垂直性**；**零营销**，靠主播与口碑 |
| 品类标签 | Steam 已确立 `Bullet Heaven`（2026-05-18 新增）与 450+ 开发者参与的标准化活动 |

> **判断**：品类进入寡头期，但`Megabonk` 证明格局仍可被打破。**窗口已关闭一半**——大厂正在进场做尽职调查。接下来的胜负手不是"做得更好"，而是**占领一个别人还没想到的机制位**。

### 2.2 独立游戏大盘现实（必须正视）

| 指标 | 数值 | 来源 |
|---|---|---|
| 2026 年 Steam 新作**收入中位数** | **$1,728**（截至 9/1） | Beacon Digital PR 汇编，源自 Totally Human Media / VaporLens |
| 中位数连续下降 | **12 年**（2016 年约 $15,000） |同上 |
| 每日新上架 | ~66 款（**每 22 分钟一款**） | SteamDB |
| 2025 年 20000 款中月流水破 100 万 | ~300 款（**约 1/67**） | Alinea Analytics |
| 2026 上半年 Steam 总收入 | $111 亿（历史最高），**新作仅占 21%** | 同上 |
| 收入集中度 | 前 1% 游戏占总收入 **84.6%** | 同上 |

> **含义**：Steam 在增长，但增长全部来自老游戏。本作不是和同周上线的 66 款竞争，而是和过去十年几万款打折游戏竞争。
> **对策**：定价对齐 Megabonk/Crab（$9.99-12.99）、靠主播内容而非买量、发布前 3 个月攒愿望单。

### 2.3 品类机会点（本作的落点）

`Brotato` 被玩家批评最集中的两点：

| 批评 | 是否仍成立 | 本作对策 |
|---|---|---|
| **地图全平面，无地形纵深** | ✅ 仍成立 | 深海垂直层（浅礁 → 暮光 → 无光 →热泉 → 深渊） |
| **剧情薄弱** | ✅ 仍成立 | 靠环境叙事与氛围，非文字叙事 |
| 构筑套路化、后期重复 | ✅ 仍成立 | 敌情预告让每波决策不同 |

## 三、题材决策：为什么是深海

### 3.1 从 Brotato 界面得到的三条启示

分析 `Brotato` 的界面截图后，提取三条决定性观察：

| 观察 | 含义 |
|---|---|
| **画面极简**（纯色地面 + 散石 + 纯色块角色） | 头部竞品**主动放弃**美术厚度 → **美术不是胜负手，机制才是** |
| **升级是"身体部位"**（臂/牙/肩/胸/眼） | 它有独立的**角色构建层**，不只是属性卡 |
| **商店是主屏幕**，武器带等级+伤害数值+刷新次数 | 商店承担大部分游戏时间 → **商店信息设计决定体验** |

> **战略推论**：既然大家都画得薄，把美术做厚就不是差异化，把机制做深才是。题材选择必须**优先生成新机制**，而非"视觉好看"。

### 3.2 题材占位分析

| 题材 | 占位情况 | 结论 |
|---|---|---|
| 动物 | 🔴 **已被占**：`Everything is Crab`（2026.05，首周 25 万份，前 CDPR/育碧团队，125+ 进化） | 淘汰 |
| 微观 / 昆虫 | 🔴 已占：`Grounded`、`Smalland`（强题材心智） | 谨慎 |
| 太空 / 星际 |🟡 极度拥挤 | 淘汰 |
| 丧尸 / 末日 | 🔴 品类原生题材 | 淘汰 |
| 都市怪谈 / 民俗 | 🟡 美术成本过高，不适配程序化管线 | 不适合 |
| **深海 · 生物发光** | 🟢 **空白**（survivors-like 品类内无作品） | ✅ **选定** |

### 3.3 选深海的4 条硬理由

**① 机制咬合最紧——题材直接长出机制**

深海提供一条别人没有的机制轴：**光**。

| 机制 | 说明 |
|---|---|
| 光 = 视野 | 光量决定光照半径，画面亮度即状态条 |
| 光 = 弹药 | 武器消耗光（不消耗弹药） |
| 光 = 生命 | 归零即死 |
| 光 = 货币 | 商店用光购买 |
| 敌人对光的反应 | 趋光 / 避光 / 致盲——派生出敌人 AI 差异 |

> 对照动物题材：动物只提供"可爱"，**不提供任何新机制**。

**② 美术管线天然适配**

- 深色背景 + 高饱和生物发光 = 天然的"剪影 + 自发光"结构
- 现有 `theme.ts` 已有 ADD 混合与辉光基础（`docs/shots/fx-*` 已验证）
- 像素点在深底上**对比度更高**，小尺寸可读性反而更好
- `pixelgen.py` 的 `outlined()` 描边在深底上效果最佳

**③ 缩略图辨识度极高**

黑底 + 青蓝/品红辉光 = 极高对比，在Steam 信息流里一眼可辨。对比 Megabonk 低模 3D、Crab 浅色像素。

**④ 环境成本极低**

深海靠"黑暗 + 偶发生物"制造恐怖，**不需要建造场景资源**。对程序化管线是最优解。

### 3.4 护甲相克链（从材质改为生物组织）

> 这是"题材 → 机制"的关键映射。护甲从制造材质变成生物组织，相克从数值变成**生物学直觉**。

| 原护甲 | 新护甲 | 生物直觉 | 相克武器 |
|---|---|---|---|
| 裸装 | **胶质** | 水母、透明软体 | 电击 / 穿刺（破膜） |
| 塑料 | **鳞甲** | 鱼类鳞片 | 钝击 / 切割 |
| 金属 | **钙壳** | 藤壶、贝类 | 强酸 / 高频震荡 |
| 发条 | **骨质** | 头足类、内骨骼 | 穿刺 / 电击 |

> **玩法收益**：玩家不用查表——看到"钙壳"就知道酸有效。**这才是"打三下就记住"的设计**。

## 四、核心玩法：怎么玩

### 4.1 一局游戏（run）的完整流程

```
┌─ 备战阶段 ─────────────────────────────────┐
│ ① 选关卡（深海深度层节点树）               │
│ ② 看敌情预告（下一波/下一关的敌军构成）    │
│ ③ 选角色（4 名潜行者，各带 1 项特性）       │
│ ④ 选初始武器（6 槽中选 1~2 把）            │
└──────────────┬──────────────────────────────┘
               ↓
┌─ 波次循环（每关 20 波，每波 45 秒）─────────┐
│ ⑤ 战斗：移动走位，武器自动攻击             │
│    → 击杀掉落「光」（经验 + 货币合一）     │
│    → 光量归零 = 死亡                       │
│ ⑥ 波末结算 → 商店                │
└──────────────┬──────────────────────────────┘
               ↓
┌─ 波间商店 ─────────────────────────────────┐
│ ⑦ 用光购买：武器 / 部件 / 光源             │
│ ⑧ 刷新商品（消耗光）                       │
│ ⑨ 查看下一波敌情 → 决定是否针对性备战      │
└──────────────┬──────────────────────────────┘
               ↓
     回到 ⑤，直至第 20 波 Boss
               ↓
        结算 → 局外解锁（后端存档）
```

### 4.2 核心资源：光（Light）

**本作把"经验"和"货币"合并为一个资源的关键设计。**

| 特性 | 说明 |
|---|---|
| **光量 = 生命值** | 归零即死（比 Brotato 的 HP 血条更紧张，每次受击都是真实损失） |
| **击杀掉落光** | 敌人死亡掉落光点，**必须冒险去捡** → 天然走位张力 |
| **光量 = 货币** | 商店用光购买 → **同一份资源既是命又是钱** |
| **光照半径** | 光量越高视野越好（画面亮度= 光量）→ **视觉上直接可读的状态条** |

> **决策张力**：Brotato 里"血"和"钱"是两套数值，玩家可以"血多钱少"。本作合并后，**每一次消费都是拿命换**。
>
> **额外收益**：解决了 Brotato 的真实缺陷——它的 HP 只是数字，玩家感觉不到危险。光量可视化后，玩家会真的因为"光快没了"而手抖。

**光的经济设计**

| 来源 | 数量 | 说明 |
|---|---|---|
| 击杀普通生物 | +1~3 | 按体型 |
| 击杀精英 | +8 | — |
| 击杀 Boss | +50 | — |
| 波末保底 | +20 | 保证不会因打不过而卡死 |
| 拾取光点 | = 掉落量 | **需冒险去捡**，这是张力的来源 |

| 支出 | 数量 | 说明 |
|---|---|---|
| 购买武器 | 8 × 品质 | 品质 I~IV |
| 购买部件 | 5~30 | 按稀有度 |
| 刷新商品 | 3（递增） | 高级刷新 8 |
| 主动技 Q | 5 | 每次释放 |
| 修复（关卡内） | 10 | 见好就收 |

### 4.3 玩家操作（4 个键）

| 键 | 行为 | 说明 |
|---|---|---|
| `WASD` / 方向键 | **移动** | 唯一的移动操作 |
| 自动 | **攻击** | 武器自动开火，无需瞄准 |
| `Q` | **光源脉冲** | 消耗 5 光，范围冲击波 + 致盲敌人 2秒 |
| `E` | **诱饵** | 消耗 8 光，投出发光诱饵，**把成阵敌人拉走** 3 秒 |
| `空格` | **冲刺** | 短 CD 位移突进，带无敌帧 |

> **设计约束**：主动技只有 2 个，给玩家战术表达但**不增加操作负担**。
> `E` 诱饵尤其重要——因为敌人**成建制列阵**，玩家需要手段去**破坏阵型**，这是 Brotato 没有的决策层。

### 4.4 敌军系统（核心差异所在）

#### 4.4.1 四层结构

```
群系 Faction（谁在打你）
  ↓ 决定数值倍率与生物池
阵型 Formation（怎么摆）
  ↓ 决定阵位与行为
兵种 Role（用什么兵）
  ↓ 决定护甲与职能
护甲 Armor（怎么破）
  ↓ 决定伤害倍率
```

#### 4.4.2 群系表（6 个）

| 群系 | 生态带 | 数值倾向 | 阵型偏好 | 视觉 Sig |
|---|---|---|---|---|
| **浅礁群落** | 阳光带 | hp 低 / 数量多 | 蜂拥、蜂拥 | 珊瑚枝桠、海葵触手 |
| **中层游猎** | 暮光带 | speed 高 / hp 中 | 锋矢、雁行 | 密集鱼群剪影 |
| **管栖矩阵** | 海底平原 | hp 高 / speed 极低 | 叠砖、方圆 | 钙壳管虫密集阵 |
| **深渊猎手** | 无光带 | 攻击高 / 数量少 | 月牙、包围 |鮟鱇诱饵灯 + 巨口 |
| **异变污染** | 全域 | 全属性高 + 变异 | 随机 | 发光畸变体 |
| **巨兽** | Boss 层 | — | 单体 | 章鱼 / 鲸鲨级剪影 |

#### 4.4.3 阵型表（6 种，6 种真实行为）

> **这是全品类空白**。Brotato 的敌人是随机撒点，没有任何主流作品做"敌方成建制列阵推进"。

| 阵型 | 阵位结构 | 行为 | 随波次变化 |
|---|---|---|---|
| **蜂拥** | 全前排密集 | `advance` 直压 | 否 |
| **锋矢** | 尖头纵深 | `charge` 1.35 倍速冲脸 | 否 |

#### 4.4.5 敌人 AI：趋光与避光

> 这是深海题材**必须做出来**的机制，也是 `Q` 主动技的价值来源。

| AI 类型 | 行为 | 出现群系 |
|---|---|---|
| `advance` | 直压玩家 | 通用 |
| `charge` | 加速冲脸 | 中层游猎 |
| `flank` | 从两翼夹击 | 深渊猎手 |

#### 4.4.6 敌情预告（核心差异化 UI）

> **Brotato 的商店是纯数值题——钱够就买最强的。**
> **本作的商店是情报题——钱够，但你买的东西能不能破这波阵，是另一道题。**

波间商店顶部常驻**敌情卡**，含 5 个信息区块：

```
┌─ 第 7 波 敌情 ────────────距下一波 0:12 ─┐
│ [群系] 中层游猎speed×1.2  hp×1.0   │
│ [阵型] 雁行  ⚠ 第4波起改为两翼包抄        │
│   ╱╲  ← 实时阵型示意图（零美术成本）      │
│ [兵种] 前排60% 中军25% 后排15%            │
│         ████████░░░░           │
│ [护甲] 胶质70% 鳞甲30%                    │
│ [破法] ✦电击  ✦切割← 由 vs 反查          │
│         [诱饵] 对密集阵型有效│
└─────────────────────────────────────────┘
```

**为什么这个设计有真实价值**：

| 维度 | Brotato | 本作 |
|---|---|---|
| 商店决策性质 | 纯经济题| 经济题 **+** 情报题 |
| 构筑方向 | 追求"通用强度最高" | "**这波能破**" vs "**通用但贵**" |
| 决策链 | 想要什么 → 买 | 想破什么 → 查情报 → 买对应武器 → **可能要放弃通用强度** |
| 重玩驱动力 | 换 build | 换 build + **每波重读情报做决策** |

**成本极低**：`FACTIONS.roles` / `FORMATIONS.slots` / `WEAPONS.vs` 三张表本已存在，只是把"打起来才知道"提前到"备战前就知道"。

> **强制约束**：必须做到"**不买对应武器就打不过**"。若敌情预告只是装饰（买了任何武器都能赢），说明机制未成立。

## 九、平台与朝向决策

> 合并自原 `朝向决策.md`（2026-10-10）。工具：`tools/orientation_check.py`

### 9.1 结论：横屏（16:9 基准）

这不是偏好问题，是市场结构问题。

| 证据 | 结果 |
|---|---|
| 同品类头部产品 | Vampire Survivors / Brotato / Megabonk / Soulstone **全部横屏** |
| Steam 竖屏 Bullet Heaven 成功案例 | **0 个**（900+ 款 survivors-like 中标"Vertical"的仅 5 款，且都是纵向卷轴射击） |
| 竖屏的成功案例在哪 | 全在移动端。Survivor.io 的 IAP >5 亿美元靠**广告 + 买量**，付费买断制下不成立 |
| Steam 桌面横屏分辨率占比 | **~87%**（16:9 50.5% + 16:10 8.5%，2026-08） |
| 竖屏获得 Steam Deck Verified 的公开案例 | **0 个**（Deck 1280×800 横屏，竖屏屏幕利用率仅 56%，7 英寸 UI 文字过小） |
| Valve 官方 "Bullet Heaven" 标签（2026-05） | hub 首推作品**全横屏** |

> 品类正在正规化，**正规化方向是横屏**。我们要在首推位置竞争，必须在横屏。

来源：[Steam Hardware Survey](https://store.steampowered.com/hwsurvey/)、
[survivorslikes.com](https://survivorslikes.com/)、
[GamesIndustry.biz](https://www.gamesindustry.biz/breakout-hit-megabonk-sells-more-than-a-million-copies-on-steam)、
[标签报道](https://www.tweaktown.com/news/111680/)

### 9.2 关键计算：横屏不改变难度，只改变分布

单位换算：`GameScene.ts:63 PX_SCALE=3` × `manifest.cell=32` → **一个单位 = 96px**

| 朝向 | 分辨率 | 可见网格 | 面积 |
|---|---|---|---|
| 横屏 16:9 | 1920×1080 | 20.0 × 11.2 | **225 格** |
| 横屏 16:10 | 2560×1600 | 26.7 × 16.7 | 444 格 |
| **横屏 21:9** | 3440×1440 | **35.8 × 15.0** | **538 格** |
| 竖屏 9:16 | 1080×1920 | 11.2 × 20.0 | **225 格** |

**1920×1080 与 1080×1920 都是 225 格。** 这意味着：

- 朝向**不改变难度总量** → 难度曲线可直接照搬 Brotato，**不需要重做平衡**
- 朝向只改变注意力分布：横屏是「横向拉扯」（Brotato 的手感来源），竖屏是「上下拉扯」

### 9.3 超宽屏是真正的风险（D3）

| | 16:9 | 21:9 |
|---|---|---|
| 可见网格 | 20.0 × 11.2 | **35.8 × 15.0** |
| 面积 | 225 格 | **538 格（2.4 倍）** |
| 长边 | 20.0 格 | **35.8 格（1.79 倍）** |

21:9 玩家能拉开 1.79 倍距离，而波次配置按固定值投放 → **超宽屏玩家难度显著更低**。
这批玩家通常更愿意买和推荐，所以不能用"占比只有 3%"搪塞过去。

**解法：视野按短边对齐，长边超出部分用黑暗封住。**

```
可见宽度 = min(实际宽度, 按短边比例推算的宽度)
```

这**恰好就是《深海回响》的核心视觉**：「黑暗中的一束光」，
头灯照亮半径之外本来就不该看见。视野封住不是妥协，
是**把设计约束变成美术语言**。

三层落地：
1. 短边对齐 → 所有玩家的可见**高度**一致
2. 长边超出部分**压黑** → 视觉上形成"探照灯锥形光区"
3. 光区边缘放**渐隐雾 / 悬浮颗粒** → 避免硬边看起来像 bug

### 9.4 落地实现与验证（D3 ✅ 已完成）

朝向**不是技术阻塞问题**，改造点只有一处，且钩子已存在：

```
main.ts:20          mode: Phaser.Scale.RESIZE
main.ts:22-23       width/height: '100%'       → 任意比例都能跑
GameScene.ts        this.scale.on('resize', this.layout, this)→ 钩子已存在
GameScene.ts:616    敌人生成沿矩形周长（非固定半径）→ 天然适配任意比例
```

实际改了 4 处：

| 位置 | 内容 |
|---|---|
| `GameScene.ts:74` | `const BASE_ASPECT = 16 / 9` |
| `GameScene.ts` `viewClamp()` | 短边对齐算出钳制尺寸 + 溢出条宽度 |
| `GameScene.ts` `viewHalf()` | 改走 `viewClamp()`，敌人生成/索敌/边界全部跟着钳制 |
| `GameScene.ts` `buildViewMask()` / `layoutViewMask()` | 4 块纯黑幕+ 16 条渐隐条，resize 自动重排 |

**验证结果**（`tools/view_check.py`，6 种分辨率各开一局实机跑，截图 `docs/_baseline/view-*.png`）：

| 分辨率 | 比例 | 钳制后 | 每侧黑幕 | 溢出像素 | 结论 |
|---|---|---|---|---|---|
| 1920×1080 | 1.778 | 1920×1080 | 0 | 0 | ✅ 基准未动画面 |
| 1920×1200 | 1.600 | 1920×1200 | 0 | 0 | ✅ 零溢出 |
| 1440×1080 | 4:3 | 1440×1080 | 0 | 0 | ✅ 零溢出 |
| 2560×1080 | 2.370 | 1920×1080 | 320 | 691,200 | ✅ 封黑 |
| 3440×1440 | 2.389 | 2560×1440 | 440 | 1,267,200 | ✅ 封黑 |
| 3840×1080 | 3.556 | 1920×1080 | 960 | 2,073,600 | ✅ 封黑 |

**关键判定**：超宽屏玩家钳制后拿到的战场**与同短边的 16:9 完全同尺寸**。
3440×1440 被压成 2560×1440，和 2560×1440 原生玩家一模一样 —— 难度不会因为屏幕贵而降低。

**踩过的坑（必须记住）**：

1. **`viewMaskSoft` 少建一半，直接让游戏开不起来。**
   访问公式是 `side*4+i`（下标 0-15），但只创建了 8 条，
   首次 `create()` 时 `barW>0` 就走到 `side=2`，取到 `undefined`，
   抛 `Cannot read properties of undefined (reading 'setPosition')`，
   **`create()` 整个中断，画面全黑、场景里一个对象都没有**。
   TS 查不出来（数组下标访问返回 `T` 不报strict）。
   现在是 16 条 + `if (!r) continue` 防御 + `if (!this.viewMaskL) return` 早退。
   > 教训：数组长度与下标公式必须成对写在同一处，且**只靠类型检查发现不了**，
   > 必须实机跑一遍。改完 `create()` 路径上的东西，第一件事就是开一局。

2. **无头浏览器的 `--window-size` 不等于画布尺寸。**
   16:9 那一档实际拿到 1920×1061（比例 1.810），被当成超宽屏封了黑 ——
   数字全对但结论是假的。
   现在 `view_check.py` 有 `calibrate()`：读引擎真实的 `scale.width/height`，
   反推窗口该开多大，用 `Browser.setWindowBounds` 逐轮收敛到 ±2px。
   **判定标准必须是引擎画布，不是窗口参数** —— 钳制发生在画布上。

3. **别用 `Emulation.setDeviceMetricsOverride` 改视口。**
   视口变了但 Phaser canvas 没跟上，截图回来内容只占左上角一小块，完全是假的。
   `Scale.RESIZE` 依赖真实的 `window.resize` 事件，老老实实按尺寸重启进程。

### 10.2 剪影：已解决（D5）

`tools/silhouette_check.py` 用 1-bit 掩码 + IoU 量化"两个单位能不能分辨"。

| 指标 | 现状16 单位（玩具兵） | 深海 8 单位 |
|---|---|---|
| IoU 均值 | **0.801** | **0.547** |
| IoU 最高 | **1.000**（完全相同） | 0.809 |
| **可区分（<0.65）** | **0 / 120** | **18-21 / 28（64-75%）** |
| 撞车（≥0.82） | 48 对 | **0 对** |

最严重的一对：`铁皮将军(BOSS) ↔ 吸尘器怪(BOSS)` **IoU = 1.000**，剪影完全一样。
玩家和敌人也撞车：`小绿兵 ↔ 射手` IoU=0.945。

**根因不是配色，是骨架**：`draw_head / draw_torso / draw_legs` 全是人形专用，
7 种体型只是人形比例微调，剪影轮廓本质相同。

**6 个深海剪影族**：`bell`（伞盖+触手）/ `tower`（阶梯管簇）/
`serpent`（连续曲线）/ `school`（密集三角群）/ `shell`（半球+尖刺）/
`leviathan`（巨兽阴影）

### 10.3 动画：已解决（D6）

**问题**：`pixelgen.py:231 make_pose()` 的姿态系统完全建立在人形假设上
（`fo`/`bo` 迈步、`ll`/`rl` 抬腿）。深海生物**没有腿**，直接套用只会整块抖动。

**方案**：为 6 族各配一套符合运动方式的动画语言。

| 族 | 运动语言 |
|---|---|
| `bell` | 伞盖脉动（钟状收缩）+ 触手相位滞后 1/4 拍 |
| `tower` | 管体依次伸长（相邻管相位差 0.18） |
| `serpent` | 波形沿体长传递（相位差 0.22 拍） |
| `school` | 整群**同步**抖动（与 serpent 语义区分） |
| `shell` | 左右摇摆 + 上下点浮（模拟横向游走） |
| `leviathan` | 躯干慢呼吸（周期 2 倍）+ 触手大幅甩动 |

相邻帧 IoU 均值：idle 0.830 / walk 0.807 / attack 0.745
（未裁剪掩码，**越低=动得越明显**）。24 个动作-单位组合**全部在动**。

**动画没有破坏剪影**：walk 帧重测 IoU 均值 0.580 → **0.547**，撞车仍为 0 对。

> **踩过的三个坑（写下来避免重犯）**：
> 1. **方块链动画只能靠有界位移，不能改拓扑**。试过用"参数曲线 + 密集采样"重绘
>    serpent → 横纵同时跳变，块错位叠出毛边，比原版更糟。
> 2. **摆动必须做幅度门控**（`amp`），否则静止帧也抖动，还会改坏已验证的单帧。
>    加门控后必须做**零姿态逐像素回归**（8/8 与原版一致）。
> 3. **`mask_signature` 会 trim + 归一化，适合判"物种撞不撞脸"，
>    不适合判"动没动"**（纯位移被归一化抵消，IoU 恒为 1.000）。两个问题必须两套指标。

### 10.4 方向表达：已解决（D7）

**问题**：9 行图集（3 方向 × 3 动作）里三个方向原本完全相同，
玩家分不清敌人在冲还是在撤——成建制列阵的包抄可读性直接失效。

**方案**：深海生物**没有正面背面，所以不做图像翻转**，
改用**运动方式**表达朝向：

| 方向 | 读法 | 各族表现 |
|---|---|---|
| `down` | 压低前倾，迎向玩家 | 伞盖压扁 / 巨口在躯体下部 |
| `up` | 拉长加速，向上逃逸 | 伞盖撑圆 / 巨口移到顶部（读作"壳背朝我"） |
| `side` | 压扁横切 | 横队/纵队排列 / 波动幅度 ×1.6 |

**验证**：32 组（8 单位 × 4 帧）**全部方向可区分**。

信号强度排序：`leviathan`（巨口+眼睛位置）> `shell`（凹面上移）>
`serpent`（头前伸）> `school`（横队/纵队）> `bell`/`tower`（差异偏弱，后续加强）。

### 10.9 P2 第一批：光资源与光照半径（D11-D14 ✅ 已实现）

**这一节的全部设计只有一句话：光量就是光照半径，没有第二条数值。**

如果光做成"弹药条"，玩家会理解成「我快没子弹了，去捡」——
于是光退化成第二种材料，「黑暗」只是个滤镜。
让**光照半径**随开火收缩，玩家会直接感到：我不停开火，眼前就暗下去，敌人从黑暗里压过来。

#### 规则（4 条）

| 规则 | 数值 | 为什么这么定 |
|---|---|---|
| 开火扣光 | **0.9 光/点伤害** | 扣的是 `weapon.damage` —— 「高伤武器更费光」**自动成立**，不用另配耗光表（那种表一定会和伤害表对不上） |
| 自然回光 | 7 / 秒 | 站着不动能续航，但不能边打边回 |
| 击杀回光 | 小怪 +5 / Boss +30 | **必须有这条**。只有自然回光时会陷入「没光→只能停火→怪贴上来→更打不到」的正反馈死循环。清怪即续航 |
| 两段半径 | 战术 420px / 头灯 150px，分界 45% | 连续变化在实机上读不出数值，玩家只会觉得"画面有点糊"。分段给出的是**能记住的状态** |

#### 实测踩到的三个坑

| 坑 | 现象 | 根因 |
|---|---|---|
| 遮罩盖不满屏 | 「一圈黑甜甜圈 + 屏幕两边照样看得清」 | 遮罩直径 = 光半径×2 = 840px，而窗口 960px —— 屏幕两侧压根不在遮罩内 |
| 遮罩方向写反 | 完全看不到效果 | 贴图 alpha 写成 `AMAX·(1-t)²`：中心全黑、边缘透明，**整块遮罩本身 alpha≈0**，等于没盖 |
| 玩家反而看不见 | 中央是一个黑方块 | 不是层级问题（玩家 depth 9 > 敌人 0）。根因是**周围亮了，深色潜水服就成了全画面最黑的一块** —— 对比方向问题 |

第3 条的解法是给玩家加**轮廓光**（ADD 混合的亮青描边，depth 37），
即生物发光的边缘光 —— 深海题材的合理语言，也是所有动作游戏解决
"角色陷进同色背景"的标准手法。

#### 深度层的排序（必须同时满足三条）

| depth | 对象 | 理由 |
|---|---|---|
| 0-9 | 敌人、玩家 | 玩家略高 |
| 35 | **黑暗遮罩** | 压住敌人（可见性优先），但要在 chapterTint 之下，让章节色铺在黑暗里而不是提亮它 |
| 36-37 | 头灯 + 轮廓光 | 刚好在遮罩之上，差 1 就够 |
| 40-63 | 特效 | **留在遮罩之上** —— 远处的爆点比远处的敌人更该看见 |
| 84-86 | 章节色 / 暗角 / 视野黑幕 | UI 永远亮着，玩家永远读得到自己的血量 |

#### 已知取舍

**发光生物隔着黑暗依然可见。** 实测量到：r=0 亮度 151 → r=100 降到 36 → r=500 只剩 3-8，
但水母的自发光贴图亮度远高于遮罩压制上限，所以远处的水母仍在。
这在设定上自洽（深海生物本身就是发光的），代价是「黑暗中的一束光」的压迫感被削弱。
**要解决它得改发光体的表现方式**（发光只在自己被照到时才亮），
这是 P2 第二批「趋光 AI」要一起处理的 —— 因为两者是同一件事：
**光决定了谁能看见谁**。

**实测**：存活 34-37s、同屏 33-43 只，与 P1b 持平 —— 光资源暂未引入新的平衡回归。
