## 一、项目定位

| 项 | 内容 |
|---|---|
| **一句话** | 一个把三国做成**兵种 / 阵型 / 势力 / 计谋**四条机制链的幸存者类游戏 |
| **品类** | Bullet Heaven（Steam 官方标签，2026-05-18 新增） |
| **核心循环** | 移动 → 自动攻击 → 击杀升级 → 三选一 → 按计谋破阵 → 章节推进 |
| **不可动摇的** | 核心循环是**入场券**。移动 + 自动攻击 + 三选一升级一个字都不改（见差异化文档 2.4 Vital Shell 教训） |
| **差异点** | 在核心循环**之上**嫁接：阵型编队 + 势力行为 + 计谋主动技 + 章节主线 |
| **美术** | **像素风（程序化生成）**。用户明确要求保持，且这是成本最低的路线 |
| **平台** | 前端 Phaser 3 + TS + Vite；后端 Go（云存档 / 排行榜 / meta 解锁）；浏览器可玩，可打包 Steam |

## 四、技术方案（落地细节）

### 4.1 数据层：四张表的接口

```ts
// 势力：决定"往阵型骨架里填什么兵" + 真实数值倍率
interface FactionDef {
  id: string; name: string; motto: string; color: number; banner: string
  roles: Record<'front'|'mid'|'back'|'flank', string>  // 阵位 -> 兵种 id
  roster: Record<string, number>   // 非阵型时的基础刷怪权重
  formations: string[]             // 该势力的阵型池
  trait: string                    // 特性说明（一句话）
  countMul: number; hpMul: number; speedMul: number  // 特性落到数值
}

// 阵型：只有骨架，不含具体兵种（兵种由势力的 roles 填）
interface FormationDef {
  id: string; name: string; desc: string; counter: string
  slots: { dx: number; dy: number; role: 'front'|'mid'|'back'|'flank' }[]
  behavior: 'charge'|'advance'|'hold'|'fireline'|'encircle'
}

// 计谋：玩家主动技
interface StratagemDef {
  id: string; name: string; quote: string; desc: string
  cdSec: number; kind: 'burst'|'control'|'buff'|'guard'
}

// 战役：章 -> 关
interface ChapterDef {
  id: string; index: number; name: string; subtitle: string
  faction: string; formations: string[]; tint: number
  reward: string[]; stages: StageDef[]
}
interface StageDef {
  index: number; name: string; durationSec: number
  objective: 'survive'|'kill'|'boss'; target: number
  spawnMul: number; bossId?: string
}
```

**为什么这样分层**：`阵型(slots + role)` × `势力(roles 映射)` 让内容量变成**乘法**而不是加法。
新增一个阵型，6 个势力立刻各多一种打法；新增一个势力，6 个阵型立刻多一种填充。**零美术成本。**

### 4.2 逻辑层：三处关键改动

**① 阵型刷怪 `spawnFormation()`**

替换原来的"单只随机撒点"：

```ts
// 选阵型（来自当前章节的阵型池）→ 取阵心（屏幕外一圈）→ 按槽位落位
// 每个槽位：role -> 势力 roles[role] -> 兵种 def -> 应用势力倍率
for (const slot of formation.slots) {
  const def = enemyById(faction.roles[slot.role])
  const e = this.spawnEnemy(def, false, { x: ax + slot.dx, y: ay + slot.dy })
  e.setData('behavior', formation.behavior)
  e.setData('holdR', HOLD_RADIUS[formation.behavior])  // hold/fireline 保持距离
}
```

**② 阵型行为（改 `driveEnemies`）**

在原有"追玩家"的基础上加一层行为分支：

```ts
const beh = e.getData('behavior')
if (beh === 'hold' || beh === 'fireline') {
  // 保持 220~280px：太近后撤，太远靠近 —— 远程兵种这样才真正危险
  const hold = e.getData('holdR')
  if (dist < hold * 0.85) 速度反向
  else if (dist > hold * 1.15) 靠近
  else 缓慢绕圈
} else if (beh === 'charge') {
  speed *= 1.35
} else if (beh === 'encircle') {
  // 目标点 = 玩家外侧偏移点，绕到侧面
}
```

**③ 计谋释放 `castStratagem()`**

```ts
if (this.stratCd > 0 || this.over) return
this.stratCd = this.stratagem.cdSec * 1000
switch (this.stratagem.id) {
  case 'fire':      /* 身前 3 道火墙，创建 3 个火区精灵，overlap 持续伤害 */ 
  case 'emptycity': /* invuln += 2500 + 全场击退 260px */
  case 'slowdown':  /* 全场 setData('slowUntil', now+4000) */
  case 'ambush':    /* 8 波箭雨，每波对 220 半径内敌人造伤 */
  case 'chain':     /* 最近 10 个敌人连成铁索 + 共享一次重击 */
  case 'laststand': /* dmgScale ×1.7 持续 10s，受伤 ×1.5 */
}
```

## 六、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| **阵型在弹幕密度下读不出来** | 核心创新失效 | 阵型只在"整组生成"时成立；单只补充仍用散兵。且阵型组数有上限（同时最多 2~3 组） |
| **hold 行为导致敌人不进攻、游戏变简单** | 平衡崩 | `hold` 半径设在武器射程边缘（220~280），玩家必须主动进入危险区才能清掉；且 `hold` 兵种是远程，站定即输出 |
| **计谋过强 → 一键清屏** | 沦为无脑按钮 | 冷却 20~30s + 效果有代价（背水一战受伤 +50%）+ 不打断自动攻击 |
| **6 章 × 3 关内容重复感** | 一遍就腻 | 每章换势力（兵种构成）+ 换阵型池 + 换色调；三种关卡目标交替 |
| **新增像素单位破坏现有生成器** | 全盘返工 | 生成器是数据驱动的（FOES 表加一行即可）；生成后立即跑守卫断言 |
| **`weaponById('x')!` 类断言掩盖 undefined** | 运行时崩、白屏 | **已有守卫**：禁止对 id 查询函数使用 `!` 断言（本轮踩过，见差异化文档 §6.2） |
| **章节进度存 localStorage 丢档** | 玩家流失 | 进度随 meta 一起走后端 `/api/meta`，换设备带 pid 即续 |
