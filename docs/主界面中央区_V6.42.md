## 2. 半径层级（**这张表比那些数字本身重要**）

```
   0 –  58    潜航器立绘（HERO_DISC / 2 = 58）
  58 – 132    左右稳定鳍（根部 58 → 尖端 132，被装甲环压掉根部，露出约 42px）
  62.5– 73.5  六个姿态推进器口（中线 THRUST_R = 68，凹槽半径 5.5）
  74          壳接缝线（1px）
  75 –  81    内装甲环带（中线 RING_B_R = 78，带宽 6）
  82 –  90    外装甲环带（中线 RING_A_R = 86，带宽 8）
  90          外壳边缘 + 外缘描边
```

**排这张表的规则**：相邻两层必须留 **≥1px** 空隙，否则两层糊成一块。

⚠️ 上一版把外环带放在 r 84–92 —— **比外壳（90）还大**，环带会悬空在壳外；
推进器口又正好压在立绘边缘（都是 66）。**单个常量看不出问题，排成表才暴露**。
这是本方案里最值得留下的一条经验。

## 3. 立体感的四条线索（逐条落地）

项目既定的体积手法（`memory/MEMORY.md`「立体感 / 体积的通用手法」）：
`⓪投影 → ①侧壁 → ②受光弧 → ③暗弧`，**光源固定在世界坐标左上**。

| 线索 | 本方案取值 | 落在哪一层 |
|---|---|---|
| ⓪ 投影 | 右下偏移 **(9, 8)**，r = HULL_R + 4，近黑 α .40 | `dHull`（最先画） |
| ① 侧壁（厚度） | 主盘**下移 14px** 的同形暗盘（`0x0a1a26`） | `dHull` |
| ② 受光弧 | 左上 80°–190°，r 86，粗 **6**，`cyanHi` α .50 | **`dLight`（永不旋转）** |
| ③ 暗弧 | 右下 258°–372°，r 86，粗 **6**，近黑 α .55 | **`dLight`** |
| ★ 球面明暗 | 左上受光椭圆（偏心 −14/+14，rx 62/ry 50，α .26）<br>右下背光椭圆（偏心 +20/−20，同上，α .50） | **`dLight`** |
| ★ 外缘硬边 | 整圈 r 90，粗 1.6，`GLASS.edge` α .32 | `dLight` |
| ★ 稳定鳍 | 梯形 + 下移 5px 的暗色厚度副本 | `dHull` |

### ★ 三条是 preview 迭代出来的、规格里原本没有的

出图预览工具 `tools/preview_diver.py` 是这轮新加的。做法：用 PIL 复刻同一套几何直接出图，
**不用等 Creator**。关键收益是它暴露了两个只看代码绝对发现不了的问题：

1. **投影偏移 18/14 太大** —— 读作"后面还叠着另一个圆"，不是"浮着"。
   改到 9/8 才对。`Graphics` 画不出模糊，偏移越大越像硬邦邦的两个圆。
2. **只在壳面做明暗 = 读作"边缘一圈装饰"** —— 必须把明暗铺满**整个**圆
   （含立绘与装甲环），才读作"一块金属被光从左上照到"。
   对比见 `docs/shots/diver_layers.png` 的「①+…光源」那一格。

顺带一条：**纯圆 + 同心环 = 一块表盘**。加了两片鳍，第一眼才读作"一台机械"。

### ⚠️ 三个必须守住的约束

1. **`dLight` 永不旋转**。装甲环要转，光源不能转 —— 受光弧若跟着环转，
   玩家读作"一张贴纸在打折"（`cocos/README.md` 已知坑表第一条）。
2. **`Graphics` 没有 clip**。球面明暗的两个椭圆必须各自落在 `HULL_R` 圆内，
   否则明暗会糊出壳外。校验：受光最远 `14+62=76 < 90` ✓；背光 `20+62=82 < 90` ✓。
3. **`UIOpacity` 不向下传播**。淡入淡出必须**逐个零件**挂 `UIOpacity`（`diverOps` 数组），
   只给父节点挂一个是**静默失效** —— 不报错、零件照常全亮，只有"没淡出"这一个症状。

## 4. 为什么删掉探照锥

探照锥原本是"画面里唯一的方向线索"。删掉它之后方向线索由 **受光弧 + 暗弧 + 投影 +
球面明暗** 共同承担 —— 它们本来就在定义光源方向，而且定义得比一个锥更统一。

**结论**：删掉之后全场只剩**一个**光源说法（左上打光），比"一个锥 + 一套明暗"
两套说法并存更干净。用户这个判断是对的。

## 5. 运动时序（V6.43 四段循环 **14.4s**）

> V6.42 是"下潜 → 沉底淡出 → 顶部淡入"，被用户判为「下潜到底部很突兀的回到上方」。
> **淡入淡出并没有解释位移，只是把瞬移藏起来了。** V6.43 删掉淡出，改成真实上浮。

| 段 | 时长 | 位移 | 速度 | 气泡 | 推进器 |
|---|---|---|---|---|---|
| 顶部待机 | 1.0s | 不动（y=380） | — | 艉部零星 0.30s | 怠速 `boost=0` |
| 下潜 | 6.4s | 380 → 556 **线性** | 27.5px/s 恒定 | 艉部尾迹 0.18s | 微推 `0.18` |
| 吹除压载 | 1.4s | 不动（y=556） | — | **艇下两侧排气 0.07s** | `0 → 1` |
| 上浮 | 5.6s | 556 → 380 **smoothstep** | 峰值 47px/s | 排气 0.09s | `1 → 0.7` |

### 5.1 为什么下潜用线性、上浮用 smoothstep

不是为了好看。两个速度曲线的**峰值比**决定了读感：

| | 平均 | 峰值 | 与下潜的比值 |
|---|---|---|---|
| 下潜（线性） | 27.5px/s | 27.5px/s | 1.0 |
| 上浮（smoothstep） | 31.4px/s | **47px/s** | **1.7** |

两者都用线性 ⇒ 加速度为零 ⇒ 上浮读成"倒放的下潜"。上浮比下潜**短 0.8s** 也是故意的：
回程比去程快才读作"有余力"。

### 5.2 上浮的"动力"从哪来（三条同时给）

| 线索 | 规格 | 为什么这样取 |
|---|---|---|
| ① **两侧排气** | 艇侧下方 (dx 76–104, dy +72)，每 0.07s / 0.09s 一个 | 排气口必须**出壳**（√(dx²+dy²) > 90）：气泡层在舱体之下，壳内的气泡一出生就被挡住。也不能取正下方 (0, 96) —— 艇沉到底时排水口 556+96 = 652 = 柱底，一半气泡生在框外 |
| ② **气泡绝对速度** | **95–150 px/s**（艉部尾迹只有 26–52） | ⚠️ **这条是主开关**。旧值 38–75 相对艇（峰值 47）只快 0–28px/s ⇒ 气泡**粘在艇上**，读作"一团气泡陪着它漂"。提到 95–150 后相对速度 48–103px/s ⇒ 气泡冲过艇身继续往上，气流有方向 |
| ③ **推进器 / 核心** | `boost` 0→1 调制喷流长度 ×1.85、亮度、核心呼吸 +3px | "看起来很用力"和"数值上在用力"是同一个量 |

**因果链**：先排水（看得见的排气）→ 机器变轻（推进器全开）→ 才开始动（看得见的上浮）。
顺序不能反 —— 反过来就是"莫名其妙浮起来了"。

### 5.3 y 的边界（柱是取景框）

V6.43 把柱高从 328 加到 **368**（柱底 612 → **652**）。原因是删掉淡出之后，
暴露出 V6.42 一直存在的越界：

| | V6.42 | V6.43 |
|---|---|---|
| 柱底 | 612 | **652** |
| `DIVE_Y1` | 600 | **556** |
| 艇下缘在最深处 | 690（**超柱底 78px**） | 646（柱底内，余 6px） |
| 症状 | 艇有一半停在柱子外面 —— 当时被淡出藏住了 | 全程整个在柱内 |

- 起点 380 = 柱顶 284 + 外壳半径 90 + 6px 余量。再往上抬，入水时会压到标题装饰线 272。
- 柱底 652 与底栏（706）留 54px，且水平不相交（底栏文字 y 699–713）。

**附加周期全部与 14.4s 不成整数比**（整数比会让动画周期性"重新同步"，读起来像脉动）：

| 动作 | 周期 | 与 14.4s 的关系 |
|---|---|---|
| 俯仰摆动 | 5.5s（±3°） | 2.62 ✗ 整数 |
| 装甲环 A（顺）/ B（逆） | 44s / 26s | — |
| 核心呼吸 | 2.4s | 6.0 ✗ |
| 扫描臂 | 6s | 2.4 ✗ |
| 声呐环 | 2.6s | 5.54 ✗ |
| 姿态推进器 | 1.5s，**6 个各错开 0.25s** | 9.6 ✗ |

**推进器必须错开**：同时喷 = 一坨光，依次点火才有环形点火感。

### 5.4 气泡的两种来源（别合并）

| 模式 | 段 | 出生点 | 回答的问题 |
|---|---|---|---|
| `cruise` / `stern` | 待机 / 下潜 | 艇心**上方** 70px（在壳内酝酿 ~0.5s 才浮出） | "这台机器在动" |
| `vent` | 吹除 / 上浮 | 艇**侧下方** 出壳（见 5.2 ①） | **"它为什么浮得起来"** |

- 尾迹气泡生在壳内是故意的：生在壳外会读作"水里本来就有气泡"，与机体无关
  —— 那正是 V6.41 被判"没有意义"的病根之一。
- 排气气泡反过来（出壳再出生）：排水的气泡被艇体盖住就白排了。
- **气泡不出取景框**：回收线在柱顶内侧 +2，并在离柱顶 30px 内线性淡出
  （V6.42 的 −6 会让气泡露在框外，看起来像"画面漏了"）。
- 横向上限 = `VENT_DX1` 104 + 横漂 33 + 半径 3 = 140 < 柱半宽 148。
  横漂用**指数衰减**（`VENT_DECAY` = 1.2）⇒ 总位移 ≈ 40/1.2 ≈ 33px，两股气流张开一下
  就转回笔直上升，不会飘出柱子。

## 6. 实现要点

### 6.1 节点结构（"一个节点 = 一个 Graphics"）

```
tDiver                        ← 下潜 = 平移它；俯仰 = 转它的 angle
├── dHull    投影 + 侧壁 + 主盘 + 稳定鳍 + 推进器凹槽
├── dArt     潜航器立绘（Sprite，与「出击准备」/ 战斗内共用同一张贴图）
├── dRingA   外装甲环带（靠 node.angle 顺时针转）
├── dRingB   内装甲环带（逆时针转）
├── dCore    核心穹顶（靠 node.setScale 呼吸）
├── dThrust  姿态推进器喷流（每帧重绘）
├── dSonar   声呐环（每帧重绘）
├── dLight   球面明暗 + 受光弧 + 暗弧 + 外缘（**永不旋转**）
└── dScan    扫描臂（靠 node.angle 转）
```

⚠️ **刻意不往下套子节点**：`UIOpacity` 不传播，套一层就漏一层的淡入淡出。
需要旋转 / 缩放的零件就在**同一个节点**上做 —— `Graphics` 与变换天然一起动。

### 6.2 局部坐标（与顶层相反）

- 顶层 `wrap()` 是 **sim 语义**（y 向下、角度顺时针）。
- 舱体内部 `sub()` 是**节点局部**（**y 向上**、角度是**标准数学角**）。

⚠️ 所以舱体内部**不能用 `Gfx.arc()` / `Gfx.fillCircle()`** —— 它们内部走
`Gfx.y(v) = H - v`，任何 `H` 都变不出恒等映射，会**多翻一次 y**。
对称图形看不出来，但"受光弧在左上"会翻到右下。
→ 舱体内部统一：颜色用 `fill()/line()`（不碰坐标），路径用 `.g` + 自带的 `larc()`。

### 6.3 每帧开销

| 动作 | 实现 | 代价 |
|---|---|---|
| 下潜 / 摆动 / 装甲环 / 核心 / 扫描臂 | 只写节点属性 | **零重绘** |
| 喷流 / 声呐 / 气泡 | 每帧重绘 | 6 段线 / 2 圈弧 / ≤22 个圆 |

主界面会停留很久，所以**不能**出现"每帧重画一屏几何"的写法。

### 6.4 守住的铁规

- 全线**禁用 ADD 混合**：发光靠多层描边 + 低透明填充。
- 颜色只用 `UI.cyan* / GLASS.*`（青蓝 = UI 与玩家专属；生物发光色留给敌人）。
- `SEAT_ANGLES_DEG` 从 `shared/dive/tables` **引**，不在视图层抄第二份。
- 尾迹气泡从**舱体艉部出生**（局部 y = +70，在圆盘内"酝酿"约 0.5s 才浮出）——
  这是与 V6.41「随机撒」的本质区别。⚠️ 也因此 `tBubble` 必须排在舱体**之下**。
