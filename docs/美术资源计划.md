## 一、现状诊断

### 1.1 核心问题：不是"画风"，是结构

看了 `pixel-preview-enemy.png`（14 个单位）后，必须先说清一件事：

> **当前是"程序化生成的人形像素单位"系统——一个人形模板 + 颜色区分。不是画风问题。**

| 观察 | 证据 | 性质 |
|---|---|---|
| **14 个敌人共用同一套人形骨架** | minion/runner/tank/swarm/shooter/shield/elite + 5 个 Boss，全部是"头 + 躯干 + 两腿" | 🔴 致命 |
| **剪影完全无法区分** | 转成黑白剪影后，14 个单位**看起来一模一样** | 🔴 致命 |
| **Boss 与小怪同构** | Boss 只是"放大 + 换色 + 加披风" | 🟠 严重 |
| **颜色承担全部区分职责** | 14 个敌人有 14 种色相，但色相是最弱的区分通道 | 🔴 严重 |
| **4 个角色同样问题** | rookie/guanyu/zhangfei/zhaoyun = 同一模板换配色 | 🟠 严重 |

**在弹幕里的实际后果**：同屏 50+ 单位时，玩家无法判断"哪个是哪个、哪个在打我、哪个要先杀"。**这是可玩性问题，不是审美问题。**

### 1.2 技术规格（必须对齐）

`pixelgen.py` 当前规格：

| 项 | 值 |
|---|---|
| 逻辑网格 | `GRID = 32`（所有单位在同一网格绘制） |
| 图集布局 | `COLS=4` × `ROWS=9`（3 方向 × 3 动作） |
| 动作帧数 | `idle:2` / `walk:4` / `attack:3` |
| 方向 | `down` / `up` / `side` |
| 描边 | `outlined()` 做 1px 深色描边（alpha 膨胀 - 原 alpha） |
| Boss 放大 | `upscale` 整数倍放大网格，**保持像素块大小一致** |
| 枪口坐标 | 生成时算好写入 `manifest.json`，游戏直接读 |
| 碰撞盒 | 量"朝下·待机"格alpha bbox → 换算逻辑像素写入 manifest |
| 输出 | `web/src/assets/pixel/<unit>.png` + `manifest.json` |

> **现有体型表** `BUILD`（7 种，脚底统一对齐 y=30）：
> `tiny` / `wisp` / `slim` / `normal` / `tall` / `wide` / `brute`

### 1.3 好消息

程序化管线意味着：**新增兵种 ≈ 30-60 分钟配置，而非手绘一张图。**
市价：同等质量 13 个单位 + 20 个场景元素，外包手绘约 **3-8 万元**。程序化管线成本优势是**两个数量级**——这是必须守住的资产。

### 1.4 坏消息（必须诚实）

**`draw_*` 函数族全部是人形专用**：

```
draw_legs_down()  draw_legs_side()   ← 人形专属
draw_torso()      draw_head()        ← 人形骨架
draw_cape()       draw_beard()       ← 人类特征
draw_weapon()     draw_marks()
```

深海生物需要**半透明伞盖、蛇形盘绕、巨大阴影、密集鱼群**——**这些超出现有管线的表达力**。这是本规划的主要工作量。

## 二、视觉体系

### 2.1 核心策略：黑暗中的一束光

> **整个画面遵循一条物理规则：所有可见光都来自玩家。**

| 距离 | 亮度 | 内容 |
|---|---|---|
| 玩家周围（光照半径） | 全亮 | 清晰可见 |
| 中距离 | 半亮 | 被黑暗吞没细节 |
| 远距离 | 全暗 | 只能看见**生物发光的轮廓** |

**这一条规则同时实现四件事**：

| # | 收益 |
|---|---|
| ① | 自然解决"弹幕中看不清自己"——玩家永远最亮 |
| ② | 自然实现"光量 = 生命"可视化——光少= 视野收缩 = 危险感 |
| ③ | 天然让**生物发光敌人**成为唯一可见威胁 → 视觉层级自动成立 |
| ④ | **极低成本**——不需要画任何场景资源 |

> **这是本作最大的美术资产**，也是深海题材最大的意外红利。

### 2.2 色彩层级规则

> **硬规则：任何时候，玩家必须是画面上最亮的暖色物体。**

| 层 | 明度 | 饱和 | 色相 | 色值 |
|---|---|---|---|---|
| **玩家** | 最亮 100% | 中高 | **暖金**（全场唯一暖色源） | `#ffd27f` |
| **玩家描边** | 最亮 | — | 暖白 | `#fff4d6` |
| **玩家辉光** | — | — | 暖橙 | `#ffb347` |
| **敌人·发光** | 高 85% | 高 | **冷色**（青蓝/青绿/品红） | `#4fe8ff` `#7fffd4` `#ff4fd8` |
| **敌人·实体** | 中低 40% | 低 | 冷灰蓝 | `#2a3a4a` |
| **弹幕** | 高 90% | 高 | 冷色，**比敌人亮一档** | — |
| **危险预警** | 中 | 高 | **纯红**（全场唯一纯红） | `#ff3b3b` |
| **背景** | 最暗 10% | 极低 | 深蓝黑 | `#060a12` |
| **场景元素** | 暗中 20% | 极低 | 深蓝灰 | `#16283c` |
| **危险区** | 中暗 | 低 | 暗红调 | `#1a2f3f` |

### 2.3 主题常量（`theme.ts`）

```ts
export const THEME = {
  // 背景层（由暗到亮）
  bgDeep:   '#060a12',
  bgMid:    '#0a1220',
  bgLight:  '#16283c',
  hazard:   '#1a2f3f',

  // 玩家（全场唯一暖色）
  player:      '#ffd27f',
  playerOut:   '#fff4d6',
  playerGlow:  '#ffb347',

  // 敌人（冷色 + 发光，按护甲）
  armorGelatin: '#4fe8ff',   // 胶质- 青
  armorScale:   '#7fffd4',   // 鳞甲 - 青绿
  armorCalcium: '#ffd700',   // 钙壳 - 金
  armorBone:    '#ff4fd8',   // 骨质 - 品红

  // 危险（唯一纯红）
  danger: '#ff3b3b',

  // UI
  textPrimary:   '#e8f4ff',
  textSecondary: '#9fb3c8',
  panelBg:       '#0a1220',
  panelBorder:   '#1e3a52',
}
```

> ⚠️ **钙壳用了金色**，与玩家暖金接近——**这是有意的风险点**。必须靠**剪影**（管状塔形）区分，不能靠颜色。敌情预告的护甲分布图会提前告知"这波有钙壳，去看塔形单位"。

### 2.4 深色背景的特效红利

| 传统浅色背景的问题 | 深色背景的解法 |
|---|---|
| 泛光（bloom）看不见 | 发光体本身成为画面最亮元素，对比度最大化 |
| 弹幕看不清 | 弹幕= 冷色发光物，黑底上一目了然 |
| 特效细节被背景淹没 | **相当于免费获得"聚光灯"** |

> **建议**：做成可选的「**高对比模式**」——纯黑背景 + 只保留剪影和发光。这既是**可访问性功能**，也是主播做视频的绝佳素材。

## 三、剪影规则

### 3.1 硬规则

> **每个单位在纯黑剪影下必须可区分，辨认时间 < 1/8 秒。**

这需要新增 **5 个非人形轮廓族**（现有 `BUILD` 7 种全是人形变体）。

### 3.2 剪影族表

| 族 | 体型变体 | 轮廓特征 | 适用 |
|---|---|---|---|
| `humanoid` | tiny/slim/normal/tall/wide/brute | 人形 | 玩家 + 通用人形 |
| `bell` | small/large | **伞状/钟形，底部垂触手** | 水母类 |
| `tower` | short/tall/cluster | **竖立塔簇，高瘦** | 管虫 / 钙壳 |
| `serpent` | coil/crest | **蛇形盘绕，螺旋** | 触手 / 鳗鱼 |
| `shell` | dome/spike/crab | **圆壳 + 尖刺 / 双螯** | 甲壳类 |
| `school` | dense/sparse | **密集三角群，无单体** | 鱼群 |
| `leviathan` | boss/whale | **巨大阴影占屏 1/4** | Boss |

### 3.3 兵种剪影映射

| 兵种 | 剪影族 | 轮廓钩子 | 说明 |
|---|---|---|---|
| **胶质漂群** | `bell` | 半透明伞盖 | 钟形，一眼软 |
| **鳞甲鱼群** | `school` | 密集小鱼剪影 | 一团三角，无单体 |
| **钙壳管虫** | `tower` | 塔状垂直线 | 高瘦垂直 |
| **骨质触手** | `serpent` | 蛇形曲线缠绕 | 曲线缠绕 |
| **光诱鮟鱇** ⭐ | `shell` + 悬灯 | **头顶悬空发光球 + 巨口** | 自发光结构 |
| **电水母群** ⭐ | `bell` + 电丝 | **伞盖 + 放射线条** | 自发光结构 |
| **骨甲近卫** ⭐ | `shell` spike | **高大 V 形双螯** | 自发光结构 |
| **巨兽幼体** ⭐ | `leviathan` | **体量压制** | 自发光结构 |

> ⭐ **关键设计**：标记的 4 个是**发光结构剪影**——即使在纯黑剪影下，它们也是唯一能"看"到的（因为有辉光）。这解决了深海题材下"远处敌人不可见"的问题。

```
┌─ 第 7 波 敌情 ──────────── 距下一波 0:12 ─┐

│ [阵型] 雁行  ⚠ 第4波起改为两翼包抄        │
│        ╱╲  ← 实时阵型示意图          │
│ [兵种] 前排60% 中军25% 后排15%            │
│        ████████░░░░           │
│ [护甲] 胶质70% 鳞甲30%                    │
│ [破法] ✦电击  ✦切割← 由 vs 反查          │
│        [诱饵] 对密集阵型有效│
└─────────────────────────────────────────┘
```

**设计要点**：

| 要素 | 规范 |
|---|---|
| **配色** | 底`#0a1220`，边框用**护甲对应色**（胶质→青、钙壳→金） |
| **位置** | 商店界面**顶部常驻、不可折叠**（核心机制必须always visible） |
| **阵型示意图** | 用 `FORMATIONS.slots` 的 `role` 实时绘制，玩家在底部（**零美术成本**） |
| **破法推荐** | **必须具体到武器名**，不能只说"用电击" |
| **警告色** | 若下波阵型变化（雁行→月牙），用 `DANGER` 纯红高亮 |

### 5.3 字体规范

> 现有规范提到用户对字号敏感（下限 12px）。深色背景需要调整描边策略。

| 元素 | 字号 | 颜色 | 备注 |
|---|---|---|---|
| 主标题 | 46-58px | 冷白 + 辉光 | — |
| 敌情卡标题 | 19-22px | 琥珀 `#ffd27f` | 核心信息，最大字号 |
| 卡片标题 | 15-17px | 冷白 `#e8f4ff` | — |
| 正文 | 12-14px | 冷灰 `#9fb3c8` | 对比度 ≥ 4.5:1 |
| 数值 | 13-15px | **按属性色**（伤害白/护甲蓝/速度绿） | — |

> ⚠️ **深色背景关键**：不能再用纯黑描边（会"吃掉"单位）。改用**冷白描边 + 低透明度外发光**，保证任何背景上都可读。

## 六、特效规划

### 6.1 问题诊断

现有反馈指出"技能特效很单一"。根因是**没有形状语言**——所有特效都是"发光的圆形"，玩家无法通过视觉区分技能。

### 6.2 形状语言规则

> **规则：每个技能有唯一形状，玩家不看图标也知道发生了什么。**

| 技能 | 形状 | 颜色 | 语义关联 |
|---|---|---|---|
| **光源脉冲 Q** | **同心圆环**（向外扩散） | 暖金 `#ffd27f` | 光 = 圆 = 扩散 |
| **诱饵 E** | **三角光标**（吸引视线） | 青绿 `#7fffd4` | 诱饵 = 指向 |
| **电击系武器** | **锯齿折线**（不稳定） | 青蓝 `#4fe8ff` | 电 = 折线 |
| **切割系武器** | **直线光条**（干净） | 白亮 `#e8f4ff` | 切割 = 直线 |
| **酸蚀系武器** | **不规则气泡**（腐蚀） | 黄绿 `#b8ff3b` | 酸 = 溃散 |
| **钙壳破除** | **碎裂裂纹** | 纯白闪光 | 破 = 裂 |
| **受击** | **短促收缩圆**（收缩） | 纯红 `#ff3b3b` | **与 Q 刻意区分** |

> **最重要的区分**：光源脉冲（扩散圆）vs 受击（收缩圆）—— **形状相同、方向相反**。玩家能瞬间分辨"是我的技能"还是"我被打中了"。

## 七、产能与分工

### 7.1 方案选择

| 方案 | 成本 | 效果 | 建议 |
|---|---|---|---|
| **A · 纯程序化** | 12-15 天 | 能出，但 Boss 可能"塑料感" | ⚠️ 可作 MVP |
| **B · 程序化 + 关键件手绘** | +3-5 天 | Boss 与发光种质量显著提升 | ✅ **推荐** |
| **C · 全手绘** | 8-15 万元 | 最好，但违背成本优势 | ❌ |

### 7.2 推荐分工

| 生产方式 | 资产 | 理由 |
|---|---|---|
| **程序化** | 8 普通兵种、15 场景元素、52 卡面图标 | 数量大、需要变体 |
| **手绘** | 4 个 Boss、1-2 个玩家角色、核心特效帧 | **会被截图传播的**，值得投入 |

> 手绘 Boss 的理由：它们是**缩略图与直播画面里的主角**。程序化能做出"形状正确"，但手绘能做出"想让人截图"。

### 7.3 产能估算

**假设**：管线扩展完成后，单个新单位配置成本 **30-60 分钟**（调体型参数 + 部件组合 + 导出验证）。

| 阶段 | 内容 | 工时 | 交付标准 |
|---|---|---|---|
| **A · 管线扩展** | 新增 6 个剪影族 | **2-3 天** | `pixelgen.py` 能输出全族 |
| **B · 剪影自检工具** | `--silhouette` 纯黑掩码输出 | **0.5 天** | 可自动验证 |
| **C · 玩家改造** | 4 角色改深海配色 + 潜水装备 | **0.5 天** | 剪影自检通过 |
| **D · 普通兵种** | 8 兵种配置 + 自检 | **1-2 天** | 8 剪影互不相似 |
| **E · Boss** | 5 Boss（程序化 + 手绘混合） | **2-3 天** | 体量差异明显 |
| **F · 场景元素** | 15 个元素 | **1-2 天** | 可复用排列 |
| **G · 色彩体系** | `theme.ts` 深色 + 光照半径 + 辉光 | **2-3 天** | 视觉层级落地 |

## 八、验收标准

> **原则：美术规范必须可验证，不能靠"感觉对了"。**

| # | 标准 | 检查方法 | 通过线 |
|---|---|---|---|
| **A1** | **剪影可辨** | `--silhouette` 输出纯黑掩码，人工 1/8 秒识别 | 8 兵种互不相似，**通过率 100%** |
| **A2** | **亮度层级** | 脚本采样：玩家 > 弹幕 > 敌人 > 背景 | 玩家明度 ≥ 背景 + 40% |
| **A3** | **色相唯一性** | 检查玩家色相不出现在敌人调色板 | 玩家暖色 vs 敌人冷色，**色相差 ≥ 60°** |
| **A4** | **描边可见** | 在 4 种背景色下渲染检查 | **4/4 通过** |
| **A5** | **辉光不过曝** | 同屏 200 单位时检查是否糊成白块 | 弹幕仍可分辨 |
| **A6** | **特效形状可辨** | 静音播放，闭眼只看形状 | 7 种特效互不混淆 |
| **A7** | **UI 对比度** | WCAG 检查 | 正文 ≥ 4.5:1 |
| **A8** | **深色一致性** | 检查所有 UI 组件在 `bgDeep` 下表现 | 无低对比残留 |
| **A9** | **像素块一致** | Boss 放大后像素块大小与普通单位相同 | 整数倍放大，无插值 |

> **建议**：A1/A2/A3 做成 `--verify-art` 命令，纳入 `tools/` 现有验证链路。
> 这与已有的 `check_facing_applied.mjs` 是同一思路——**自动化守卫而非人工检查**。

### 8.1 最先做：剪影自检（0.5 天）

> **这是整个美术计划的第一步，也是风险最高的一步。**

**第一步输出**：把现有 14 个玩具兵单位渲染成纯黑剪影图。

**预期结果**：14 个单位看起来**几乎完全相同** —— 这会把"问题有多严重"从主观判断变成客观事实。

**第二步**：新增 `bell` 族，做一个水母单位，验证**非人形剪影在管线下是否可行**。

**决策点**：
- 若剪影可辨 → 深海美术方案成立，继续扩展
- 若不可辨 → 退路为"**深海 + 强描边 + 体型极端化**"，用极端体型差异（极宽/极瘦/极小）替代剪影族

> **半天能出结果，且能避免 3 周后才发现方案不可行。**
