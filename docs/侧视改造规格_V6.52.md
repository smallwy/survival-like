## §2 实体侧视化

### §2.1 敌人：从「旋转朝玩家」改成「镜像 + 限幅倾角」

**现状**（`DiveGame.ts:1944,1955`）：
```ts
const face = Math.atan2(w.py - e.y, w.px - e.x)        // 朝玩家
sp.node.angle = -((face - e.texRot) * 180) / Math.PI   // 全 360° 旋转
```
这是**俯视写法**：鱼是"从天上看的"，所以可以原地转圈朝你。

**侧视下必须改成**：
```ts
// ① 用自身运动方向，不用「朝玩家」—— 侧视的鱼自己游
const vx = e.vx ?? (e.x - e.lx)
const vy = e.vy ?? (e.y - e.ly)
// ② 水平分量定镜像，垂直分量只给倾角
const mirror = vx < 0 ? -1 : 1
const pitch  = clamp(Math.atan2(vy, Math.max(18, Math.abs(vx))), -0.61, 0.61)  // ±35°
node.setScale(mirror * baseScale, baseScale)
node.angle = -(pitch * 180) / Math.PI
```

三条硬理由：
1. **侧视的鱼不该翻滚。** 一条从正上方游下来的鱼若被转 90°，屏幕上就是"一条竖着的鱼"，读不出是什么。
2. **±35° 是"俯冲/上浮"的表达上限。** 再大就退化成"转头"，与"镜像转身"语义打架。
3. **镜像比旋转更像鱼。** 鱼左右游靠摆尾，不靠翻身。

⚠️ `texRot` 字段**作废**（它存在的唯一理由是配合全旋转）。删前全目录搜引用。
⚠️ 矢量兜底 `fillTri(e.x, e.y, face, r*1.25, r*0.85)` **必须同步改** —— 否则贴图是侧视鱼、但超过 120 敌退回矢量时变成"朝玩家的三角"，同屏一多画风突变。
改成：**侧视鱼形**（梭形身体 + 尾鳍三角），同样用镜像。

### §2.2 潜航器：从「60° 俯角球核」改成「侧视剖面」

> **2026-10-14 已实施（V6.54）。** 实施中推翻了本节的两条判断，逐条标在下面 ——
> 详细规格见 `docs/潜航器侧视剖面_V6.54.md`。

**现状** `drawBody()` = 60° 俯角的球形深潜核（`SUB_D = 88` 为直径）。

**改为侧视剖面潜航器**：
- ⛔ ~~复用 `Title.ts` 中央区的 `drawHull` 几何~~ —— **错判，作废**。
  去读 `Title.ts:1403 drawHull()` 会发现它是**俯视圆盘**（`HULL_R=90` 主盘 + 装甲环带 + 六口绕一圈），
  跟侧视剖面**不是同一套几何**。可复用的只有**手法**（"投影 / 侧壁 / 受光弧 / 暗弧"四条体积线索），
  几何必须**新写** ⇒ `HULL_OUTLINE`（14 点梭形）。
  **教训**：写规格时引用别的文件的具体函数，必须先去读那个函数，不能靠记忆里的"它应该长这样"。
- 尺寸 ✅ 已实施：`SUB_D = 88` 语义从「直径」改成「**艇长**」；艇高 `HULL_H = 56`（88:56 ≈ 1.57:1）
- 朝向 ⚠️ **已降级**：~~镜像 + ±35° 限幅~~ → **只做镜像（带 ±0.25 死区），不做倾斜**。
  理由：座圈投影在**模拟层**（`world.ts seatPos`）。机体若倾斜而座圈不倾，炮会脱离艇身；
  要一起倾就得再动一次模拟层投影。收益低、风险高 ⇒ 留 v2。镜像已足够表达「艏尾」（船不会翻身，只会掉头）。
- 明暗 ✅ 部分已实施："舷窗剖面 + 背脊带"做了；"挂载带随深度压暗"**未做**
  —— 深度压暗是 `gVeil` 全局层的事，机体不该自己再压一次

⚠️ ~~**炮塔座位是最大风险点**~~ → **已解，且不是靠"重排座位"**。
真正的杠杆是**座圈投影**：`SEAT_RATIO` 从"俯视压扁率 0.5"改成**"侧视高度投影 28/48"**。
于是 ±90° 两座（`cos = 0`）正好压在机体的**高边缘**上、±30°/±150° 四座沿艇长铺开，
六座炮心**全部落在艇舷上** —— 而 `SEAT_ANGLES_DEG` **一个数都没动**
（那是 web/cocos 共享数据，动它等于同时改两个引擎）。
⚠️ 代价：`seatPos()` 变了 ⇒ 子弹出生点与索敌原点跟着变。这是**投影变化**不是**战斗数学变化**
（射程 / 伤害 / 优先级 / 频率一律不变），但会移动弹道起点 —— 需实机确认手感。

## §3 水域层：从「静止背景」改成「竖向滚动水体」

### §3.1 滚动量 `scrollY`（纯表现，模拟层零改动）

```
scrollY += vScroll * dt
vScroll = SCROLL_BASE + burst
SCROLL_BASE = 46                  // px/s。现状 6~20 慢一个数量级
burst = 换带时置 220（4.8×），指数衰减 e^(-t/0.9)
```
⛔ **`scrollY` 只驱动表现层**（背景图偏移 / 颗粒 / 远景鱼群 / 光柱），**绝不回写 sim**。

**背景怎么滚而不露边 —— 本节的真正难点**：
| 层 | 滚？ | 怎么解决边缘 |
|---|---|---|
| **水色**（远景） | **不滚** | 它本来就没有特征，只有色相。由 `depthM` 插值决定 |
| **地形/岩壁/石柱**（中景） | **滚 0.5×** | 图像上下边缘做 **64px alpha 渐隐**；水色在它后面兜底 |
| **颗粒**（近景） | **滚 1.0×** | 程序生成，无限流，无边缘问题 |

⚠️ alpha 渐隐是**遮丑不是解决** —— v2 环境图必须画更长的垂直内容（1536×1180，见 §4.3）。
⚠️ **水色不滚**是个反直觉但正确的决定：滚动纯色没有任何视觉信息，只会让"深度感"变模糊。深度感来自**有特征的东西在动**（颗粒、地形、鱼）。

### §3.2 颗粒三层视差

| 层 | 视差系数 | 数量 | 尺寸 | alpha |
|---|---|---|---|---|
| 远景 | 0（不滚） | — | — | — |
| 中景 | 0.35× | 24 | r 2.2–4.0（暗大） | 0.16 |
| 近景 | 1.00× | 36 | r 1.2–2.4（亮小） | **0.30** |

- 数量随深度走 `LAYERS.motes`（**34 / 48 / 70 / 90 / 110**）
- ⛔ **深度不影响速度** —— 别做"越深越慢"，那削弱下潜感。深度只影响**密度 / 尺寸 / 亮度**
- ⚠️ **颗粒必须向上走**（玩家下潜 = 悬浮物向上掠过）。现状方向是对的，只是慢了一个数量级
- ⚠️ **L4 热泉带反向**：热流粒子向下 + 主颗粒向上被衰减（×-0.62）⇒ 相对速度被顶掉、颗粒近乎停住。
  **这是 `ventPush 190` 的视觉证据 —— 机制与视觉第一次说同一句话。**

### §3.3 换带：三段式（回应「不要坐电梯」）

**现状**：换层是**阶跃** —— `layerIdx` 一变，背景图 / 色 / `vis` 全部跳变。用户描述为"坐电梯"。
**注意**：用户说的不是"过渡时间不够长"，是**速度曲线是台阶**。

| 段 | 时长 | 内容 |
|---|---|---|
| ① **起势** | 0.8s | `vScroll` 从稳态 46 升到 220 |
| ② **温跃层扫带** | 0.6s | 一条 3 图元的横向波纹带从下往上扫过，扫过处色相瞬切 |
| ③ **crossfade** | 2.0s | 双 `bgNode` smoothstep（**必须在 `descDur 2.1s` 内跑完**，否则相位结束留半透中间态） |
| ④ **落定** | 0.9s | `vScroll` 指数衰减回 46 |

⚠️ **换带不能只靠 crossfade。** crossfade 是"图慢慢化开"，没有"你在动"的信息。
**必须有速度曲线 + 扫带** —— 那才是"下潜"，而不是"融化"。
⚠️ 不能中途交换 spriteFrame（短时间连换两层会闪）。

### §3.4 换水域的「特效提示」

- **带名标签**（屏幕中央偏上）：`阳光带 · 0–200m`，2.4s，字号 **32 / 20**，`fade in 0.35 / hold 1.4 / fade out 0.6`
- **水压环**：从屏幕中心外扩的 **3 圈同心环**，0.9s，`UI.cyanHi @0.42→0`
- ⛔ **不做全屏闪白** —— 深海里一次全屏白会瞬间毁掉"暗"的基调

L1 阳光 ｜ L2 残光 + 远处光斑 ｜ **L3 生物荧光点链** ｜ **L4 热泉烟柱 + 橙红辐射** ｜ L5 稀疏点阵（不是纯黑）

### §4.3 硬指标

- 尺寸 **1536×1180**（1180 给滚动留 431px 余量；现图 984 只够 235px）

- 上下边缘**无硬接缝**（配合 §3.1 的 alpha 渐隐）
- 无文字 / 无 UI / 无战斗实体
- ⚠️ **L1.png 现 2.46 MB**（其余 0.25–0.67 MB），它是首屏第一张，**必须压到 ≤0.8 MB**

### §4.4 敌人贴图（新发现，最容易漏）

⚠️ **现有敌人贴图是俯视素材。** 侧视下必须换成**侧视鱼剪影**：

## §5 HUD

### §5.1 深度计（左侧竖条）

- **360 × 10 px** 竖条，五带刻度
- ⚠️ **深度区间是非线性的**（0–200 / 200–1000 / 1000–4000 / 4000–6000 / 6000–11000），
  竖条**必须按视觉等分、标注真实值** —— 否则 L1 只占条长的 **1.8%**
- 游标：三角 + **18px 渐隐拖尾**
- 浅 / 深两段用不同色阶的刻度线；当前带高亮
- ⛔ **不做数字滚动动画**（会被读成卡顿）

### §5.2 鱼情雷达（右上角圆圈）

- 直径 **168 px**，中心 = 玩家，半径 = **600 世界距离**（≈ 屏幕对角线一半）
- 点：敌人 **珊瑚色 3px** ｜ 鱼骨 **青色 2px** ｜ Boss **放大的环**
- 圈外**不显示**（v1 不塞边缘箭头，保持干净）
- 外圈两层：`UI.cyanDim @0.28`（= 屏幕可视范围）+ `@0.14`（外圈）
- **跟随玩家朝向**（上方 = 玩家艏向）；否则侧视里方向对不上
- ⚠️ 雷达是**俯视地图**、主画面是**侧视** —— 这是有意为之：**雷达负责"全向态势"，画面负责"深度与纵深"**，两者语义不冲突
