# 鱼群 · 朝向 · 雷达修正（V6.55）

> 触发：用户 2026-10-14 实机截图反馈 ——「bug 挺多的 鱼游的方向 背景的白色 要你做的背景 鱼情都是问题」。
> 本文记录**四个已定位的缺陷**、各自的根因、修法，以及本次重定的观感参数。

---

## 0. 一句话结论

四条反馈对应**四个独立缺陷**，都不是"参数调不好"，而是**代码里写错了东西**：

| 用户原话 | 真实根因 | 性质 |
|---|---|---|
| 「背景的白色」 | `gAtmo` **漏在每帧 clear 名单之外** ⇒ 46 条远景鱼每帧叠加成拖影带 | 漏一行 |
| 「鱼游的方向」 | 渲染层读 `e.vx/e.vy` 算朝向，而**这两个字段在模拟层从不更新**（恒 0）⇒ 全场鱼水平朝左 | 读错字段 |
| （同上的第二半） | `frameAspect` 取 `sf.rect`（**裁剪后**）而渲染按 `originalSize`（整张画布）⇒ 透明边多的贴图被拉成方块 | 口径不一致 |
| 「鱼情」 | 右上那个圆是**波次倒计时**（"27" = 剩余秒数），**鱼情雷达从来没做** | 功能缺失 |

⚠️ 四条里有三条是**"静默失效"**：不报错、不崩溃、图上也有东西 —— 只是东西不对。
这正是本项目 MEMORY 第 7 条铁规说的那类坑，本轮一次撞上三个。

## 1. 白带：`gAtmo` 漏在每帧 clear 之外

**位置** `DiveGame.ts` `update()` 的每帧清屏行。

**根因** V6.53 新增了 `gAtmo` 层（远景鱼群），并在**标题界面分支**与 `hideWorld()` 里补了 clear —— 唯独**漏了战斗中的每帧清屏那行**。

Graphics 是**累积顶点**，不 clear 就一直画。于是：

```
46 条鱼 × 每帧都画一遍 × 横向移动 12–32 px/s
  = 屏幕上几十条横向拖影，几秒后连成一片白带
```

**这解释了截图里"背景的白色"的全部形态**：
- 为什么是**横条**：鱼的 `vx` 是水平的，拖影自然是横向的；
- 为什么边缘**呈波浪/锯齿**：鱼身是椭圆、尾鳍是三角，叠加后边界就是那个形状；
- 为什么**越看越多**：时间越久累积越厚。

**修法** 把那行补成完整的九层名单，并在注释里写死"**新增任何 Graphics 层，第一件事是加进这张名单**"。

## 2. 朝向：读了一个从不更新的字段

**位置** `DiveGame.ts` `drawEnemies()`。

旧代码：

```ts
const spd = Math.hypot(e.vx, e.vy)     // ← e.vx / e.vy 恒为 0
if (spd > 0.5) { /* 算 flip 与 tilt */ }   // ← 永远不进入
```

而 `shared/dive/world.ts` 里敌人位移是**直接改坐标**：

```ts
e.x += nx * e.speed * slow * dt        // 从来没有 e.vx = …
e.y += ny * e.speed * slow * dt
```

`vx / vy` 只在 `mkEnemy()` 里被初始化成 0，**之后没有任何地方写过**。

⇒ `spd` 恒为 0 ⇒ `flip` 恒为 1、`tilt` 恒为 0 ⇒ **屏幕上每一条鱼都是水平朝左的**。
用户看到的"鱼游的方向不对"就是这个。

### 修法：给模拟层补一个**朝向**

新增 `Enemy.fx / fy`（朝向单位向量），由 `updateEnemies()` 每帧写入：

```ts
e.fx = nx; e.fy = ny                    // 朝目标方向（缺省）
// dash 冲刺阶段另外覆盖成冲刺方向：
e.fx = e.dirX; e.fy = e.dirY
```

**为什么存"朝向"而不是"速度"**：冲刺/蓄力时位移会归零或突变，朝向**不该跟着闪**。
状态机在 `charge` 阶段原地不动，但鱼仍然盯着玩家 —— 那才是正确的观感。

### 顺带修掉一个符号错误：镜像必须乘 `flip`

节点变换是 **T·R·S**（先缩放、后旋转），`scale.x = -1` 会把**旋转的视觉方向一并翻转**。
同一个 `angle` 值，镜像前后的"抬头 / 低头"正好相反。

```ts
sp.node.setScale(flip, 1, 1)
sp.node.angle = (-flip * tilt * 180) / Math.PI   // ← 必须带 flip
```

基准来自本项目既有约定（`DiveGame.ts` 文件头 + `Gfx.ang`）：
**sim 的角度是"y 向下、顺时针为正"，而 `node.angle` 正值 = 视觉逆时针。**

## 3. 方块鱼：两处比例口径不一致

**位置** `art.ts` `frameAspect()`。

```ts
// 旧（错）：rect 是**裁剪后**的矩形
const w = sf.rect.width, h = sf.rect.height
```

但渲染时设的是 `trim = false` + `sizeMode = CUSTOM` + `setContentSize(…)`
—— 顶点按 **`originalSize`（整张画布）** 铺满 contentSize。

**分子分母来自两张尺寸不同的"图"**，于是：
透明边少的素材（`swarm.png`）偏差小、看着正常；
透明边多的素材（`dash.png` 上下鳍撑得很开）rect 比例被裁成 0.55 而实际是 1.55
⇒ 屏幕上被拉成一块**竖长的方块**。

**修法** 改取 `sf.originalSize`。

⚠️ 这个坑 `Hud.putArt` **已经踩过一次**（那边的结论就是"必须用 `originalSize`"），
`art.ts` 这段注释甚至把因果写反了（声称 `rect` 才是含透明边的尺寸）。**这次是复发。**
口径只有一个：**凡是要拿素材比例，用 `originalSize`**。

## 4. 鱼情雷达：新做

**位置** `Hud.ts` `drawCombat()` · `===== ③b =====`。

用户 2026-10-13 的要求原话：「右上角 展示鱼情 用圆圈表示当前平面的鱼情 类似地图 导航」。
⚠️ 用户截图时**误把波次倒计时那个圆（写 27）当成了鱼情** —— 它其实是氧气条右侧的
波次剩余秒数。**雷达是全新的，不是改旧的。**

### 规格

| 项 | 值 | 依据 |
|---|---|---|
| 圆心 | `(W − 88, 164)` | 避开右上角已被占用的三件（暂停键 / 鱼骨 / 生物质），最低占用到 y≈90 |
| 外环半径 | 52 | 占屏 1.8%，不显著遮挡右上角进场路径 |
| 映射半径 | 44 | 留 8px 环带画"还没进画面"的贴边点 |
| **量程** | 780 | 比屏幕半对角线（≈752）略大 ⇒ **画面内的敌人必然落在圈内**，贴边的只可能是"还没进来"的 |
| 中心 | 玩家点 + 航向小箭头（`w.aim`） | "导航"语义的最小集 |
| 点色 | 直接取 `e.color` | 与战斗画面里那条鱼的核心色同源 ⇒ 一眼对得上是哪一类 |
| BOSS | 大点 + 呼吸环 | 全场唯一"必须提前知道它从哪来"的目标 |
| 贴边的点 | alpha 0.5 | 区分"已在画面内"与"那个方向有东西" |

⛔ **雷达点不给 2px 发光核** —— 那是"可瞄准敌人"的铁律（见 `drawEnemies`）。
给了核玩家会朝打不到的雷达点开火。

### 它补的缺口

侧视画面**看不到"四周"**：从正上方游来的敌人在屏幕上只是"一条斜着游过去的鱼"，
玩家据此判断不出"还剩几条、从哪个方向压过来"。

> **侧视画面管纵深，雷达管平面。** 两者各说一头，缺一个就有一半信息是瞎的。

## 5. 远景鱼群观感重定（同一轮里做的）

修好 clear 之后，46 条**亮青色**椭圆仍然是"飘着的白云 / 落雪"。
用户说的"背景的白色"有一半来自这里。

### 依据

**水下的鱼绝大多数是背光剪影。** 光从上方来，你在下面看远处的鱼，
看到的是"比水体更暗的形状"；只有**自身会发光**的生物才是亮的。所以分档：

| 带 | 体色 | 逻辑 |
|---|---|---|
| L1 阳光带 | `0x2b5266` **暗剪影** | 水亮 ⇒ 剪影取暗一大截的同色系 |
| L2 弱光带 | `0x5f97a2` **微光轮廓** | 水已暗 ⇒ 再暗就**直接消失**，只能略亮 |
| L3 午夜带 | `0x74f2cc` **生物荧光** | 唯一亮的一带（V6.51「光的主权转移」给它的主角位） |
| L4 热泉带 | `0x8a6a48` 暖光轮廓 | 同 L2 的理由，换成热泉的暖色 |
| L5 深渊带 | `0x33485c` 巨影 | 近黑水里唯一能读出的"一团灰蓝" |

⚠️ 第一版配色**过度修正**了：全给暗剪影 ⇒ L2/L4/L5 的鱼在暗水里**直接看不见**
（"没有鱼"也是失败）。**这一组是在 `tools/preview_atmo.py` 的合成图上试出来的。**

### 第二个改动：**成团**

旧版 `x = rand*W, y = rand*H` 各自独立随机 ⇒ 屏幕上是一层**均匀的点**，
读作"雪花 / 星星 / 屏幕脏了"，不是鱼群。

改为**分团生成**：

- 团心留 40px 边距；团内用**三角分布**散布（团心密、边缘疏 —— 这就是"群"的形状）；
- **同团同向同速**（速度 ±12% 抖动）：方向各自随机 = 一锅乱炖；速度差大 = 团被拉成长条后散掉。

> 同样 46 条鱼，**成团之后才第一次读得出"一群鱼"**。

### 新增工具

`tools/preview_atmo.py` —— 复刻 `drawBg → drawVeil → drawAtmo` 的**合成结果**。

```bash
python tools/preview_atmo.py            # 5 带拼图 → docs/shots/atmo_layers.png
python tools/preview_atmo.py --layer 0  # 只出 L1
python tools/preview_atmo.py --old      # 用 V6.53 旧亮色（看"白云"是怎么来的）
```

**为什么值得单独写**：这一条已经不是"参数对不对"，而是"合起来是什么"。
上一版每个数值都合法，合起来却是"背景飘白云" —— **只有把合成结果画出来才看得见**。
