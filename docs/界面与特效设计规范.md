# 界面与特效设计规范

> 立这份规范的直接原因，是三条来自实机的反馈：
>
> 1. 「界面看起来很乱，这个选择出征的单位界面 和 进入关卡能独立开来吗」
> 2. 「技能特效还是很单一 —— 你需要统一规划下，是美术特效搞不定吗」
> 3. 「我需要很好的视觉感，整个游戏界面 还有施法特效」
>
> 三条都**不是"再多画点东西"能解决的**，它们是"没有规则"的三种症状：
> 界面没有信息分层、特效没有形状语言、整体没有色彩系统。
> 所以这一版先立规则，再按规则填内容。

---

## 一、界面架构：两屏

### 1.1 旧版为什么"乱"

旧版把 **选章 / 选关 / 选武将 / 选计谋 / 出征** 五组内容塞进一屏 900×646 的面板：

- 一屏里同时存在 4 张可选卡片 + 6 个计谋小格 + 章节箭头 + 两行提示；
- 玩家没有落点 —— "我现在到底在挑什么"这个问题没人回答；
- 字号被挤到 11~13px 才能塞下，而本作的用户对字号明确敏感。

**结论：一屏不是"信息密度高"，是"信息没有层级"。** 解法不是重排，是拆。

### 1.2 拆成两屏

```
① 战役 · 选关     打哪一关 / 目标是什么 / 首通给什么（+ 势力特性）
② 帐前 · 点将     用谁 / 带哪个计谋（+ 本关摘要）
③ 出　征
```

这个顺序与同类作品一致，玩家的既有心智可以直接迁移：

| 作品 | 流程 |
|---|---|
| Vampire Survivors | 选关 → 选人 → 开战 |
| Brotato | 选人 → 选武器 → 选关 |
| 20 Minutes Till Dawn | 选人 → 开战 |
| **本作** | **选关 → 点将 → 出征** |

共同点是：**心一屏只有一件事**。所以每一屏都能把主题字号放大到 19~25px
（用户字号下限 12px，正文实测落在 12~14px）。

### 1.3 键盘路径

| 键 | 屏① 选关 | 屏② 点将 |
|---|---|---|
| ← / → | 切章（自动跳到该章第一个未通关的关） | — |
| Enter | 进入点将 | 出征 |
| Esc | — | 返回选关 |

按钮与键盘**收敛到同一个入口**（`gotoDeploy()` / `deploy()`），
避免"按钮能进、键盘不能进"或反过来的分叉。

## 二、设计系统（`web/src/config/theme.ts`）

### 2.1 色

旧版是「满屏科技青 `#4ecdc4` + 直角矩形 + 纯白文字」。那套语言读起来是赛博/科幻，
放在三国题材上错位；而且青绿同时被用作边框、高亮、强调、进度条 ——
**什么都强调 = 什么都不强调。**

| 角色 | 色值 | 用途 |
|---|---|---|
| 墨 ink0 | `0x08060c` | 全屏压暗底 |
| 墨 ink1 | `0x120e17` | 面板底 |
| 墨 ink2 | `0x1b1524` | 抬起面（章节条等） |
| 墨 ink3 | `0x261e31` | 卡片底 |
| **鎏金** gold | `0xc9a227` | 描边 / 标题 / 选中 |
| 金高光 goldHi | `0xefd489` | 标题、强调字 |
| **朱红** red | `0xb83b2e` | 主行动按钮 / 印章 / 危险 |
| **青玉** jade | `0x3fbfa8` | 次强调（克制使用：经验条、护甲环、就绪环） |
| 米白 main | `#efe6d2` | 正文（比纯白更"旧"） |

**图形色用 `UI.*`（number），文字色用 `TXT.*`（`'#rrggbb'`）。**
混用会得到"黑字黑底"——这是 Phaser 里最常见的一类隐形 bug，所以分成两个导出。

### 2.2 形

- 面板 = 墨底 + 外侧金暗线 + 内侧强调线 + **四角回纹角标**（`panel()`）；
- 圆角很小（2~6px），保持"木牌 / 竹简"的硬朗感；
- 分隔线中间嵌一个小菱形（`rule()`）；
- **朱红印章**（`seal()`）：三国 UI 的"神来之笔"往往就是这方印。
  结算界面用它盖结果 —— 通关盖「胜」、未竟盖「惜」、阵亡盖「殁」，不读字也知道结果。

### 2.3 层级

`ink0 底 < ink1 面板 < ink2 抬起 < ink3 卡片 < line 分隔`
—— 层级写死在一个序列里，任何新面板都能找到自己的位置，不会出现"卡片比面板还亮"。

## 三、特效体系

### 3.1 「很单一」不是美术问题

先说结论：**不是美术资源搞不定。** 本作所有特效都由代码画（`makeTextures()` 里的
`fx_*` 底形），零外部素材。缺的从来不是素材，是**规则**：

- 旧版六个计谋的爆发特效基本都是「一颗圆点 + 换 tint」；
- 换六个颜色之后，玩家的眼睛读到的仍然是同一个形状 —— 这就是"单一"。

### 3.2 统一的三段式

所有计谋共用同一条骨架，差别只在"爆发形态"：

| 段 | 内容 | 解决的问题 |
|---|---|---|
| ① **蓄力** `castTelegraph()` | 脚下符印浮现 + 光环向内收拢 + 类别图标盖在角色上 | "这一下是我按的"，和普攻的细碎命中彻底分开 |
| ② **爆发** | 形态化的扩散（形态各异，见下表） | 六个计谋必须**轮廓不同** |
| ③ **余韵** | 地面残留：灼痕 / 霜面 / 插地箭簇 / 城垛轮廓 | 让"刚刚发生过一件大事"停留一会儿 |

> 蓄力段是**纯视觉**的，不延迟任何伤害/状态的结算 ——
> 逻辑时序与改造前完全一致，自动化断言（计谋六连测）不需要为特效让路。

### 3.3 色彩语言（与备战界面的计谋图标共用）

| 类别 kind | 色 | 含义 |
|---|---|---|
| burst | 橙 `0xff7b29` | 爆发（火计、十面埋伏） |
| control | 蓝 `0x6ec6ff` | 控制（缓兵计、连环计） |
| buff | 黄 `0xffd93d` | 增益（背水一战） |
| guard | 青玉 `UI.jade` | 守御（空城计） |

**备战界面画的就是这套形状与颜色** —— 玩家进局前就把"形状 → 效果"记住，
局内不用再读字。

### 3.4 底形清单（`makeTextures`）

| 贴图 | 形状 | 用在哪 |
|---|---|---|
| `fx_rune` | 外环 + 内环 + 八辐条 | 所有计谋的蓄力符印 |
| `fx_ember` | 小菱形 | 火星 / 扬尘 / 木屑（通用碎屑） |
| `fx_shard` | 六角雪花 | 缓兵计（唯一带棱角） |
| `fx_flame` | 上尖下圆的水滴 | 火计火舌 / 火墙 |
| `fx_arrowfall` | 箭头朝下的箭 | 十面埋伏（唯一"从上方来"） |
| `fx_bolt` | 锯齿折线 | 连环计铁索放电 |
| `fx_slash` | 月牙 | 近战命中（和远程点命中在轮廓上分开） |
| `cring` / `glow` / `tracer` / `dot` / `shard` | 复用上一版 | 冲击环 / 光晕 / 曳光 / 粒子 |

### 3.5 六个计谋的爆发形态

| 计谋 | 形态 | 一眼可辨的依据 |
|---|---|---|
| 火计 | 沿方向喷三段**火舌** + 地面灼痕 + 上升火星 | 水滴形 + 方向性 |
| 空城计 | 三层**音波环** + 地面**城垛轮廓** + 跟随护罩 | 唯一有"墙"的 |
| 缓兵计 | 六角**冰晶**径向飞散 + 地面结霜 | 唯一带棱角 |
| 十面埋伏 | 天上落**箭**（预兆圈 → 弹道线 → 插地箭簇） | 唯一从上往下 |
| 连环计 | 铁索 + 折线**电弧** | 唯一"连"起来的 |
| 背水一战 | 赤色战意**向上升** + 屏幕四边脉冲 | 唯一反向（别的一律向外扩散） |

> 断言把这条规则钉死了：`六个计谋的爆发形态互不相同（distinct=6/6）`。
> 一旦有人把它们改回同一种形状，守卫会直接 FAIL。

### 3.6 特效照片是怎么拍出来的（证据链）

`docs/shots/fx-1..6-*.png` 是上表的视觉证据。它们**不是**随手截的，六张图里有四张
在第一版是废的，原因全部出在"拍照方法"而不是"特效本身"：

| 拍废的原因 | 现象 | 解法 |
|---|---|---|
| 上一发的残留盖住下一发 | 拍「十面埋伏」拍到的是上一发火计的**火墙**（火墙活 4 秒） | 每发前 `s.fxClear()`（清场通道） |
| 场上没有敌人 | 阵型的阵心是**刻意**刷在屏幕外的，计谋全打在空地上 | 每发前 `s.fxRing(n, r)`（摆靶通道） |
| 靶子半径一刀切 | 火墙铺在身前 78px、落箭有 220px 随机半径，同一个半径要么打不到、要么糊成一坨 | 半径按每个计谋的有效范围给（表见 `shoot_game.py` 的 `FX`） |
| 升级面板挡住整个画面 | 摆靶的敌人被打死掉经验 → 一捡就弹板 → 弹板**暂停物理**并盖住全屏，六张全是升级面板 | 拍照期间 `s.expNeed=1e18` + 已弹着的按 `1` 走游戏自己的关板路径 |
| 抓拍慢半拍 | 火舌只活 380ms，等 0.35s 再走一次 CDP 往返，照片里只剩灼痕圈 | 火舌延到 460ms+ 且抓拍提前到 0.20s |

两条通道（`fxClear` / `fxRing`）都是**只碰视觉**的调试通道：不带 `fx` 标记的对象
（敌人、掉落、UI）一个都不会被误伤；清场连火墙那个还在每 220ms 结算火伤的 Zone
一起清掉 —— 只清贴图不清 Zone 会得到"画面干净、火还在烧"的假干净，这条也有断言。

调特效时用 `SHOT_FX_ONLY=1 python tools/verify_shot.py`，跳过 11 张常规图和 60 秒
中盘采样，一轮从 3 分钟降到 45 秒。

## 四、踩过的坑（都写进了守卫）

| 坑 | 现象 | 守卫 |
|---|---|---|
| 备战面板的 window 键盘监听只增不减 | **对局中按 ← / → 会把备战面板弹回来**（方向键正是移动键），tsc 全绿、布局断言全绿 | 监听必须是场景级唯一一份 + handler 内挡 `started` |
| 相机 zoom 非 1 | 连 `scrollFactor=0` 的 HUD/备战一起缩放偏移，全部飞出屏幕、点击落空 | `CAM_ZOOM === 1` |
| 压暗底放进会被缩放的面板容器 | 小窗口下四边各漏一条约 10px 的局内画面缝 | 压暗底必须是场景级对象 |
| 多条 toast 钉在同一个 y | 「计谋就绪」和「施计」前后脚出现，糊成一团 | 按 `toastLive` 往上叠 |
| 特效 = 圆点换色 | "特效单一" | 六个计谋形态互不相同的断言 |
| 清特效只清贴图 | 贴图没了、火墙的 Zone 还在每 220ms 结算伤害 | `z.setData('fx', 1)` + 清场后 Zone 必须失活 |
| 抓拍脚本只写通道不调用 | 通道在游戏里、照片还是脏的 | 守卫直接读 `shoot_game.py`，断言它真的调了 |
