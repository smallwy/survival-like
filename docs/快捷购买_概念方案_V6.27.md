# 快捷购买 · 概念图与落地规格（V6.27 待定）

> 「快捷购买」= 商店里按 **1 / 2 / 3** 直接买第 N 张卡。
> 现状：卡片左上角一个方括号编号 `[1]`，真正的操作说明在**顶栏下方一行 13px 小字**里。

---

## 一、现状的三个问题（量出来的，不是感觉）

| # | 问题 | 实测数据 |
|---|---|---|
| 1 | `[1]` 用的是**方括号**，在 UI 语汇里读作"编号"（第 1 张），不读作"按 1 键" | `[1]` 15px 等宽字占 `c.x+16 ~ c.x+43`，类型标签在 `c.x+46` → **间隙只有 3px**，两者粘成一个词 |
| 2 | 操作说明**离视线焦点最远** | 玩家在看卡（y≈140~610），提示在 `barY+BAR_H+5`（y≈73），33 个字说了 4 件事 |
| 3 | 买完之后**没有"这张按不了了"的信号** | 卡变灰，键位没有变化；玩家只能按一下试试 |

---

## 二、方案 A · 键帽就地

**思路**：把"按哪个键"从**文字说明**变成**形态语言** —— 键帽（keycap）是跨界面的通用符号，
一个圆角方块 + 加厚的底边就足以表达"这是一颗能按的键"。

### 规格

| 项 | 值 |
|---|---|
| 键帽尺寸 | **24 × 24**，圆角 **6** |
| 位置 | `c.x + 14`，与卡片首行**垂直居中**（首行文字 y+20 基线上移 8px） |
| 边框 | `1px` 状态色 + **底边 `2px` 深一档**（这一笔就是"可按下的厚度"） |
| 数字 | `13px MONO 500`，`TXT.cyber #c8f8ff` |
| 类型标签 | 从 `c.x+46` 移到 **`c.x+48`**（键帽右缘 38 + 10px 间隙），基线与键帽中心对齐 |

### 三态（位置固定，只换颜色与符号）

| 状态 | 键帽 | 数字色 | 备注 |
|---|---|---|---|
| 可购买 | 底 `#0f2b34` / 边 `UI.cyan` / 底边 `UI.cyanDim` | `#c8f8ff` | 唯一亮态 |
| 不足（买不起） | 底 `#161d26` / 边 `MENU.divider` / 底边同底 | `TXT.mute` | **同一套形状掉亮度**，不做第二种样式 |
| 已购 | 底 `#0d141b` / 边 `#22303c` | `#37505e`，符号换成 **✓** | 一眼知道"这张不再响应 3" |

### 配套的两处文案

- 卡底价格条右侧：`点击购买` → **`按 1 购买`**（12px，`TXT.cyan`）
- 顶栏提示行：`点击卡片购买 · 卡片右上角锁定 · 1 / 2 / 3 快捷购买 · Tab 展开状态`
  → **`点击购买 · 右上角锁定 · Tab 查看状态`**（把 1/2/3 交给键帽，文案不再复述）

### 代价
- 卡片首行高度多占 **0px**（键帽 24 落在原首行空间内，只需微调基线）。
- 键帽是**静态**的 —— 玩家按下 1 时，卡上是"卡面闪一下"（已有）而不是"键帽凹下去"。
  要做按压反馈需要额外一层（3px 下移 + 底边归零），可选。

---

## 三、方案 B · 底栏购买带

**思路**：用**对齐**建立秩序。当前底栏只有 368px 宽（刷新 172 + 12 + 继续 172），
两边共 **936px 空着**；而卡片行是 792px 宽、居中在 x `256 ~ 1048`。
把底栏扩成**与卡片同列的整幅操作带**，快捷购买槽直接落在每张卡的正下方。

### 规格（视口 1304 时）

```
x:      24 ──── 232      256 ── 504   528 ── 776   800 ── 1048      1072 ── 1304
      ┌──────────┐   ┌──────────┐ ┌──────────┐ ┌──────────┐   ┌──────────┐
      │  刷新 8  │   │ 1 增压推进│ │ 2 共振放大│ │ 3  回声炮 │   │ 继续下一波│
      └──────────┘   └──────────┘ └──────────┘ └──────────┘   └──────────┘
         208 宽          248 宽        248 宽       248 宽            232 宽
```

- 槽位 x **直接复用卡片列的坐标**（`x0 + col*(cw+gap)`，`cw=248`、`gap=24`）——
  零手算，卡片列宽度一改槽位自动跟着走。
- 高度沿用 `BTN_H = 56`，底栏 y 不变（`y0 + ch + 34`）。
- 槽内两行（都**不换行**）：
  - 行 1：键帽 **22 × 22** + 名称 `12px`（最多 4 汉字 ≈ 48px，槽内净宽 228 放得下）
  - 行 2：鱼骨圆点 + 价格 `14px MONO` + 状态字 `12px`（右对齐）
- 状态：可购买（边 `UI.cyan`）/ **高亮**（bg `MENU.cardHi` + 键帽**反白**：底 `#c8f8ff`、字 `#08111c`）/ 不足（整体压暗）
- 左右两端抽离：**「刷新」贴左、「继续」贴右**，都不与槽共边 ——
  主行动是"离场"，不是"第四个商品"。

### 代价
- 底栏从 368px 变成 1280px，**视觉重量显著上升**；商店整屏变得更"密"。
- 与卡面信息**部分重复**（名称、价格在卡上和槽里各一份）。
  这是刻意的：槽是"操作面"，卡是"决策面"，Brotato 的手柄/键盘 UI 也是这么分的。
- 卡片宽度若改成非 3 列（如 4 列），需要重算槽位 —— 但因为复用坐标，是自动的。

---

## 四、我的建议

**先做 A。** 理由：它修的正是第 1、2、3 条真问题（编号语汇、视线距离、购后信号），
改动只在卡片首行 + 两处文案，不新增任何布局元素，回归风险最低。
B 更像"商店整体版式重做"的一部分，适合和侧栏面板（被动槽 4→6 撑出视口那件事）一起做。

---

## 五、待定

1. 选 A / B / 两者都做。
2. 键帽要不要**按压反馈**（按下 1 时键帽下移 3px、底边归零）。
3. 顶栏那行提示是否同意缩短（现在是 4 件事挤在 33 个字里）。
