## §1 为什么必须移除（**这是路线问题，不是调参问题**）

V6.60 → V6.61 → V6.64 三轮尝试，物理推导一轮比一轮严谨：

| 版本 | 引入了什么 |
|---|---|
| V6.60 | 等距平行条 + `(1−t)^1.6` 分段衰减 + 梯形 |
| V6.61 | 汇聚消失点（透视）+ Beer–Lambert `e^(−1.75t)` + 分波长吸收 + 散射扩散 + 逐条独立相位 |
| V6.64 | 拆两层：整片基底光幕 + 13 条只贡献**乘性起伏包络** |

**三轮都判失败，根因是同一个**：`Graphics` 是**矢量填充**，没有渐变、没有模糊、没有软笔触。
而体积光**之所以是体积光，全部来自边缘的软过渡** —— 边缘一硬，无论中间算得多物理，
画面上都只是「一层带硬边的半透明色块」。

> **判据（可复用）**：一件事能不能用 `Graphics` 做，不看它「物理上多对」，
> 看它**承不承认"边缘是模糊的"**。承认（体积光/软阴影/光晕/烟）⇒ 必须位图或着色器；
> 不承认（几何零件/UI 框/硬边命中提示）⇒ 矢量做反而更准。

⇒ 移除后，**光的表现整体下放到 env 背景图**（打样见 §3）。

## §2 移除清单（`cocos/assets/scripts/view/DiveGame.ts`）

| 类别 | 移除内容 |
|---|---|
| 接口 | `interface Beam`（`x/w/ph/lit/sx`） |
| 常量 | 整段光柱常量（`BEAM_N` / `BEAM_VP_*` / `BEAM_SWAY_*` / `BEAM_COL_*` / `BEAM_ABSORB` / `BEAM_DIFFUSE` / `BEAM_W_*` / `BEAM_WAVE_*` / `BEAM_A0/A1` / `BEAM_SHEET_A` / `BEAM_ENV_GAIN` / `BEAM_SEG` / `BEAM_OVERLAP` / `BEAM_LIT_GAIN` / `BEAM_D0/D1`） |
| 字段 | `beams` / `beamFade` / `beamVpX` / `beamVpY` |
| 方法 | `prepBeams` · `beamGain` · `drawBeams` · `beamEnvelope` · `beamSheetStrip` · `buildBeams`（**6 个**） |
| 调用 | `prepBeams(w)`（在 `drawBg` 之前）· `buildBeams(layerIdx)`（在 `buildAtmo` 里）· 调度分支 `case 1: this.drawBeams(w)` |
| 连带 | 颗粒的「被光柱照亮」（`BEAM_LIT_GAIN` 那三行）—— **没有光束就没有照亮的对象**，留着只会让 L1/L2 的颗粒凭空变亮且无因 |

**保留**：`ATMO_QUALITY` 与「按带互斥」的预算结构原样不动（`case 0/1` 留空分支），
这样荧光 / 烟柱 / 呼吸点阵的图元预算不变。

**光柱的墓志铭**留在原常量位置（`DiveGame.ts` 里那段 `⛔ 光柱 / 光幕渲染已从渲染层移除`），
避免下一个人「好心」把它加回来。

### 本轮的工程教训（值得单独记）

> **按行号连做多次删除，必须从后往前。**
> 我先删了前面的区间，再用旧行号删后面的 ⇒ 删错地方，而且编译期报的错
> （`TS1128 Declaration or statement expected`）离真正的原因很远，误导了我一次。
> **正确做法**：先把所有区间收集完，再按 `start` 降序应用。

### 画面上兑现了什么

| 要求 | 兑现 |
|---|---|
| 无海床 / 无岩壁 / 看不到底 | ✅ 全是开阔水体 |
| 丁达尔光柱从上方斜射 | ✅ 数道宽光柱，**边缘完全模糊发散**（矢量做不出的那部分） |
| 水面焦散网状光斑 | ✅ 画面上部有 |
| **海生物陪衬（本轮新增）** | ✅ **三层**：最远极淡密集小鱼群 → 中间稀疏稍大鱼群 → 最近三四只大鱼 + 一只水母 |
| 主光源在画面上方 | ✅ |
| 无文字 / 无 UI | ✅（模型自带的角标水印已本地修掉，见 §4.3） |

### ⚠️ 一处需要收敛：最近一层的鱼**偏大偏实**

打样的最近一层鱼屏显约 50–70px、颜色接近纯黑。而**敌人**的识别铁律是
「**2px 发光核心 + 比水体暗的实心剪影**」—— 背景鱼一旦做到这个量级，
玩家会**先打背景**。

⇒ 下一轮要求：最近一层的鱼**体量收到 2/3 以下、透明度整体降 30%**
（或换成"只留 1–2 只且更远"）。判据是 §2bis 的分工表：**背景剪影必须比渲染层的动态鱼更淡、更小、更少**。

## §4 三个待解问题

### 4.1 画布：1536×1024 vs 目标 1536×1180

生成后端给的横向尺寸是 **1536×1024**（比例 1.50），规格要的是 1536×1180（比例 1.30）。

⚠️ 这个规格的**原始目的**是给 V6.56 的**背景地形滚动**留纵向余量。
但 **L1/L2 是无地形开阔水域** —— 本来就没有可滚动的地形结构，
强行把它拉高到 1.30 只是为了让"滚动时边缘不漏"。

**三条路（待拍板）**：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A. 二次扩图** | 把这张当参考，再出一版纵向更高的构图 | 再花一次额度；且模型可能给不出 1.30 |
| **B. 分块拼接** | 上下各出一张 1536×1024，接缝处做渐变过渡，拼成 1536×1180 | 接缝风险；两张风格可能漂移 |
| **C. 改规格** | L1/L2 用 1536×1024，**视差滚动**代替整图滚动（背景不动、只动颗粒与鱼群） | 要改渲染层（小） |

**我倾向 C**：L1/L2 的滚动感本来就靠**颗粒与鱼群**给（`scrollV` 已在动它们），
背景整图滚动是无地形水域里**收益最低**的一项，而它却卡住了整个环境的画布规格。

### 4.2 上下无缝

打样首末行差 **61.8**（阈值 14）。目前首行是水面亮部、末行是深蓝水体 —— 这是**构图**决定的，
不是画质问题。若走方案 C，这一条**直接消失**（不需要纵向拼接就不需要上下同色）。

若坚持要无缝：出图时明确要求「**画面最上方 10% 与最下方 10% 都画中性水体纹理，
不放任何"舞台性"内容（水面、光柱起点、大剪影）**」。

### 4.3 水印（已本地修掉）

模型输出带了右下角角标。本轮用「同一 y 区间左侧水体填充 + 边缘羽化」盖掉，
水印所在区域是平静水体，肉眼无痕。✅ 已修，但**正式出图仍应在提示词里再压一次**
（本轮提示词已写"无边框、无水印、无签名"，模型仍加了 —— 说明**提示词压不住后处理角标**，
必须走"出图后本地修"这条固定工序）。
