# 下潜滚动与换带过渡 · V6.56

> 对应 V6.52 §3.1 / §3.2 / §3.3 / §3.4。落地顺序第 3+4 步。
> 提交：`feat(sideview): V6.56 下潜滚动 + 换带三段式`（分支 `cocos`）

## §0 结论先行

**这轮解决的是"体感"。** 之前 V6.53/V6.54 把**朝向**改成了侧视，但**运动**没跟上 ——
屏幕上除了鱼在游，水本身是**冻住的**：背景图静止、颗粒 6~20 px/s（37~125s 才扫过一屏）、
换带是**一帧硬切**。

所以玩家读到的不是"我在下潜"，而是"我在一个贴着海底照片的平面上打转"，
换带时"像坐电梯"（用户原话）。

本轮把**运动**补上，四件事：

| # | 做了什么 | 规格 |
|---|---|---|
| ① | **下潜滚动速度 `scrollV`** —— 换带时爆冲、指数衰减回稳态 | §3.1 |
| ② | **颗粒 / 远景鱼群接进速度场**（含 L4 反向） | §3.2 |
| ③ | **温跃层扫带** —— 从下往上扫过的一条波纹带 | §3.3 ② |
| ④ | **双图 crossfade + 水压环** | §3.3 ③ / §3.4 |

⛔ **模拟层一行未改。** `scrollV` 是纯表现量 —— 弹道、碰撞、氧气收支、敌人生成全部不动。

## §1 数值表（每个数都给了依据）

| 常量 | 值 | 依据 |
|---|---|---|
| `SCROLL_BASE` | **46 px/s** | 扫过一屏（749px）= **16.3s**。旧值 6~20 ⇒ 37~125s，**慢一个数量级**，屏幕上读不出"在动"。46 是"一眼能看出在动、又不至于晕"的档位（≈ 屏幕高的 6%/s） |
| `SCROLL_BURST` | **220 px/s** | = **4.8×** 稳态。V6.52 §3.1 直接给定 |
| `BURST_TAU` | **0.9 s** | 指数衰减 `e^(-t/0.9)`。实测值：τ=127 / 2τ=76 / 3τ=57 → **约 3.5s 落回稳态**（见 `descent_curve.png`） |
| `SCAN_DUR` | **0.6 s** | V6.52 §3.3 ② 直接给定 |
| `XFADE_DUR` | **2.0 s** | ⚠️ **必须 < `descDur`（2.1s）**。下潜相位一结束就 `startWave()`，流 0.1s 余量；跑不完会在屏幕上留一个"两张图各一半"的中间态 |
| `RING_DUR` | **0.9 s** | V6.52 §3.4 直接给定 |

### 颗粒视差系数 `MOTE_MUL`（按带，`[近景, 中景]`）

| 带 | 近景 | 中景 | 说明 |
|---|---|---|---|
| L1 / L2 / L3 / L5 | `+1.00` | `+0.35` | 标准视差：**近快远慢 = 深度线索** |
| **L4 热泉带** | **`-0.62`** | **`-0.22`** | **整组反向**（热流向下） |

- 远景（背景图）**不滚** —— 它没有可滚的特征（见 §4 差异说明）
- ⛔ **深度不影响速度**（V6.52 §3.2）：别做"越深越慢"，那削弱下潜感。深度只影响**密度 / 尺寸 / 亮度**
- ⚠️ **L4 反向是 `ventPush = 190` 的视觉证据** —— 玩家看到颗粒往下走，紧接着手感上被顶开，
  **机制与视觉第一次说同一句话**。取 `-0.62` 而不是 `-1.0`：读作"水流被顶住了"，不是"整片水在倒流"

## §2 三个关键实现点（都是"看着对、其实错"的高发区）

### ① `beginXfade()` 的调用时机**不能挪**

```
handleEvent('descend')  ← 本帧 update 内，layerIdx 已 ++，但 syncBg 还没跑 ⇒ bgNode 上还是【旧图】
        ↓  beginXfade() 把旧图拷到 bgNodeOld
syncBg(w)               ← 本帧稍后，把 bgNode 换成【新图】
```

`handleEvent` 在 `w.update` 之后、`syncBg` 之前 —— **这个顺序天然满足，但极其脆弱**。
挪到 `syncBg` 之后再调，拷到的就是新图 = **没有过渡**（而且是"不报错、图也在"的静默失效）。
已在代码里就地标注。

### ② 旧图**压在上面淡出**，不是"两层各淡一半"

节点顺序是设计的一部分：

```
bg     Sprite  新图，恒定满不透明（在下面）
bgOld  Sprite  旧图，255 → 0 淡出（在上面）
```

alpha 合成下 `旧×a + 新×(1-a)` **正好等于一次干净的交叉淡入**。
两层都设半透会先暗一档再亮回来（双重曝光）—— 看起来像"闪了一下"。

### ③ `Mote.vy` 被删掉了

速度**不逐条存**，改为每帧由 `MOTE_MUL[带] × scrollV` **现算**：
逐条存速度的话，换带爆冲只能推快**新生成**的颗粒，屏幕上已有的那批还在按老速度走
⇒ "换带时整片水没一起动"。现在每条只留一个 `jit`（±20% 抖动，免得整屏颗粒像一块板）。

**回绕必须双向** —— L4 的颗粒是往下走的，只判 `y < -4` 会让它们在屏幕下方越积越多。

## §4 与 V6.52 规格的差异（诚实标注）

1. **`scrollY`（积分量）没有落 —— 落的是 `scrollV`（速度）**
   V6.52 §3.1 写的是 `scrollY += vScroll * dt`。实际实现里**所有消费者都按速度驱动**
   （颗粒、鱼群都直接 `y += v × dt`），积分量本身没有消费者。
   等 §4.3 的可滚环境图落地、需要"图偏移到哪里"时才引入 `scrollY`。
   **不是省事，是不写死字段。**

2. **扫带的位置从 `gAtmo` 出**（V6.52 未指定层）
   必须夹在 `gVeil` 与 `gBack` 之间：放 `gVeil` 下面会被压暗吃掉；放 `gBack` 上面会盖住敌人。

3. **水压环用独立的 `ringT`，不共用 `xfadeT`**
   共用会让"没加载到美术资源"（`beginXfade` 早退）连带把水压环也吞掉 —— 一个角落里的耦合。

## §6 实机确认清单（Creator 3.8.8 · `Dive.scene`）

⚠️ 静态验证全绿只是**下界**。以下必须目视：

1. **稳态滚动**：水面颗粒是否**明显在往上掠**（约 16s 扫过一屏）？不是"几乎不动"
2. **三层视差**：近景颗粒（亮小）明显比中景（暗大）快？远景背景图不动？
3. **换带那一刻**：世界是否**猛地往上一窜**然后缓下来（≈3.5s）？而不是"啪"地切图
4. **扫带**：是否有**一条横向波纹带从屏幕底部扫到顶部**（0.6s）？
5. **水压环**：是否有 **3 圈**从屏幕中心外扩（0.9s）？
6. **背景有没有闪一下**：如果 crossfade 期间画面**先暗一档再亮回来** ⇒ 说明两层都半透了
   （旧图应在上、新图在下且满不透明）
7. **L4 热泉带**：颗粒是否**反向往下走**？手感上是否同时被热泉顶开？
8. **暂停**：暂停时水**继续动**（与海雪口径一致 —— 暂停是"停住战斗"，不是"把水冻成冰"）
9. **退回标题**：换带正跑到一半时退回标题，**旧背景图不能留在标题界面上**
