### §0.3 类型与规模

| 项 | 现状 | 判定 |
|---|---|---|
| `Kind` | `'swarm' \| 'dash' \| 'drift' \| 'boss'` | **全游戏只有 3 种敌人外观** |

   且直接产出"浅层见底"的违和感。
3. **种类**：只有 3 种鱼 ⇒ 用户「不同水域的鱼情要区分、种类应该丰富」**在当前资源下做不到**。

## §1 环境图 5 张

### §1.1 尺寸与格式（硬约束）

| 项 | 值 | 依据 |
|---|---|---|
| 画布 | **1536 × 1180** | 纵向比现在多 **196px**。V6.56 的 `scrollY` 机制已就位，但没有余量就滚不动（现在 cover 到 1304×835 后**只剩 86px**） |
| 上下边缘 | **无缝**（镜像或内容自然延续） | 滚动时需要 wrap |
| 格式 | PNG 或高质量 WebP | — |
| 单张体积 | **≤ 0.8 MB** | L1 现在 2.46MB，是其余 4 张总和的 3 倍 |
| 亮度红线 | **每张 ≥ 6% 像素亮于 90**（V6.51） | 低于此值 = 叠加压暗后近黑屏（L5 曾经中央亮度 ≈9） |

### §1.2 逐带要求

| 带 | 地形 | 光 | ⛔ 禁区 |
|---|---|---|---|
| **L1 阳光带** | **无底** —— 开阔水体，只画远处水色渐变与水面焦散 | 强顶光 + 丁达尔光柱 | ⛔ **不许出现海床、峡谷、岩壁、任何"能见到底"的东西** |
| **L2 弱光带** | 无底，或极远处一线模糊地形 | 只剩远处零星光斑 | ⛔ 同 L1；不许画近景岩壁 |
| **L3 午夜带** | 两侧暗岩壁（可有，但只作为**剪影**） | 无自然光，生物荧光是唯一光源 | ⛔ 不许有"打亮"的岩面 |
| **L4 热泉带** | 热泉烟柱 + 管虫丛剪影 | 橙红自发光，从**下方**上来 | ⛔ 不许用冷青做主光 |
| **L5 深渊带** | 近乎无地形 | 只有极稀疏发光点 | ⛔ 全黑（须留 ≥6% 亮像素） |

## §2 敌人贴图矩阵

### §2.1 目标：3 种 → **约 10 种**

按 `LAYER_ECO.species`（数据层已定）派生出每一带的敌人外观：

| 带 | `species` | 建议贴图（每带 2 种） | 类别 |
|---|---|---|---|
| L1 | 表层鱼群 | `swarm_l1`（小型银青鱼）· `dash_l1`（尖吻快鱼） | 小 · 快 |
| L2 | 中层鱼群 | `swarm_l2`（中体青灰鱼）· `drift_l2`（扁体慢鱼） | 中 · 慢 |
| L3 | 荧光链鱼群 | `swarm_l3`（**带发光点**的链鱼）· `drift_l3`（发光水母） | 中 · 发光 |
| L4 | 热泉散鱼 | `swarm_l4`（暖橙短体鱼）· `dash_l4`（避开热泉的急游） | 小 · 热 |
| L5 | 深渊巨影 | `giant_l5`（**大而实**的巨影，2 种轮廓） | 巨 · 压迫 |

### §2.2 尺寸与格式（沿用图标锚点惯例）

| 项 | 值 |
|---|---|
| 画布 | **512 × 512**（正方形，便于统一缩放；高度不足的用透明补齐） |
| 底 | **纯色底**（纯黑或纯绿）—— 便于抠底，**不是透明底交付** |
| 方向 | **侧视、头朝左**（与 `swarm/dash/drift` 一致 —— 渲染层靠 `scale.x = -1` 镜像到右侧） |
| 主体 | **单个、居中、正交视角、不与其他元素重叠** |
| 体积线索 | 沿用以太 4 条：投影 / 侧壁 / 受光弧 / 暗弧。**光源固定左上** |
| ⛔ 禁止 | 文字、UI 边框、底板、阴影面板、多个主体叠放 |

> ⚠️ **头必须朝左**：`drawEnemies` 的镜像基准是"贴图朝左"。朝右的新图会让整场鱼反向。

### §2.3 「种类丰富」的三层落地（**不只是换图**）

| 层 | 改什么 | 影响面 |
|---|---|---|
| ① 皮肤 | 按 `layerIdx` 选贴图 | 渲染层，零风险 |
| ② **变种倍率** | 同一 `Kind` 在不同带有不同的 `hp / speed / r` 倍率 | 数据层小改（`mkEnemy` 读 `LAYER_ECO` 的倍率字段） |
| ③ 新 archetype | 行为差异（新的移动/攻击模式） | 模拟层大改 —— **本轮不做**，单独立项 |

> **① + ② 就能让"玩家得到的体验有差异化"**（同一波次在不同深度手感不同），
> 而且模拟层的弹道/碰撞/氧气收支**一行不改**。
> ③ 才是真正的"新敌人"，但它会碰 P0 判定，按 V6.48 的结论**排在后面**。

## §3 生态装饰贴图（`gAtmo` 的第二批素材）

`LAYER_ECO.bio[]` 里的元素目前**全部是矢量的**（`buildSchools` 用椭圆+三角画剪影）。
按 **B 混合形态**（静态装饰 → 切图），以下应当位图化：

| 带 | 元素 | 类型 | 建议 |
|---|---|---|---|
| L1 | 丁达尔光柱 · 水面焦散 | 光效贴图 | **加法叠层**（`alpha = 亮度`，纯黑底导出） |
| L2 | 远处光斑 · 暗流纹路 | 光效 | 同上 |
| L3 | 荧光浮游链 · 生物光斑 | 发光体 | 同上，用**青绿**荧光色 |
| L4 | 热泉烟柱 · 管虫丛 | 地形装饰 | 普通 alpha（剪影） |
| L5 | 呼吸点阵 | 发光体 | 加法叠层 |

**尺寸**：光效贴图 **512×512**（会被拉伸）；地形装饰 **512×512**。
**通道规范**：光效一律 **`alpha = 亮度`**（纯黑底导出，渲染层走普通 alpha —— ⛔ 全线禁用 ADD 混合）。

## §5 可脚本验收的项（**不靠眼估**，已实跑）

⚠️ 沙箱里**没有 numpy**，下面用纯 PIL（已实测可用）：

```bash
# ① 尺寸与体积
python -c "
from PIL import Image; import glob, os
for p in sorted(glob.glob('cocos/assets/resources/env/L*.png')):
    print(os.path.basename(p), Image.open(p).size, round(os.path.getsize(p)/1e6,2),'MB')
"

# ② 亮度红线：每张 env ≥6% 像素亮于 90
python -c "
from PIL import Image; import glob, os
for p in sorted(glob.glob('cocos/assets/resources/env/L*.png')):
    h = Image.open(p).convert('L').histogram(); t = sum(h)
    pct = sum(h[91:])/t*100
    print(os.path.basename(p), round(pct,1), '%', 'OK' if pct>=6 else 'FAIL')
"

# ③ 敌人贴图方向：主体重心 x 必须落在 **42%~47%**（头在左）
python -c "
from PIL import Image; import glob, os
for p in sorted(glob.glob('cocos/assets/resources/fish/*.png')):
    a = Image.open(p).convert('RGBA').getchannel('A'); w,h = a.size
    v = list(a.resize((w,1), Image.BOX).getdata()); s = sum(v) or 1
    cx = sum(i*n for i,n in enumerate(v))/s
    print(os.path.basename(p), round(cx/w*100), '%')
"
```

**当前实测结果（重出前的基线）**：亮度 `L1 38.6 OK / L2 5.5 / L3 1.4 / L4 2.6 / L5 0.4`（4 张 FAIL）；
重心 `swarm 46% / dash 42% / drift 42%`（全部 ✅）。
