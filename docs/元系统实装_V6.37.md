## 3. 数据层规格

### 3.1 档案 v2 字段表

| 字段 | 类型 | 含义 |
|---|---|---|
| `runs` / `bestLayer` / `bestBiomass` / `lastSub` / `lastDepth` / `cleared` | v1 原样 | **一个都没改**，v1 存档直接可用 |
| `bio` | number | 当前沉淀余额（可花） |
| `totalBanked` | number | 历史累计沉淀（只增不减，解锁条件读它） |
| `surfaced` | number | 上浮兑现次数 |
| `unlocks` | `string[]` | 已解锁记录（**不是 `Set`**，见 §3.2） |
| `seen` | `Record<string,number>` | 图鉴遇见计数 |
| `milestones` | `string[]` | 已达成里程碑 |
| `normalClears` | number | 通关次数 |
| `perks` | `Record<PerkId,number>` | 三项永久强化的等级 |

### 3.2 三条必须遵守的规则

**① `unlocks` / `milestones` 用 `string[]`，不用 `Set`。**
JSON 序列化 `Set` 会**静默变成 `{}`** —— 不报错，直接把进度丢光。这类 bug 只在"玩家第二天回来发现全锁了"时才暴露。

**② 存档迁移：纯函数可测 + key 升级但回落读旧 key + 旧 key 不删。**

```
loadProfile()  → 读 sgr.profile.v2
                 没有 → 读 sgr.profile.v1 → migrateV1toV2() → 返回
                 v1 的 key **保留不删**（回滚保护：新版本出问题能退回旧版）
```

**③ 解锁判定 = 已记录 ∪ 条件已达成。**

```ts
isUnlocked(p, id) = p.unlocks.includes(id) || reached(p)
```

只看 `unlocks` 会让**新档被锁死** —— 默认武器（脉冲机枪等）的 `reached()` 是 `() => true`，但它们并不在 `unlocks` 里。少了后半截，"初始武器抽不出来"。

### 3.3 沉淀率 25%

`BANK_RATE = 0.25`，`banked = floor(带出 × 0.25)`。

- 一局带出 400 → 沉淀 100 → 买得起第 1 档强化（40）
- 红线 **≤ 30%**：太高会让"多沉一层"的收益盖过"活着上浮"的取舍，把下潜决策压扁

溺水时 `banked = 0`，且结算屏**显式写**"溺水 · 生物质全损，无沉淀"—— 不写玩家不知道沉淀那一栏为什么消失。

## 5. 永久强化（`PERKS`）

| 名称 | 效果 | 每级 | 满级 |
|---|---|---|---|
| 装填效率 | 全局射速 | +2% | **+10%** |
| 结构强化 | 氧气上限 | +3 | **+15** |
| 声呐调校 | 拾取范围 | +4% | **+20%** |

- 各 **5 级封顶**，价格 `[40, 60, 80, 100, 120]`（满级单项 400 沉淀）
- 满级三项合计 ≈ **两件遗物** —— 这是刻意的红线：局外不能让"开局就比别人强"盖过"这一局你打得好不好"

**实现上的一个坑**：强化必须**并进 `st`**，不能直接改 `o2Max`。因为 `equipRelic()` 会用 `layer().o2Max + st.o2Bonus` **整份重算** `o2Max` —— 直接写 `o2Max` 的话，玩家一装"骨殖转化"（`o2Bonus −15`）就把永久强化冲掉了。

## 6. 图鉴（`CODEX`，23 条）

| 分类 | 条数 | 内容 |
|---|---|---|
| 敌人 | 3 | 游群 / 冲刺体 / 漂移水母 |
| 首领 | 1 | 深渊守望者 |
| 武器 | 7 | 按**族**收（进化形态归到基础族，不重复计数） |
| 遗物 | 12 | 按遗物 id |

- **只记录，绝不产生战力** —— 集齐不给加成。"集齐换战力"会把收集从"我想去看看那是什么"变成"我必须刷满才不吃亏"
- 计数来源：敌人按**刷怪次数**（`world.spawned`），首领/武器/遗物各记 1 次（用 1 次和用 100 次价值一样）
- id 带前缀 `enemy:` / `boss:` / `weapon:` / `relic:`，四类 id 空间不撞车
- 未见图鉴显示**剪影**而不是问号块 —— 剪影保留轮廓信息（"这是个硬壳的"），才有补图鉴的动力

## 8. 本轮修正（2 条）

### 8.1 【真 bug】图鉴网格溢出面板底 44px

原规格 `ROWS = 4`：`4 × 142 + 3 × 12 = 604`，从 `py + 140` 起算 → 网格底 **768.5**，而面板底只有 **724.5**（屏幕底 749）。
**溢出 44px，且第 4 行会压到页脚文字。**

之前没暴露的原因：现有最大分类是遗物 12 条，只画 2 行，第 3/4 行根本没内容 —— **是个潜伏 bug，加几条遗物就会现形**。

**修法**：`ROWS = 4 → 3`（18 格/页，已覆盖现有最大分类 12 条），并把 `gy` 改成按「tab 下沿 → 页脚上沿」**垂直居中**计算：

```ts
const bandTop = this.py() + 74 + 44
const bandBot = this.py() + PANEL_H - 34
const gy = bandTop + Math.max(0, (bandBot - bandTop - gh) / 2)
```

这样只要 `ROWS × CELL_H + (ROWS−1) × GAP` 不超过这条带，**增加行数也不会再溢**。
修正后：网格底 **641.5**，页脚 **690.5**，余量 **49px**。

### 8.2 两处 `MENU.header` 不存在

`MENU` 只有 `page / card / cardHi / slot / divider / edge` 六个键，**没有 `header`**（`header` 属于 `BRIGHT`，是"中调舱内"那套弹窗皮肤）。
`Codex.drawShell()` 与 `Title.drawDock()` 各写了两处 `g.fill(MENU.header, 0.9)` 当顶栏横梁。
**修法**：改用 `UI.panelHi`（"抬起面"）—— 面板底是 `UI.abyss`，取同族色既亮于面板、读作横梁，又不用给 `MENU` 硬塞新色。

## 10. 待你目视确认（4 处）

在 Cocos Creator 3.8.8 里打开 `cocos/`，点 ▶ 跑 Dive 场景：

1. **标题屏** —— 右上角有没有沉淀钱包（菱形 + 数字 + "沉淀生物质"）；主按钮下方有没有「装置坞」「图鉴」两个按钮。

3. **图鉴屏** —— 点「图鉴」，确认 4 个 tab、遗物 tab 12 格、未见的显示剪影 + `？ ？ ？`、右上角是 `已见 N / 23`；点面板外能关。
4. **装置坞** —— 点「装置坞」，切到「强化」tab，确认三行强化的价格/等级/可买状态；买一次看沉淀有没有扣、等级有没有涨；切「武器」tab 看只读列表。
