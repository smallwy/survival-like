## 1. 背景 —— 已修（真 bug，不是设计问题）

### 症状
五层背景图 `env/L1~L5.png` 全部导入正常、`.meta` 齐全、`syncBg()` 也在正常接线，
但屏幕上永远是**一片纯深蓝 + 海雪**，背景图一次都没出现过。

### 根因
`drawBg` 里那层「铺满全屏的 `UI.abyss` α=**1**（不透明）」被画进了 **`gBg`**，
而 `gBg` 在节点树里排在背景图**之后** —— Cocos 里「后建 = 上层」，
于是那层不透明色**正好把背景图整个盖住**。

web 侧根本不是这么写的：

| | web | 修前的 Cocos |
|---|---|---|
| 不透明底色 | `main.ts:13` `backgroundColor:'#04070d'`（画布清屏色，在**所有图层之下**） | 画进了 `gBg`（在背景图**之上**） |
| `gBg` 的职责 | `tint` α0.10 + 海雪 | 不透明底色 + 海雪 |

### 规格（引擎中立 · 三层职责）

| 层 | 职责 | 不透明？ | 与背景图的相对位置 |
|---|---|---|---|
| 底色层 | 水的基色（`UI.abyss`）+ 按可视区外扩 8px（防机型宽高比差异露边） | **是** | **之下** |
| 背景图层 | 环境实景（cover：等比放大到盖满，多出部分居中裁掉） | — | 基准 |
| 海雪层 | 60 颗上浮微粒，α0.16 `0x9fe1cb` | 否 | **之上**（雪是"我在水里"的近景证据） |

### Cocos 落地
- 新增节点 `gBase`（`Graphics`），**排在 `bg` 之前** —— 见 `view/DiveGame.ts` `buildNodes()`。
- 节点树顺序：`gBase → bg(Sprite) → gBg → gVeil → gBack → fishLayer → gEnt → sub → gPlayer → gFront`。
- 没背景图时 `bgNode.node.active = false`，`gBase` 自动成为兜底底色（行为不变）。
- **排查陷阱**：这类错误**不报错、图也在**，只能靠"对着节点顺序数一遍"发现 ——
  已写入 `cocos/README.md` 已知坑第 20 条。

## 1.5 商店买完又变黑 —— 已修（真 bug）

用户报：「商店买了之后 又黑色了」。与上面那个是**同一块背景、不同的失效路径**。

### 根因
弹窗相位（商店 / 决策 / 结算）会走 `hideWorld()`，它把 `bgNode.node.active = false`。
而 `syncBg` 的旧写法是：

```ts
if (!this.artLoaded || this.bgLayer === w.layerIdx) return   // ← 层没变就整个跳过
...
this.bgNode.node.active = true
```

于是**同层内**（`layerIdx` 不变）离开商店后，`syncBg` 直接早退、**不会重开背景图** ——
屏幕上只剩 `gBase` 的 `UI.abyss #04070d` 铺底（近黑蓝，被读作"黑"）。
只有下潜换层（`layerIdx` 变了）才会重新显示，所以这个 bug 时有时无。

### 修法
把两件事拆开：**换贴图**只在换层时做；**该不该显示**每帧都设。

```ts
if (this.bgLayer !== w.layerIdx) { /* 换 spriteFrame + cover 尺寸 */ }
this.bgNode.node.active = true   // ← 每帧无条件
```

### 通用判据（已记入 README 已知坑 #21）
**任何一个被某处 `active = false` 关掉的节点，它的"重开点"要么每帧执行、
要么有明确的回开事件。**只挂在"变化事件"（这里是"换层"）上就一定会在某个路径上漏。

## 1.6 玩家机体 = 炮塔总成 —— 已重做

用户报：「装射器和武器没有镶嵌上」。**不是没画，是照着旧版 web 画了已经删掉的东西。**

### 根因
Cocos 侧 `drawPlayer` 画的是：**座圈整圆 + 空座的深色圆点 + 一条代表发射器的裸线段**。
而 web **V6.13 已删除"空座 + 座圈连线"** —— 用户原话：
> 「人家只有特定的镶嵌，其他都内置进去、不显示出来」

即：战斗画面里**只画实际装配的发射器本身**（镶嵌在机体上的实体零件），
不画"还空着几个位"的提示。

### 规格（引擎中立）
每台已装配的武器 = **一座塔**，相对机体中心的角度由 `SEAT_ANGLES_DEG[i]` 决定，
塔心距为 `SEAT_RING_R`（新解锁的扩容位在 `i >= BASE_SEATS` 时用琥珀色标示）。

| 层 | 内容 | 作用 |
|---|---|---|
| ① 底盘外环带 | `UI.cyanDim` α0.55 **实底**（不填黑）+ 环带上缘亮弧 / 下缘暗弧（随塔转） | "镶嵌"的物理感 —— 有厚度、有受光面 |
| ② 内凹槽 | `UI.abyss` α0.40，向下偏移 `R*0.10`，内壁左上受光 | 塔是**嵌进去**的，不是贴上去的 |
| ③ 外缘亮环 | `neonCircle`（开火瞬间转白）+ 左上金属高光弧 | 强调轮廓 |
| ④ 装填进度环 | `neon` + `g.arc`，起点 `a0 = −π/2`，进度 `1 − timer/ivLast` | 玩家能读出"这台还有多久开火" |
| ⑤ 中心毂 | 暗影 → 亮面 → 左上高光点 | 塔心 |
| ⑥ 扩容座 | `i >= BASE_SEATS` 时：琥珀环 + 4 个卡榫 | 与内置位的区分，**只在战斗里标"这是后装的"** |
| ⑦ 发射器本体 | `neonLine` 指向 `pose.ang` + `drawEmitter(id, …)` | 按武器 id 出不同造型 |

`drawEmitter` 按 id 分四类：`sonar`（三层同心弧）、`gun`（三根平行枪管 + 枪口亮点）、
`torpedo`（本色半透明管身 + 管口环 + 内壁高光）、电弧（两根电极柱 + 中间跳跃弧光）。

> ⚠️ **管身绝不能填近黑色** —— 那是"击杀后画面上的黑方块"的真凶
> （Cocos 端曾用暗色多边形当管身，深色层里看着就是一块脏斑）。改用**本色半透明**。

### Cocos 落地要点
- 新增 `rot(cx, cy, ang, lx, ly)`：**手算旋转**（Cocos `Graphics` 无 `translate/rotate`，
  见 `cocos/README.md` 已知坑 #24）。
- `drawTurret(w, i)` / `drawEmitter(id, cx, cy, ang, firing)` 插在 `drawPlayer` 与 `drawFx` 之间。
- **删掉**了 `SEAT_RING_R / MAX_SEATS / SEAT_ANGLES_DEG` 之外的"空座渲染"代码；
  三个常量**保留给商店**的 `mountDiagram` 用（要显示"还有空位"的时机是**商店**，不是战斗）。
- 朝向指示：艏部探照灯（`w.px + cos(aim) * (R*0.95 + 16)` 处的青色亮点）。

## 1.7 商店重做：全屏暗色 → 亮色居中面板 V7 —— 已重做

用户报三条：**① 商店资源不对 ② 全屏、太大 ③ 画风太暗，要亮色**。

### 根因
1. **太大**：旧版用 `pageFill()`（**不透明、铺满全屏**）画底 —— 那是"页面"的语义，
   不是"弹窗"的语义。规格里商店一直是**居中面板 + 暗幕**。
2. **太暗**：沿用菜单暗色皮肤 `MENU`（明度阶梯 `page < slot < card < cardHi`），
   整个商店沉在近黑里，商品立绘（本身就是暗色霓虹原画）更跳不出来。
3. **资源不对**：立绘缺失的卡（属性卡 / 挂载卡 / 遗物卡）旧实现一律画一个"—"，
   等于**四类卡里三类是空壳**。

### 亮色皮肤 `BRIGHT`（`shared/theme.ts`）

明度阶梯与暗色皮肤**方向相反**：

| 皮肤 | 阶梯 | 关键约束 |
|---|---|---|
| `MENU`（暗） | `page < slot < card < cardHi` | 卡内凹槽**比卡面亮** |
| `BRIGHT`（亮） | `surface > card > slot` | **卡内凹槽必须比卡面暗**，否则亮色立绘跳不出来 |

| token | 值 | 用途 |
|---|---|---|
| `scrim` | `0x06121c` | 暗幕（半透明压暗，保留战斗画面作为背景上下文） |
| `surface` | `0xeef7fb` | 面板底（近白水青） |
| `header` | `0xd8ecf6` | 顶栏带 |
| `card` / `cardOff` | `0xffffff` / `0xf2f7fa` | 卡面实底 / 买不起的卡面 |
| `slot` | `0xdceaf2` | 立绘位（**比卡面深**） |
| `edge` / `divider` | `0x8fb9cd` / `0xc2dbe7` | 硬边 / 分隔线 |
| `accent` / `accentEdge` | `0x0fa8cf` / `0x0b7a97` | 主按钮 |
| 类型色 | 器械 `0x0e8fb5`、挂载 `0xc47a00`、属性 `0x7048cf`、遗物 `0x0e9b8e` | 与暗色皮肤同源，保持一致 |

配套文字色 `TXT_LIGHT`：`main #0d2b3a` / `dim #43647a` / `mute #7d97a8` /
`accent #0a7d9e` / `warn #cd3f66` / `good #0e8f7a`。

> ⚠️ **换底色必须同时换文字色**。只换底会得到"白字白底"。
> ⚠️ 新导出名 **`BRIGHT` 不能叫 `LIGHT`** —— `shared/index.ts` 是 `export *`，
> 而 `gameData.ts` 已有 `LIGHT`（关卡光照），撞名直接红 `TS2308`（已知坑 #23）。

### 版式规格（面板宽 **700**，设计分辨率 1304×749）

| 项 | 值 | 依据 |
|---|---|---|
| 面板宽 | `700` | 3 张卡各 204 + 2 道 18 间距 + 2 道 26 内边距 = 700，正好整除 |
| 卡宽 / 间距 / 内边距 | `204` / `18` / `26` | 同上 |
| 顶栏高 / 底栏高 | `56` / `56` | 与卡高 292 的 1:5 关系，视觉上不抢戏 |
| 卡高 | `292` | 容下"键帽行 → 立绘槽 84 → 名称 → 描述 → 状态行 → 代价行 → 价格 → 按钮" |
| 立绘槽高 | `84` | 商品立绘是 1:1 或 4:3，84 是"能认出来"的下限 |
| 对比手段 | **实底 + 硬边** | 亮色面板**不靠发光**给对比（发光在浅底上只会脏） |

### 卡内结构（自上而下）
`键帽 1/2/3 + 类型标签 + 锁定按钮` → `立绘槽` → `名称` → `描述` → `状态行`
→ `遗物代价行` → `价格` → `购买按钮`。

### 立绘缺失时的**代码图形兜底**（核心修复"资源不对"）

| 卡类型 | 兜底图形 | 实现 |
|---|---|---|
| 器械 / 武器 | 武器形状签名图标 | `weaponIcon(wid, cx, cy, 24)` |
| 挂载 | **座圈俯视示意图** | `mountDiagram(cx, cy, id, boxH, w)` —— **与 `DiveGame.drawTurret` 共用** `SEAT_ANGLES_DEG / SEAT_RING_R / TURRET_R`；新解锁位闪琥珀环 |
| 属性 | 形状签名 glyph + **进度条** | `statGlyph(k, cx, cy, s, col)`（11 种）+ `statGauge(cx, cy, id, w)`（浅色=买后到哪、深色=现在，含"12% → 24%"） |
| 遗物 | 遗物图标 | `relicIcon(relicId, cx, cy, 20)` |

> `cardWeaponId(up)` 与 `cardArtKey(up)` **共用同一套映射**，避免"有图时一个 id、没图时另一个 id"的漂移。

### 其他
- **文本截断**：Label 是池化的，取真实宽度要等一帧 —— 故用 `estWidth()` 估算
  （CJK ≈ 字号，ASCII ≈ 0.6×字号）+ `fitText(s, size, maxW)` 截断补"…"。
- **按钮皮肤系统 `BtnStyle`**：`button()` 新增第 7 参 `o`，**缺省完全等于原暗色行为**
  （老调用点零改动）；新增 `BTN_LIGHT_PRIMARY / _SECONDARY / _DISABLED / _TINY / _LOCKED`。
- `scrim(alpha)`（半透明）与 `pageFill()`（不透明）**是两个函数，别混** —— 混用就是"太大"的成因。
- `brightPanel()` = 实底 + 硬边 + 上缘高光 + 顶栏带（圆角矩形 + 方角补块拼），**不加投影**。

## 2. 发射物与打击特效 —— 已移植

规格出处：`docs/美术资源计划.md` §15.4「子弹强化」。

### 2.1 子弹三段式

| 层 | 作用 | gun（速射） | torpedo / harpoon（慢速重弹） |
|---|---|---|---|
| ① 拖尾 | 速度感来自**长度梯度**，不是长度本身 | 4 层递减线段：第 i 层 `L0=10+7i, L1=L0+8`，线宽 `3.4−0.7i`，α`0.9/(i+1.4)` | **气泡尾迹**（水里跑的不是焰火）：5 颗，步距 7px，半径 `3.2−0.42i`，α`0.5/i`，横向正弦摆动 `wob = sin(t*9 + 1.7i) * (1.6+0.5i)` |
| ② 外发光晕 | 保证深色层也发光 | 双层同心：`r=6.5` α0.22 + `r=3.6` α0.40 | 单层 `r=9` α0.20 |
| ③ 亮核 + 本色环 | 弹头是全屏最亮的东西之一 | 本色环 `r=2.6` 线宽 1.6 + **纯白核** `r=1.7` | 弹体轮廓（尖头 7 / 身尾 8 / 半宽 3.4 / 尾翼外扩 2.6）+ 暗色填 α0.55 + 头部白点 `r=2.3`，偏移 `+4px` |

**配色**：`gun` = `UI.amber`、`torpedo` = `UI.danger`、`harpoon` = `UI.jade`（鱼叉走同一套弹体轮廓，只换色）。

### 2.2 枪口闪光（新增）

| 项 | 值 | 为什么 |
|---|---|---|
| 位置 | **炮口**（与弹的出生点重合） | 喷在机体中心会看不出是**哪台武器**开的火 |
| 形态 | 朝弹道方向的**锥形亮弧 + 中心白核** | 一记圆点读不出方向 |
| 尺寸 | 锥长 `7 × (1.6 − 0.6k)`，锥口半宽 `7×0.62`，白核 `r=3.5` | 与 web 逐值一致 |
| 颜色 | 白 α`0.85k`（锥）+ 本色 α`0.55k`（核） | — |
| 时长 | 0.11s | 够短才有"爆"的感觉 |
| 附加 | 3 颗朝弹道 ±0.35rad 的小火星，速度 70–160，寿命 0.16s | 让"火力从这出去"更实 |

### 2.3 命中火星（改）

| 项 | 值 |
|---|---|
| 迸溅 | 沿弹道**反向扇形 ±43°**（不是全向散 —— 全向散读不出打击方向） |
| 数量 | 普通 4 颗 / 暴击 6 颗 |
| 速度 | 110–300 px/s |
| 阻尼 | **水的阻尼** `v *= 1 − 3.4·dt`（很快就停，不像太空里的火花） |
| 形态 | 沿各自飞行方向拉成**短条**（"溅"不是"点"），长度 `4 + 2.2·size·k` |
| 寿命 | 0.24s（暴击溅射 0.42s） |

### Cocos 落地要点
- 子弹画在 `gEnt`（**鱼贴图之上** —— 玩家攻击必须看得见）。
- 枪口闪光 / 命中火星画在 `gFront`（全场最高层）。
- `Spark` 结构**必须有 `ang` 字段**：缺了它，锥形亮弧和短条都会退化成"圆点"。
- 每层发光**必须重新组一遍路径**（Cocos `Graphics` 在 `fill/stroke` 后不清路径，见已知坑第 15 条）。

## 3. HUD 精细化 —— 已落地（2026-10-13）

出处：`docs/UI规格_赛博霓虹.md` §5.2–5.5、`docs/美术资源计划.md` §16.4。
实现：`cocos/assets/scripts/view/Hud.ts` 的 `drawCombat`（全部矢量，无新增资源）。

| 项 | 规格（已确认） | 落地状态 |
|---|---|---|

## 5. 落地形态（要你定一个）

当前架构是「**零 png、运行时矢量绘制**」。三种走法：

| 方案 | 底板 / 图标 | 动态条与冷却环 | 精美度 | 工作量 |
|---|---|---|---|---|
| **A 全矢量**（现状） | 继续用 Graphics 画 | 矢量 | 中（受限于 Graphics 无渐变/无模糊） | 最小 |
| **B 混合**（推荐） | 九宫格贴图 + 图标 png | 保持矢量动画 | **高** | 中 |
| **C 全贴图** | 连血条底槽、按钮都九宫格 | 也贴图 | 最高 | 最大 |

**推荐 B**：图标与面板这类**静态、需要细节**的走贴图；氧气条脉冲、冷却环这类**需要逐帧变**的保持矢量 ——
两者在 Cocos 里正好是两个渲染批次，互不干扰，也避免"每帧重画一堆九宫格"。

### 若走 B 的引擎落地参数（Cocos Creator 3.8.x）

| 项 | 写法 |
|---|---|
| 九宫格 | `SpriteFrame` 上设 **`insetLeft / insetTop / insetRight / insetBottom`**（四值**具名**，顺序是「左 上 右 下」；**Unity 是「左 下 右 上」，别照抄**）；`Sprite.type = SLICED` |
| 图集 | `AutoAtlas`，上限 **2048×2048**；按「HUD 常驻 / 弹窗 / 商店立绘」分三组（常驻的常驻内存，弹窗的用完可释放） |
| 图标导入 | 单色图标给 `Sprite` 上色：出**纯白 + alpha** 一张，运行时 `sprite.color` 染色 —— 12 个图标 × 3 档 = 36 张变 12 张 |
| 适配 | 设计分辨率 `1304×749`（已在 `settings/`）；`fitHeight` —— 本作是横向空间博弈，高度不能裁 |
| 字号 | **正文不低于 12px**（你本机桌面应用的既定下限），HUD 数值建议 14–22px |
