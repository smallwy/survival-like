## §1 背景图「冻结的鱼」

### 1.1 现状实测（`cocos/assets/resources/env/L*.png`）

| 带 | 文件 | 检出鱼（`measure_fish` 口径） | 条/百万px |
|---|---|---|---|

| L2 弱光带 | `L2.png` | 20 | 13.2 |

| L5 深渊带 | `L5.png` | 99 | 65.5 |

**五带全都有**，且玩家一眼看到的（L1 那条 40~90px 的鱼排）就是其中最显眼的一批。

### 1.2 为什么"假" —— 三条叠加

1. **背景图不滚动。** V6.56 §1 明确「远景（背景图）不滚 —— 它没有可滚的特征」。
2. **V6.70 的补丁只能整图平移。** `stepBgDrift()`：Lissajous ±26px / 周期 31s·47s
   ⇒ 横向峰值速度 ≈ **5.3 px/s**，扫过 1304px 要 **4 分钟**；而且**全图所有鱼同速同向**。
   ⇒ **"一群鱼整齐划一地滑过去"本身就是不自然的** —— 真鱼群是各自摆尾、有松紧的。
3. **位图救不了。** 鱼既不能摆尾，也不能给单条做视差 ⇒ 无论图怎么动，读到的都是"照片在平移"。
   ★ 这正是**同一条被报第二次**（V6.70 已报过「背景图贴死的一动不动的鱼群 肯定是不合理的」）。

### 1.3 为什么「减密」没解决（本轮新发现）

`thin_fish.detect(fish_only=True)` 的口径是**细长小鱼**：

```
面积 8~1200 · 外接框长边 ≤90 · 长宽比 1.5~5.5 · 填充率 ≥0.20 · 环带平坦度 ≤0.45
```

在 L1 上实测（`detect()` 逐团统计）：

| 项 | 值 |
|---|---|
| 检出总数 | 169 |
| 其中 y<300（光柱带） | **135**（80%） |
| 其中 y>500（玩家可见的大鱼区） | 6 |
| 长边 ≥30px 的团 | **5**（玩家看到的是 20 多个） |

⇒ **它的"密度"指标不代表玩家看到的东西。** 所以 V6.69「减密到和参照图一致」之后，
玩家看到的鱼基本没少。⚠️ 这条对以后所有"背景减密"工序都成立。

### 1.4 方案（推荐 A）

**A（推荐）· 背景图去鱼 + 渲染层补远层**

| 项 | 规格 |
|---|---|
| 背景图鱼的密度 | **0**（判定：`measure_fish` 口径 ≤5 条/百万px，允许 2~3 个检出抖动） |
| 落地方式 | ① **重出图**：提示词主体句加「**画面中没有任何鱼、没有任何可辨认的游动生物**」（首选）<br>② 后处理：真图补洞会留极淡"水痕"（见对照图 AFTER），需人工精修 |
| 渲染层补偿 | `LAYER_ECO` 加一档**远层**：尺寸 **0.45×**基准（26→12px）、α **×0.5**、速度 **×0.35**、条数 = 现 `school` × **0.6**<br>⇒ 补回"画面里有生物"，且**全部会动** |
| 不需要动的 | 中景/近景海雪、敌人、探照灯 —— 它们本来就在动 |

**B · 只把补偿做掉，背景图不动** —— 不推荐：冻结的鱼还在，等于没回答用户。

**C · 重出可无缝滚动的 1536×1180 图** —— 不推荐：成本最高，且**鱼仍随整图刚性平移**，
不解决"假"；出血需求见 V6.56 §3。

> ⚠️ **交接**：背景图重出/后处理属**场景插画**（`cocos-game-artist`）；
> 本节给的是**结构规格 + 密度判据 + 渲染层补偿参数**。渲染层补偿（远景鱼群远层）归本岗。

### 2.6 本轮已落地（P3 = 压条，P4 = L1 也出）

**`Hud.ts`**：`layers` 入场卡整段替换为压条；常量 `BAND_X0/X1/Y/H = 24/1080/150/92`。
四条实现要点（都是"看着对、其实错"的位置）：

1. **不复制 `layerCardT` 的初值**：`world.ts` 里写 2.6，Hud 若再写一个 2.6 就是**第二份副本**
   ⇒ 用私有字段 `cardPeak` 记住本轮见到过的最大 `layerCardT`，滑入进度 = `cardPeak − layerCardT`。
   那边改成 3.0 时压条**自动跟着变**（写死的话只会静默错位，不报错）。
2. **同一个色要两份表示**：`lerpColor()` 返回 `0xRRGGBB`（`Graphics` 用），
   `Label` 收 `'#rrggbb'` ⇒ `edgeCss` 由 `edge` 派生，⛔ 不在两处各写一个字面量。
3. **右对齐走 `this.text(..., true)`**（内部把锚点设 1）—— 位置给**右边缘** `BAND_X1−22`。
4. **tip 过 `fitText(..., 690)`**：最长的 L2 tip 是 21 字 ≈ 273px，加机制 chip 后仍安全；
   但截断是必须的 —— 溢出会压到右侧的"氧耗"上，那是可见事故。

**`DiveGame.ts`（P5 垂直轻推）**：`XFADE_PUSH = 40` + `stepBgDrift()` 里按 `xfadeT` 推出偏移。
⚠️ **节点 y 是上为正**（`syncSub` 的 `ny = H − simY` 是同一套坐标）⇒ "新图从下方来"是**负**偏移，
写反了它就从上方掉下来，且不报错。安全性：纵向出血 ≈72px（`BG_BLEED` 1.07），
叠上 `stepBgDrift` 的 ±16 后 **56 < 72**。

## §5 工具事实（本轮踩到，记下来别再走回头路）

| 事实 | 说明 |
|---|---|
| ⛔ `thin_fish.py --keep 0` **什么都不做** | `thin()` 里 `if not drop or len(drop) == len(comps): break` ⇒ keep_n=0 时第一轮就 return。**该工具从不支持"全删"**，只支持"减到 N 条" |
| ⛔ `thin_fish.detect()` 严判**抓不到玩家看到的大鱼** | 见 §1.3。做"背景减密"时不能只看它的密度数字 |
| ⚠️ 对比度阈值 (`bg − gray > thr`) **分不开"鱼"和"光柱负空间"** | 直接当遮罩会把丁达尔光柱区抹成白云（遮罩占 6%）。必须回到**连通域 + 形状过滤** |
| ✅ 可用的去鱼口径 | 局部对比 `bg(11px 高斯) − gray > 5` → 形态学开运算 → 连通域 → 面积 60~4000 / 长边 ≤200 / 填充率 ≥0.34 / **y ∈ [30%, 72%]** → `thin_fish.inpaint()`（归一化卷积）迭代至收敛。见 `tools/preview_v681_env_fish.py` |
