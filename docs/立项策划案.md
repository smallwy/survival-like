# 幸存者（轻美术）· 立项策划案

> 文档版本：V1（已落地工程骨架）
> 一句话定位：一款**轻美术、高爽感**的幸存者类（Survivors-like）游戏，独立个人可做、美术依赖极低、可上 Steam。

## 1. 为什么是幸存者类
- 《Vampire Survivors》证明：**极简像素/几何美术 + 一个人**，也能卖出数百万份。
- 美术依赖极低：1 个主角 + 几何小怪 + 光效弹幕，零精细资源。本项目用"一张白色圆点纹理 + 着色"实现全部单位。
- 真玩法、有手感：移动 + 自动战斗 + 构筑（升级三选一），复玩靠 build。
- 独立个人 + Go 后端做云存档，正好满足"公司/家用电脑随时接手、进度不丢"。

## 2. 核心玩法循环
1. 单角色在程序生成地图上移动（WASD/方向键）。
2. 海量小怪从四周涌来，**自动攻击**最近敌人。
3. 击杀掉经验球 → 拾取 → 升级三选一（武器/属性）。
4. 单局限时（默认 15 分钟），撑到时间或阵亡结算。
5. Roguelike：随机刷怪、随机升级池、meta 解锁（后端存档驱动）。

## 3. 美术方案（刻意压低）
- 玩家、敌人、子弹、经验球：**同一张 `dot` 纹理**，仅颜色/大小/数值区分。
- 场景：纯色背景 + 相机跟随，无瓦片美术。
- 反馈：飘字 + 颜色，不用特效图。
- 后期若想换皮（如"三国皮肤包"），只换着色与文案，不动结构。

## 4. 技术架构
- **前端**：Phaser 3 + TypeScript + Vite（纯 Web，跨平台，`npm install` 即跑）。
- **后端**：Go（云存档 / 排行榜 / 配置下发），零第三方依赖，跨平台编译。
- **通信**：前端 `/api/*` 由 Vite 代理到 Go（`localhost:8080`），代码不写死地址。
- **数据**：存档为玩家进度 JSON；排行榜 Top100 JSON。生产可平滑换 SQLite/对象存储（接口隔离）。

## 5. 数值框架（详见 `数值框架.md`，可调参数在 `web/src/config/gameData.ts`）
- 玩家：HP 100 / 移速 220 / 起始武器手枪。
- 敌人：随等级 `hp = base + level*4`，速度固定；刷怪间隔随等级缩短。
- 经验：每级需求按 1.25 倍递增。
- 升级池：6 选 3（伤害/移速/攻速/血量/拾取/新武器）。

## 6. 后端 API
- `GET  /api/health` 健康检查
- `POST /api/save?pid=<id>` body `{data}` 云存档
- `GET  /api/load?pid=<id>` 取档（404=未存过）
- `POST /api/leaderboard` body `{playerId,name,score}` 提交成绩
- `GET  /api/leaderboard` 取 Top100

## 7. 可移植 / 共享设计（重点）
- 工程是独立 Git 仓库，相对路径优先，配置全走**环境变量**（`APP_PORT` / `APP_DATA_DIR`），绝不硬编码机器路径。
- 依赖锁定：`go.mod` + `package.json`，任意装了 Go/Node 的电脑 clone 即可构建。
- 运行时数据（`data/*.json`）已纳入 `.gitignore`，不污染仓库。
- 两台电脑流转：clone → `go run ./server` + `npm install && npm run dev`，进度走后端云存档自动同步。

## 8. 上 Steam 路线（后续）
- MVP 完成 → 接 Steamworks SDK（后端可托管云存档/排行榜，前端集成 SDK）。
- 定价建议买断 10–20 元（或 EA）。
- 预告片主打"低美术但超爽"的割草爽感 + 升级 combo。

## 9. 风险
- 品类已卷，**手感与数值曲线是命脉**，需反复调（先用脚本模拟胜率）。
- 美术虽低，"爽感"靠特效节奏，别做成纯黑屏白点。
- 后端云存档需做基础校验/限流，避免被刷。

## 10. 路线图
- M1（已完成骨架）：移动+自动射击+刷怪+经验升级+结算+后端 API。
- M2：更多武器/敌人与 Boss、关卡/波次、meta 解锁。
- M3：美术换皮选项、音效、Steam 接入、商店页与预告片。
