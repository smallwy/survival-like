### §1.2 阈值与依据（改这里必须同步改规格）

| 项 | 阈值 | 依据 |
|---|---|---|
| env 画布 | **1536×1180**（容差：宽不减、高 ±40） | V6.56 的 `scrollY` 机制**没有余量就滚不动**（旧图 cover 到 1304×835 后只剩 86px） |
| env 单张体积 | **≤0.8 MB** | L1 现 2.58MB，是其余 4 张总和的 3 倍 |
| env 亮度 | **≥6% 像素亮于 90** | 对渲染层的压暗系数留了约 50% 余量 |
| env 上下无缝 | 首行/末行逐列平均绝对差 **≤14** | wrap 时这两行相邻，差值大 = 一条可见横向硬边 |
| 敌人贴图长边 | **512** | `key_fish_bg.py --long 512` |
| 敌人重心 x | **40%~48%** | 头朝左。定性判据，±2% 实测噪声不判死；**>50% 才是真反向**（整场鱼会翻） |
| 立绘内容高度 | **占画布 86%**（±2） | `process_item_art.py` 的 `FILL=0.86` 作用在**高度**上，宽度按内容比例 contain |

### §1.3 一次判据校准的教训（**写进规格，别再犯**）

V6.58 §2.2 写"敌人贴图 **512×512 正方形**，高度不足用透明补齐"。**这条是错的**，本轮修正：

- `key_fish_bg.py` 的实际口径是 **保持内容原始宽高比、裁到内容、长边缩到 512** ⇒ 产出 **512×257 / 512×346 / 512×378** 这类非正方形；
- 若改成 512×512，主体只占画布中间一条 ⇒ 引擎按 `frameAspect`（来自 `originalSize`）铺顶点时，**显示尺寸会同比变小**（多了透明边），需要连带改渲染层的缩放 —— 换一张图引发一次渲染改动。

⇒ **新口径：紧贴内容、长边 512，不要求正方形。** `check_art.py` 的"包围盒须贴住至少 3 边"就是这条的自动判据。

### §2.1 逐带要求（**沿用 V6.58 §1.2，已确认部分不动**）

| 带 | 地形 | 光 | ⛔ 禁区 |
|---|---|---|---|

| **L2 弱光带** | 无底，或极远处一线模糊地形 | 只剩远处零星光斑 | ⛔ 同 L1；不许画近景岩壁 |
| **L3 午夜带** | 两侧暗岩壁（只作**剪影**） | 无自然光，生物荧光是唯一光源 | ⛔ 不许有"打亮"的岩面 |

| **L5 深渊带** | 近乎无地形 | 只有极稀疏发光点 | ⛔ 全黑（须留 ≥6% 亮像素） |

**关于"上下无缝"的正确做法**：是**内容自然延续**，**不是镜像**。
镜像会把 L1 的天光镜像到画面下方 —— 物理上错（水下不该有第二片天）。
⇒ 做法：上下 15% 区间画**中性水体纹理**（同色系的低对比絮状），不要在此区间放任何"舞台性"内容（光柱起点、地形、大剪影）。

|---|---|---|

## §2bis 背景生物陪衬：**与渲染层远景鱼群的分工**（别做重）

背景图里的海生物剪影是**静态**的（烘焙进图、随背景滚动），渲染层的 `gAtmo` 远景鱼群是**动态**的。
两者**同时存在**是对的（静态给纵深、动态给"活着"），但要守住分工：

| 项 | 背景图（静态剪影） | `gAtmo`（动态鱼群） |
|---|---|---|
| 运动 | 只有背景滚动 | 团游 + 摆尾 |
| 数量 | **少**（每张 3–8 团，最近层 ≤3 只） | 多（L1 最多 46 条） |
| 透明度 | 更低（烘焙在图里，天然被"雾"压） | `ATM_FISH_ALPHA`（L1 `[0.26, 0.44]`） |
| 抢眼度 | ⛔ **必须低于** `gAtmo` | 参照物 |
| 位置 | 集中在画面**中上部**（远处） | 全屏分布 |

⚠️ **判据**：如果背景图里的鱼"看着比游戏里的鱼还清楚"，就是做过了 —— **减淡、减小、减数量**。

**确认判据**（跑 `python tools/check_art.py env` 后看 L1 一行）：
画布 ≥1536×1140 · 体积 ≤0.8MB · 亮度 ≥6% · 缝 ≤14。

## §3 敌人贴图：3→10 种

### §3.1 先定四条原则（**先看原则，再看表**）

1. **同带同族** —— 同一带的敌人共享色系与体型区间 ⇒ 玩家读作"这一带的鱼长得像一伙的"。
2. **跨带异族** —— 换带必须**同时**变色系与**一个结构特征**（背棘 / 发光点 / 伞盖 / 短体 / 边光）⇒ 玩家读作"我下潜了"。
3. **同带内 2 种必须剪影可分** —— 深海会把亮度压掉，**颜色最先失真**（V6.62 铁律）。区分只能靠轮廓。
4. **每张头朝左、重心 40~48%** —— 渲染层靠 `scale.x = -1` 镜像到右侧。

基线的 4 张沿用现有文件（`armor` 需修正重心），新增 6 张。

**为什么 #9/#10 用"边缘光"而不是"更暗"**：L5 是深渊带，环境本身近黑。
若敌人也全黑 ⇒ **直接消失**（"没有敌人"也是失败 —— V6.55 远景鱼群配色就栽在这）。
⇒ 深渊的解法是 **近黑体色 + 冷白边缘光**：剪影靠那圈边光读出来，而不是靠体色对比。

### §3.3 三条硬约束（沿用 V6.58 §2.2，逐条都有理由）

| # | 约束 | 理由 |
|---|---|---|
| ① | **纯色底**（纯黑或纯绿），**不是透明底交付** | 抠底靠 `key_fish_bg.py` 的"从四边泛洪 + 色距紧容差"。⚠️ 判据是**与边缘采样色的色距**，不是绝对亮度 —— 中灰底（亮度≈128）的素材用亮度门槛会**一个像素都删不掉** |
| ② | **单个主体、居中、不与其他元素重叠** | 两个主体会让泛洪"桥"过去，抠出连体图 |
| ③ | **体积线索四条全给**：投影 / 侧壁 / 受光弧 / 暗弧，**光源固定左上** | 缺一条就"平"。直径 <32px 的零件加细节只是噪声 |

⛔ 禁止：文字 · UI 边框 · 底板 · 阴影面板 · 多个主体叠放 · **外溢光晕**（会让色距泛洪失守）。

### §3.4 接入方案（图齐后再改代码，**现在不要动**）

`ENEMY_TEX` 现在是 `Record<Kind, string>`，取不出"按带分皮肤"。建议加一张**稀疏覆盖表**：

```ts
/** 按带覆盖的敌人皮肤。key = `<kind>_l<层号1..5>`，**查不到就回退 ENEMY_TEX[kind]**。 */
export const ENEMY_SKIN: Record<string, string> = {
  swarm_l2: 'f_swarm_l2', swarm_l3: 'f_swarm_l3', swarm_l4: 'f_swarm_l4',
  drift_l3: 'f_drift_l3', drift_l5: 'f_drift_l5', dash_l5: 'f_dash_l5',
}
```

**为什么用"稀疏表 + 回退"而不是"每带一个长度 5 的数组"**：数组要填 5×4=20 个槽位，
没出的图得填 `null`，而 `null` 会在渲染层变成"没有贴图"（静默退回几何剪影，很难注意到）。
**稀疏表天然表达"这张还没出"，回退到基线是显式行为。**

⚠️ 新 key **必须同步登记进 `artPaths()`**（`shared/dive/artKeys.ts`）。
漏登记时 `verify_cocos.py` 的"美术完整性"阶段会把新 PNG 判为**"磁盘上有、但无 key 指向"的残留**，
直接 FAIL。反向（登记了但没出图）也会 FAIL —— 这道闸门是双向的。

### §4.2 雷族回改：从"五舱平铺"到"一个表盘"


**检查点**：大表盘 + 粗指针 + 引信旋钮 + 两处琥珀微光 → 「**它在倒计时**」的视觉直译，**不需要任何文字**。

**剪影为什么更好了**：原方案的顶面是"五个小舱平铺"（= 平的一片）；
新方案顶面是"**一个圆台**"。矮横圆盘 + 顶部单圆凸起 ⇒ 轮廓反而**更独特**，
而且与网族的"横长方"、诱饵族的"竖高球"对比更狠。

| 变体 | 相对基础的变化 |
|---|---|
| `mine_ch` 连锁雷 | 表盘变**并排两个**（横向拉长 1.4×），指针分别停在 1/3 与 2/3 —— "多个表一起走"= 链式 |
| `mine_o2` 氧气雷 | 表盘**上方加一对氧气瓶**（竖向加高），指针改**青色**（不是琥珀）—— 氧气雷是"回氧"不是"伤害"，**危险色不能用** |

### §4.3 网族回改：从"一团网兜"到"正在收紧的环"

**新增元件：四爪之间一圈向内收的环（不是蓬松的一团）**

`net` 基础（替换 V6.47 §4.2 的主体描述）：

```
主体是一个横长方形的网筒发射器。前端一个张开的**四爪抛网架**（四根向外斜张的粗壮爪臂），
四爪之间不是网兜，而是一圈**正在向内收紧的环**：可见**两条同心环索**与**十二条径向索**，
所有径向索都不是直线而是**带弧度的、正在向中心收口**的形状（读作"收拢中"而非"已张开"），
环心一个**金属收口环**，一条**绷紧的钢索**从环心连回筒身的绞盘。索体为深墨绿编织材质，
可见清晰的菱形网目纹理。筒身侧面一个卷网绞盘，手轮上绕着一根**绷紧的钢索**。
```

**检查点**：两条环索 + 十二条**带弧度**的径向索 + 收口环 + 绷紧钢索 → 「**套住并锁死**」。

**剪影为什么更好了**：原方案前端是"一团蓬松的网兜"（实心团）；
新方案前端是"**一圈环**"（空心）。横长方 + 前端空心圆环 —— 与雷族的"圆盘 + 圆台"完全不同。

| 变体 | 相对基础的变化 |
|---|---|
| `net_el` 电网 | 环索变 **3 圈**（更密），环上带**青白电弧短刺**（⚠️ 只在材质内部与轮廓线，**不许外溢光晕**） |
| `net_cv` 驯化网 | 环索变 **6 根触须状臂**（有生命感），向内卷曲 —— 比四爪更碎 |
