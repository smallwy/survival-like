### §2.1 通用硬约束（15 张逐条都适用，**已确认不动**）

| 项 | 值 | 依据 |
|---|---|---|

## §3 验收闸门（本轮新增，**可跑**）

`生物形状规格_V6.83.md` §5 的"36px 涂黑测试"到 V6.85 为止**一直是人眼看**的。
171 对人眼逐对比不可靠 ⇒ 已把它写成脚本（这是 UI 岗的图标家族一致性检查在敌人立绘上的同一条方法论）：

```bash
python tools/check_fish_silhouette.py              # 校验 + 出对照图
python tools/check_fish_silhouette.py --check       # 只列 FAIL
python tools/check_fish_silhouette.py --thresh 0.78 # 改阈值（改它必须同步改 §5 规格）
```

**判据**：裁到 alpha 包围盒 → **长边归一到 36px**（等比，抹掉尺寸差，只比形状）→ 两两算 **IoU**。
`IoU ≥ 0.72` ⇒ FAIL「36px 下可互换」。
（为什么 0.72 不是 0.9：实机是满屏 150 只 + 半透明 + 还在动，玩家不是在做逐像素比对。）

### §3.1 当前实测（2026-10-16，19 张 / 171 对）：**FAIL 9 对**

| IoU | 对 | 性质 | 修法 |
|---|---|---|---|
| **0.908** | `shard` ↔ `splitter` | 同族 A，都是小纺锤 | `shard` 改**碎形**（不规则三角，不是鱼）；`splitter` 的裂口要**断开**（露背景） |
| **0.873** | `kamikaze` ↔ `mimic` | 都是圆钝块 | `mimic` 必须有**尖角/不对称**（E 族），`kamikaze` 加**螺旋纹** |
| **0.862** | `mimic` ↔ `shard` | 同上 | 靠 `mimic` 的不对称解决 |
| **0.803** | `kamikaze` ↔ `shard` | 同上 | 同上 |
| **0.792** | `mimic` ↔ `splitter` | 同上 | 同上 |
| **0.774** | `armor` ↔ `splitter` | 跨族（B↔A），都是圆团 | `splitter` 的尖吻必须出来；`armor` 的六边形棱角必须出来 |
| **0.773** | `kamikaze` ↔ `splitter` | 同上 | 同上 |
| **0.760** | `armor` ↔ `shard` | 同上 | `shard` 改碎形后自然解决 |
| **0.735** | `lancer` ↔ `leech` | **D 族与 A 族撞了** | `leech` 的同心吸盘 + 环状分节必须真的分节（现在是一条梭形） |

⚠️ 本判据**刻意抹掉尺寸差**。实机还有第二个线索：半径（`ENEMY_BASE`）。
所以"形状撞了但实机尺寸差一大截"的对（如 `armor` r30 ↔ `shard` r12）危害**小于**"形状 + 尺寸都撞"的
（如 `shard` r12 ↔ `splitter` r21 —— 尺寸也接近，这才是真事故）。

## §5 切图 · 命名 · 图集 · 导入清单（本行，已核对）

| 项 | 规格 | 说明 |
|---|---|---|
| **命名** | `fish/<id>.png`（id 见 §2.2） | 与 `ENEMY_TEX` 的值去 `f_` 前缀一致；`artKeys.ts` 自动从 `ENEMY_TEX` 推导 |
| **切图** | **每张一整个文件，不切九宫格** | 敌人是整图缩放，没有可变边框 |
| **图集** | **不做 AutoAtlas**（现状：全仓无 `AutoAtlas` 资产） | 每张独立纹理。理由：19 张 × 512 长边，打进图集会因"最大尺寸 + 不同高度"造成大量空洞；且 `packable: true` 已开，将来要打图集**直接加一份 AutoAtlas 资产即可，不需要改图** |
| **纹理上限** | 长边 **512** | 实机显示 2r = 24–68px ⇒ 512 已有 7–21× 余量，足够缩放与高 DPI |
| **meta 口径** | **`trimType: "none"`**，`width/height = rawWidth/rawHeight = 画布尺寸` | ⚠️ 见 §5.1 —— 本轮修了 5 张 |
| **比例口径** | 渲染层一律用 **`sf.originalSize`**（不是 `rect`） | `art.ts:frameAspect` 已按此实现；`rect` 是裁剪后的，用它会静默缩尺寸 |

### §5.1 ⚠️ 本轮修掉的 meta 缺陷（**新发现，已修**）

审计 19 张 `.png.meta` 发现 **5 张 `trimType: "auto"`**（`swarm`/`dash`/`drift`/`armor`/`orbit`），
其余 14 张是 `none` —— **同一个目录两套口径**。

其中 `orbit` 是**真问题**：`trim = (184, 65)`，即 alpha 包围盒 270×251 / 画布 512×330
⇒ `rect` / `pivot` / `originalSize` 三个口径与其余 18 张都不一致，而**没有任何一处会报错**。
（另外 4 张 `trim = (0,0)`，与 `none` 视觉等价 —— 但口径必须统一，否则下一张谁都不敢保证。）

**根因是闸门盲区**：`gen_fish_meta.py` 的默认路径只遍历一份**写死的 `NAMES`**（14 个新名字），
5 张老图**从来没被检查过** ⇒ `--check` 一路报 "✅ 全部正确"。

已修：① 删掉 `NAMES`，默认**扫目录**（闸门要覆盖磁盘上的每一张，不是"我以为存在的那几张"）；
② 重跑后 19 张**全部统一 `none`**。`verify_cocos.py` 复跑 **7/7**。
