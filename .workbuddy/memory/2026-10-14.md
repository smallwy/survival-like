### 四条关键结论（可复用）

1. **"沉底淡出"是补丁，不是设计**。它当初就是用来遮 V6.42 的越界（艇半挂在柱外 78px）。

2. **"动力感"的主开关是速度差，不是气泡数量**。排气口跟着艇走，气泡若只比艇快
   0–28px/s（旧值 38–75 vs 艇峰值 47）⇒ 气泡**粘在艇上**，读作"一团气泡陪着它漂"。

   取 (76, 72) 斜下 —— 正下方 (0, 96) 会让 ② 失败。
4. **抽帧预览看不出连续动画的问题**，但**位移/速度/间距这类"时间上"的问题只有抽帧预览能看到**

### 五个可复用的判断

1. **`enemyAim(e)` 一个函数收下三个机制**：驯化网 / 诱饵 / 光墙本质都是"改写敌人寻路目标"。
   分散在各自的 update 里迟早互相打架。优先级写死 **内讧 > 诱饵 > 玩家**。
2. **`mkEnemy()` 工厂是被 TS 报错逼出来的**：给 `Enemy` 加三个控制字段时，
   手写两处对象字面量（`spawnEnemy` / `spawnBoss`）**只改了一处**，报 "not assignable"。
   抽工厂后新增字段物理上不可能只改一半。
3. **发现了两个重复真源**：
   - `WEAPON_NAME` / `WEAPON_FAMILIES` 在 `codex.ts` 与 `unlocks.ts` **各有一份**，
     加三族时只改一份 ⇒ TS 报 "missing properties"。**重复定义的真实代价是"每个新增项都要记得改两处"**。
   - `SimEvent` 里有两个 `muzzle` 定义（加字段时没删旧的）⇒ 联合类型把 `fam`/`power` 变成可选，读取时报"属性不存在"。
4. **"施法感"的解法不是"开火时多画点"，是"让开火有预告"**：
   新增**前摇蓄力环**（`ivLast ≥ 1.4` 的武器，开火前 28% 窗口画 36→9 向内收拢的双环）。
   进度**直接读 `weapon.timer / ivLast`** —— 模拟层不需要维护第二份"正在蓄力"状态。
   ⚠️ 不能走 `pushShock` 池（每帧 push 会挤爆 `SHOCK_CAP`，症状是打击特效**整体消失**且不报错）。
5. **特效分化要分"形状语汇"而不是"图元数量"**：每条新分支与原来**持平或更省**。
   靠加粒子做区分会在满屏 100+ 敌人时糊成一团 —— 那正是"特效不够"的另一种表现。

## 推送到 GitHub：分叉合并 + push 挂掉的真实原因（19:47）

用户问「你做的东西确定提交到了 github 吗」——**答案是没有**。本地 `cocos` 有 8 个提交只在本地。

### 三条可复用的结论

1. **"git commit 了" ≠ "上了 GitHub"**。本次本地领先远端 8 个提交（V6.43 → V6.47），
   远端还停在 `27964e4`。以后交付口径应写「已 commit `xxx`（**未推**）」或「已推送 `origin/cocos`」，

## V6.51 水域光照与生态（用户否掉「越深越黑」，要求有光有鱼有色彩）

用户原话：「水域带有游戏色彩吧 / 至少能产生鱼群吧 / 太黑了 应该要有光吧 / 能够看见生物 水体物质 / 类似潜水 / 也不是完全漆黑 / 发挥下想象 在游戏里怎么创新设计」

### 病根（PIL 量化五张 env 图，**不是感觉**）

| 图 | 均值亮度 | 峰值 | 近黑(<22) | 亮(>90) |
|---|---|---|---|---|
| L1 | 86.8 | 216 | 0% | 39.9% |
| L2 | 63.5 | 102 | 0% | 10.6% |
| **L3** | **21.6** | 104 | **79.4%** | **1.2%** |
| L4 | 42.9 | 181 | 8.4% | 2.4% |
| **L5** | **14.6** | 104 | **89.5%** | **0.4%** |

叠加压暗 `(1-vis)*0.42` + 暗角（L5 = 0.81）⇒ **L5 屏幕中央实际亮度 ≈ 9 = 黑屏**。
三条结构病根：① tint 阶梯是「去饱和到黑」 ② 全链路没有任何光源 ③ 背景层只有背景图+海雪两个元素，**看不到任何活物**。

### 核心原则：**光的主权转移**（不是「越深越黑」，是「每带换一个光的主角」）
L1 太阳 → L2 残光+探照灯登场 → **L3 生物荧光** → **L4 热泉自身** → L5 探照灯+呼吸点阵。
**关键反转：L4 热泉带比 L3 亮**（物理成立、玩法上打破单调递减的节奏疲劳）。
**关键区分：提高对比度 ≠ 提高环境亮度** —— 均值可以低，但必须有亮点。

### 可验收红线（本轮唯一硬指标）
**每张 env 图必须 ≥6% 像素亮于 90。** 现状 L3=1.2% / L5=0.4% 都不合格。
（均值低 + 有几处亮 = 「黑暗中有光」；均值低 + 无亮点 = 「一团黑」。）

### 新增节点 `gAtmo` —— 层序是最大的坑
现有：`gBase → bg → gBg → gVeil → gBack → fishLayer → gEnt → sub → gPlayer → gFront → hud`
**`gVeil`（压暗+暗角）在 `gBack`（实体）之下** ⇒ **光照层必须插在 `gVeil` 与 `gBack` 之间**。
插在 gVeil 之下 = 光被自己的压暗层吃掉（白工）；插在 gBack 之上 = 盖住敌人（战斗可读性崩）。

### 六个元素 + 图元预算
鱼群剪影(全带,18-42) / 探照灯(L2+,6) / 能见度雾(全带,8) / 光柱(**仅L1L2**,18) / 荧光群(**仅L3**,36) / 烟柱(**仅L4**,27) / 点阵(**仅L5**,78)。
**后四者按带互斥** ⇒ 最坏 L5 = ~105 图元 ≈ **+9.5%**（V6.48 基线 ~1100）。硬上限 130，带 `ATMO_QUALITY` 三档降级。

⚠️ **可读性红线**：远景鱼群**绝不给 2px 发光核心**（敌人有，那是定位铁律 DiveGame.ts:563-568），
alpha ≤0.35、尺寸 ≤敌人 0.6×、不可瞄准、不碰撞 —— 否则玩家朝打不到的鱼开火。

### 四个创新点（把光照变成玩法）
1. **探照灯 = 双向暴露** ★最大创新：光让你看得见，也让你被看见。`LAMP_R` 越大 → 雾外能见度越大，但趋光生物生成概率越高（`attractR = LAMP_R × 2.2`）。可做成武器位/遗物 = 一次真实取舍。**v1 只做视觉，吸引机制挂 P1。**
2. **光的颜色 = 情报语言**（零学习成本）：青绿=鱼骨 / 紫青链=生物荧光 / 橙絮=热泉 / 冷白=你自己 / 白点阵=深渊。复用鱼骨既有的「发光=值得」读法。
3. **深渊的呼吸**：L5 点阵全场同步明灭 3.2s（与主循环 14.4s 取非整数比 4.5）⇒ 极低成本制造「底下有巨大的东西」。
4. **温跃层扫带**：换带时一条波纹带从下往上扫过 0.6s，扫过处色相瞬切 —— 与 V6.50 的 2.0s crossfade 叠加（图慢慢化，气氛被「扫」过来）。**只 3 图元，性价比最高。**

### 其它
- **能见度靠「雾」不靠「黑」**：雾是同色（取当前带 tint），不是黑雾。**「亮的暗」vs「暗的暗」** —— 浑浊读作「看不远」（潜水感），黑幕读作「我瞎了」。
- ⛔ 一律**同心环带**，禁用径向渐变（项目既有教训：渐变反复叠加成死黑）。
- 交互光反馈（§6）：开火/爆炸/拾取时环境亮一下 —— 解决「战斗与背景两张皮」。
- tint 重定：**L3 0x14203c→0x352f6b（青紫）/ L4 0x3a1a10→0x7a3a16（橙红饱和）/ L5 0x0a0614→0x1a1740（靛蓝，不是黑）**；tint alpha 0.10→0.16。
- 压暗 `(1-vis)*0.42→*0.24`、暗角 `0.16+(1-vis)*0.72 → 0.10+(1-vis)*0.42`；vis L3 0.40→0.68 / L4 0.25→0.60 / L5 0.10→0.46。

## V6.51a 介质决定（不做视频）+ 俯视下潜的四个读出通道

用户追问：「我要的是往下游的感觉 / **这个不是要做视频么** / 还是怎么设计 / 还可以看到

### ① 介质定死 = 引擎内程序化，**不做视频**
四条否决理由（任一成立即否决）：深度连续性（视频锁死，不能跟 `depthM` 走）／
可被玩法驱动（探照灯半径、下探节拍、连杀加速、换带全都动不了）／循环（视频首尾必须无缝）／
体积与分辨率（10s 1080p≈8-15MB 且分辨率固定，本方案零新增资源）。
**核心**：深度是玩家行为决定的连续量 ⇒ 视频＝把画面换成"只能按片子节奏走的画面"。
⇒ 与现有海雪/鱼骨/特效用同一条管线（`Graphics` + 精灵池）。

### ② 俯视角度下「往下游」靠四个通道翻译（本轮设计主命题）
**俯视看不到"下"，"下"必须由别的通道翻译过来**：
| # | 通道 | 屏幕里长什么样 | 权重 |
|---|---|---|---|
| ① | **相对运动** | 悬浮物**向上掠过**（= 开车时路边景物向后跑） | ★★★ |
| ② | 换带 | 颜色/亮度/生物群整体换一次 | ★★ |
| ③ | 生物群变化 | 鱼群种类/大小/密度随深度换 | ★★ |
| ④ | HUD 深度计 | 左侧竖条游标下移 | ★ |

**现状缺的就是①** —— 海雪 `vy=-6~-20` 方向对但慢一个数量级、只有一层、无视差。
主修：`SCROLL_BASE` 46 px/s + 换波峰值 220（4.8×）+ 三层视差（视差本身就是深度线索）。

### ③「向下的海洋生物 + 周围的鱼群」= 生态两层
**俯视里唯一能表达深度的是大小 + 明暗**（近大亮 / 远小暗）：
- **远景剪影层**（深）= 你点名的"向下的生物"：小鱼群横游 / 深渊巨影，≤敌人 0.6×、alpha ≤0.35、
  **无发光核**、不可瞄准不可碰撞
- **同层实体层**（浅）= 现有敌人，带 2px 发光核
⚠️ 远景鱼群**绝不能带那枚 2px 发光核**（敌人定位铁律 `DiveGame.ts:563-568`），
破了它玩家会朝打不到的鱼开火。

```
SUB_D = 88（艇长） × HULL_H = 56（艇高） × SEAT_RATIO = 28/48
                        ↑ 48 × K = 28 ⇒ K = 28/48（±90° 两座压在高边缘）
```
验算：±90° 差 **0.2px** / ±30° 差 **0.8px** / ±150° 差 3.3px（塔盘半宽 8.8）。
⇒ 六座炮心全部"镶在艇缘"。**漏算不报错，只会看着"炮浮着"。**

### 五条可复用判断
1. **座圈投影在模拟层 ⇒ 改视角必须连它一起改**。`SEAT_RATIO` 从"俯视压扁率"改成"侧视高度投影"，
   六座炮自动落位 —— `SEAT_ANGLES_DEG` **一个数都没动**（web/cocos 共享数据）。
   只在渲染层做侧视 ⇒ 子弹从炮口旁边飞出来。
2. **朝向：镜像 > 旋转，且必须带死区**。`faceX` 用 `cos(aim)` 判左右、**死区 ±0.25**
   （否则玩家原地微调时艇身来回抽）。倾斜**留 v2** —— 机体倾斜而座圈（模拟层）不倾 = 炮脱离艇身。
3. **镜像只翻 x，不翻 y**。翻 y = 掉头时艇腹朝天（俯视时代"转 180°"的同款错误）。
4. **"上半壳受光"不能一次到位**。整块缩放 = "一块肥皂"；单层亮上半壳 = "贴了张亮纸"（硬水平边界）。
   正确写法 = **面（淡）+ 边缘光带（两级描边）**。
5. **剪影特征 > 轮廓微调**。88px 尺寸下"像不像潜水器"靠**指挥塔 / 尾舵 / 舷窗带 / 艉部推进器**。
   `--silhouette` 三档（88/66/44px）全通过。

## V6.55 实机反馈修正：四个**静默失效**缺陷（提交 `6240d42`，已推送）

用户实机截图四条 → 逐条定位后是**四个独立缺陷**，三条属"不报错、不崩溃、图上也有东西"。

### ① 背景的白色 = `gAtmo` 漏在每帧 clear 名单外
V6.53 新增的层只在**标题界面分支**与 `hideWorld()` 里 clear，**战斗中每帧清屏那行漏了**。
Graphics 是累积顶点 ⇒ 46 条鱼每帧叠加，几秒内连成铺满全屏的**横向白带**。
- 为什么是横条：鱼的 `vx` 水平；为什么边缘锯齿：椭圆身 + 三角尾叠加；为什么越看越多：时间。
- **铁规（补第 7 条）**：新增任何 Graphics 层，**第一件事是加进每帧 clear 名单**。
  本文件顶部那行 `gBase/gBg/gVeil/gAtmo/gBack/gEnt/gPlayer/gFront` 是唯一名单。

### ② 鱼全朝左 = 读了一个**从不更新的字段**
`drawEnemies` 用 `Math.hypot(e.vx, e.vy)` 算 flip/tilt；而 `world.ts` 里敌人位移是
**直接改坐标**（`e.x += nx*speed*dt`），`vx/vy` 自 `mkEnemy` 归零后**再没人写过**。
⇒ `spd` 恒 0 ⇒ `flip` 恒 1、`tilt` 恒 0 ⇒ **全场鱼水平朝左**。
- 修法：`Enemy` 加 **`fx/fy` 朝向单位向量**，`updateEnemies` 每帧写入（dash 冲刺阶段覆盖成 `dirX/dirY`）。
- **存"朝向"而不是"速度"**：蓄力/冲刺时位移会归零或突变，朝向不该跟着闪。
- ⚠️ **`e.vx / e.vy` 在本项目是死字段，任何地方都不要读它当速度。**

### ③ 方块鱼 = `frameAspect` 两处口径不一致
`art.ts` 取 `sf.rect`（**裁剪后**）而渲染设的是 `trim=false + CUSTOM + setContentSize`
（按 **`originalSize` 整张画布**铺顶点）⇒ 分子分母来自两张不同尺寸的图。
透明边少的 `swarm` 偏差小看着正常，透明边多的 `dash` rect 比例被裁成 0.55（实际 1.55）⇒ **拉成方块**。
- ⚠️ 这是 `Hud.putArt` **踩过的同一个坑的复发**，且 `art.ts` 原注释把因果**写反了**。
- **口径只有一个：凡是要拿素材比例，用 `originalSize`。**

### ④ 鱼情雷达 = 功能从来没做
用户**误把波次倒计时那个圆（写 27）当成了鱼情** —— 它其实是氧气条右侧的波次剩余秒数。
新增 `Hud.drawCombat` 的 `③b` 段：圆心 `(W−88, 164)`、外环 52、映射半径 44、
**量程 780**（> 屏幕半对角线 752 ⇒ 画面内敌人必在圈内；贴边的只可能"还没进来"）。
点色直接取 `e.color`（与战斗里那条鱼的核心色同源）；BOSS 大点 + 呼吸环。
⛔ **雷达点不给 2px 发光核**（那是"可瞄准敌人"的铁律）。
> **侧视画面管纵深，雷达管平面** —— 侧视看不到"四周"，缺一个就有一半信息是瞎的。

### 顺带修正：镜像会翻转旋转方向
节点变换是 **T·R·S**（先缩放后旋转）⇒ `scale.x = -1` 把**旋转的视觉方向一并翻转**。
`sp.node.angle` 必须写 `(-flip * tilt * 180/π)`，漏掉 `flip` = "朝右游的鱼抬着头往水底扎"。
基准：`Gfx.ang(a) = -a`、文件头约定 **`node.angle` 正值 = 视觉逆时针**、**sim 的 y 是向下**的。

### 远景鱼群观感重定（"白色"的另一半）
亮色椭圆（`0xbfe9ff` 系）在深海里读作**天上飘的云 / 落雪**。整组翻成**背光剪影**：
| 带 | 体色 | 逻辑 |
|---|---|---|
| L1 | `0x2b5266` 暗剪影 | 水亮 ⇒ 取暗一大截的同色系 |
| L2 | `0x5f97a2` 微光轮廓 | 水已暗 ⇒ 再暗就**直接消失**，只能略亮 |
| L3 | `0x74f2cc` **生物荧光** | 唯一亮的一带 |
| L4 | `0x8a6a48` 暖光轮廓 | 同 L2 |
| L5 | `0x33485c` 巨影 | 近黑水里唯一能读出的"一团灰蓝" |
- ⚠️ **第一版配色过度修正**（全给暗剪影）⇒ L2/L4/L5 的鱼在暗水里**看不见**。"没有鱼"也是失败。
- **第二个改动：成团**。旧版 `x=rand*W, y=rand*H` 独立随机 = 均匀点阵 = "雪花/星星"。
  改为分团（三角分布 + **同团同向同速**）—— **同样 46 条鱼，成团之后才读得出"一群鱼"**。

### 新增工具 `tools/preview_atmo.py`
复刻 `drawBg → drawVeil → drawAtmo` 的**合成结果**，5 带拼图 / 单层 / `--old` 对比。
**价值**：这一条已经不是"参数对不对"而是"合起来是什么" —— 上一版每个数值都合法、
合起来却是"飘白云"。**只有把合成结果画出来才看得见。** 第一版配色的过度修正就是它试出来的。

## V6.56 下潜滚动 + 换带三段式（提交 `48c9e86`，已推送）

V6.52 落地顺序**第 3+4 步**。前两轮把**朝向**改成了侧视，但**运动**没跟上 ——
背景图静止、颗粒 6~20px/s（**37~125s 才扫过一屏**）、换带**一帧硬切**。
玩家读到的是"贴着海底照片的平面上打转"，换带"像坐电梯"。本轮把运动补上。

### 四件事
| # | 内容 | 关键数 |
|---|---|---|
| ① | 下潜滚动 `scrollV`：爆冲 + 指数衰减 | 稳态 **46 px/s** / 爆冲 **220**（4.8×）/ τ **0.9s** |
| ② | 颗粒 + 远景鱼群接进速度场 | 近 **1.00×** / 中 **0.35×**；**L4 反向 `-0.62/-0.22`** |
| ③ | 温跃层扫带（底 → 顶） | **0.6s**，26 段正弦，头线/过渡带/余晖 3 层 |
| ④ | 双图 crossfade + 水压环 | 淡入 **2.0s**（< `descDur` 2.1s）/ 环 **0.9s** 3 圈 |

⛔ **模拟层一行未改**。`scrollV` 是纯表现量。

### 三个"看着对其实错"的点（已就地注释 + 入长期记忆）
1. **`beginXfade()` 必须在同帧 `syncBg()` 之前调**。`handleEvent('descend')` 在本帧 update 内、
   `syncBg` 在其后 ⇒ 那时 `bgNode` 上还是**旧图**，拷得到。挪后 = 拷到新图 = **没有过渡**，
   而且是"不报错、图也在"的静默失效。**这个顺序是靠调用位置保证的，极易被后来的重构破坏。**
2. **旧图压在上面淡出**（`bgOld` 在 `bg` 之上，255→0；新图在下恒满不透明）。
   合成 = `旧×a + 新×(1-a)` = 干净交叉淡入；两层各半透会**先暗一档再亮回来**（双重曝光）。
3. **删掉 `Mote.vy`** —— 速度改为每帧 `MOTE_MUL[带] × scrollV` 现算。
   逐条存速度的话，爆冲只能推快**新生成**的颗粒，屏幕上已有的那批还在按老速度走
   ⇒ "换带时整片水没一起动"。**回绕补双向**（L4 颗粒往下走，只判 `y<-4` 会堆成一条静止亮带）。

### 一处关键数字
`SCROLL_BASE = 46` 的依据：**16.3s 扫过一屏**（749px），一眼能看出在动、又不至于晕。
旧值 6~20 ⇒ 37~125s ⇒ 屏幕上真的读不出"在动"。

### 做不了的（诚实标注）
**背景图的"地形滚动"**：V6.52 §3.1 表里"中景地形滚 0.5×"指的是 env 图里的岩壁。
但现有 5 张 env 图是 **1536×984 的一整张定死全景**，cover 到 1304×835 后纵向**只剩 86px 余量**
—— 结构上无法自身滚动。必须等 §4.3 的 **1536×1180 + 上下边缘无缝**新图（**插画岗**）。
速度机制已就位，新图落地后接一个 `scrollY` 偏移即可。
（同理：`scrollY` 积分量本轮**故意没加字段** —— 所有消费者都按速度驱动，没有消费者就是死字段。）

`buildNodes()` 里 `this.mkWrapped('gBack', …)` **写了两遍**，第一个节点被第二个覆盖引用、
**永远为空**却一直挂在场景里。已删重复行 —— 渲染结果**完全不变**（空节点不产生绘制）。

### 三条可复用结论

1. **判据要落成数字**：横向 alpha 剖面（屏宽 20%~80%）的 `min/max` —— **>0.3 = 连续光幕，≈0 = 离散柱子**。
   不依赖审美。V6.64a 的"改对了"是我的错觉，**是数字否掉的**。
2. **⛔ 起伏绝不能用"再叠一层半透明形状"**：那样叠出来是**加法** `a₁+a₂(1−a₁)`，

3. **变色速率是个几何量**：`BEAM_COL_BOT` 从 `0x93cdf0` 改到 `0xcfe9fb`。
   原来按 `t0` 拉到 1/3 屏高就明显偏蓝 ⇒ 画面上是**一条横向色阶带**（不是"渐变"）。
   物理上这次变色要走完几百米水柱，一屏高度只该看出**轻微**偏暖→偏冷。

> 中间算得再物理，画面上也只是「一层带硬边的半透明色块」。

- **面光源**（天光，L1/L2）⇒ 判**全画面亮部占比**（L1 ≥40% / L2 ≥12%）；
- **局部/点光源**（荧光 L3 / 热泉 L4）⇒ 判**局部亮区**（存在 ≥2% 面积、p90 ≥110 的连通区），
  ⛔ 用全画面占比会**逼着把水体一起提亮**，那正是"段感消失"的成因；
- **稀疏微光**（深渊雪 L5）⇒ 判**对比与结构**（p50 ≤40 且 p99 ≥55 且微光点分布可辨），
  ⛔ 要求 6% 亮像素 = 要求"深渊带"不是深渊。

### 三、曝光补偿是**工序**不是调色

渲染层 `drawVeil` **吃掉一半亮度**（V6.59 实测 L4 40.5→20.1）⇒ env 图要按"被压暗之后"配曝光。
新脚本 `tools/brighten_env.py`：`out = 255·(x)^(1/g)`，**逐通道**。
选 gamma 不选线性增益：① 单调 ⇒ **色相不变**；② 白点保 255 ⇒ 荧光/热泉亮芯**不过曝成白块**。
本批：L2 `0.80`（压暗）/ L3 `1.45` / L4 `1.40` / L5 `1.35`。
