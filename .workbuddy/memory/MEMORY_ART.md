## 平台参数 · 皮肤 · 通用手法

  （`12/13/15/17/20/26`，档差 ≥2px），⛔ 不许再写字面量。**无 ttf/otf** ⇒ 层级只靠「字号 + 字色 + 描边」。
  图集 ≤2048²；九宫格四值**必须具名**（Cocos 左上右下；Unity **左下右上**；两者顺序相反）。
- 风格 = **深海霓虹 + 补质感**（青蓝 `#4fe8ff`），⛔ 不转手绘卡通。"要亮色"**只针对商店/弹窗**。
- 三套面板色：`MENU`（暗，菜单/作战 HUD；**凹槽比卡面亮**）/ `BRIGHT`（商店/弹窗，**中调 V8**；
  **凹槽比卡面暗**，近黑/近白都试过）/ `GLASS`（只给主界面；界分靠**顶部受光高光带**）。
  ⛔ 别借 `MENU.slot` 到深海整图。色值正文 `docs/UI规格_赛博霓虹.md` · `docs/UI落地清单_Cocos.md`。
- **养成线是纯数值** ⇒ 外观零变化；**解锁的可见回报只在机体上的 6 个孔**。
- 立绘/文字：① 立绘框与素材画布同比（**2:1**）② `Hud.putArt` 用 `sf.originalSize` 定比例
  ③ 飘字「字号小」常是表象，真因是**没描边**（必须加粗 + 深色描边）。
- ★★ **`item_<id>.png` 是"发射器"的唯一形象来源**（V6.78）：商店卡立绘槽、**座圈槽**、
  以后的任何入口都只能**引用这张图**，⛔ **不许各写一份矢量"像它的东西"** ——
  判据是「**同一个东西在两处必须长得一模一样**」（座圈返工三轮的根因就是这条被违反）。
  ⚠️ **作用域 = UI 槽位，不含世界层**（V6.79 补）：世界层炮座上的发射器**仍是矢量**
  （`DiveGame.drawEmitter`）—— 依据是**用户自己**：他看着世界层那句炮说
  「**脉冲机关枪是正确的**」，而枪族正是矢量。⇒ 36px 的世界对象与 80×40 的立绘窗
  **是两种媒介，不是"两处不一致"**。⛔ 别把这条判据套到世界层上，那会把用户夸的东西也判死。
  ⚠️ 两个回退表 `WEAPON_ART_FALLBACK` / `RELIC_ART_FALLBACK`（`artKeys.ts`）**是欠账清单**：
  出图后**必须删条目**并把图放进 `items/`，否则玩家看到的是**别人的武器**而管线一声不响。
  ✅ **2026-10-15 V6.77d 已全部还清**：42 张齐（含 3 机制武器 + 6 进化 + 4 遗物），**两表已清空**；
  总览 `docs/shots/item_art_sheet.png`（新 13 张 mean 148 / 旧 29 张 176，区间完全重叠 ⇒ 不是"两批货"）。
  ★★ **出图两条硬规矩**（V6.77d 踩出来的）：
  ① **"银白"必须写进"主体句"，不能只写在通用风格前缀里** —— 只写前缀时模型的"深海 = 暗色"先验会压过
  锚点（13 张全成**深灰做旧金属**，mean 30–126）；主体句加「明亮的高抛光银白色合金材质、整体明度高、
  干净新崭、⛔ 不做暗色做旧 / 锈蚀」⇒ mean **114–194**，一次命中。
  ② **image-to-image 改不动整体长宽比**（连出两版 AR 与基础图差 <2%）⇒ **要改剪影比例必须 text-to-image**，
  在提示词里**写死目标 AR**（`mine_o2` 0.79 / `lure` 0.54 / `lure_bo` 0.96 就是这么来的）。
  ⚠️ 族色（网 = 青绿 / 电弧 = 紫 / 回声 = 粉 / 酸 = 绿）会有意压低 luma **~30**，别当成"批次不一致"。
- **同心圆两种读法不能混**：**空心**（能见度雾）用环带；**实心**（探照灯/光晕）用同 α 由外向内叠。
  **硬边来自"半径突变的层"**（`r_i = R(1−i/n)^1.35`）；⛔ 内层分档 alpha = 靶环；⛔ 最外 2~3 层要淡入
  梯度，否则圆边界留一圈可见的圆周线。
- ⛔ **禁径向渐变、禁 ADD 混合**（Cocos Canvas 下 ADD 会变实心白块）。
- **预览脚本按"看得见的量"配，不按"函数"配**（复刻**合成结果**）—— 「每个参数都合法、合起来却错」
  只有合成图能提前发现。

## ★★ 状态 / 身份画在物体身上，⛔ 不围一圈线（V6.80 通则）

- 根因同**铁规 14**：**闭合 / 半闭合的亮色轮廓 = "UI 框"的语汇**（读作"贴上去的框"，不是"这东西正在
  发生什么"）。V6.80 用户三条（精英黄圈 / 定身青环 / swarm 蓄力环）**同一根因** ⇒ 正解 = 把状态

- ★ **声纳** = 三重同心波前 + 24 段声呐束；⚠️ **`p.maxR` 就是伤害半径 ⇒ 视觉必须画在真半径上**，

## env / 出图 / 光照

### 曝光补偿（工序，不是调色）

- `drawVeil` 吃掉一半亮度 ⇒ **素材要按"被压暗之后"配**。`out = 255·x^(1/g)` **逐通道**
  （单调 ⇒ 色相不变；白点保 255 ⇒ 亮芯不过曝）。
- 实值：env L2 `0.80` / L3 `1.62` / L4 `1.22` / L5 `1.35`；**机体 `2.0` + `--sat 1.15`**
  （⚠️ V6.77 从 `1.35` 提到 `2.0`：判据是**成品本体 p50 落在 90~100**。1.35 时实测 **61**，
  浅海背景 L1 的 p25 就有 74 ⇒ 开局读作"一块黑板"；2.0 后 **93**，1.9 档在深海发白 ⇒ 别再高）。
- ⚠️ **烘焙类改动（如开槽）必须排在「裁影之后、补偿之前」**，否则比艇身暗一档 = "贴了块黑胶布"。
- ⚠️ **"太黑"先分层归因**（一半在压暗层、一半在**素材本体**）；**点光源拉不动均值** ⇒ 必须重出图。
- ⚠️ **"上下无缝"只对无地形带成立**（`SEAM_SKIP={'L3','L4'}`）。

### 位图素材的固定工序（机体 `sub_hull`）—— 顺序是硬的

`prep_sub_art.py`：抠底 → 量躯干（**列高众数**）→ 各向异性缩放到 `88×56` → **裁影**（`HULL_OUTLINE`；
不裁就挂点飘）→ **削硬亮边** → **开槽** → **曝光**。⚠️ 三条顺序约束：削边**在裁影之后**（边界得先是最终
剪影）、**在开槽之前**（槽口那圈 ×1.30 亮边是"这里有洞"的主力，会被一起削平）；开槽**在曝光之前**
（用原像素乘系数画，要跟着过 gamma）。

- ★★ **AI 出图必然带一圈 rim light** ⇒ 沿剪影最外圈比内侧亮 **1.5~1.8×**，缩到实机读作「白色的划线」
  （用户报**三次**）。判据 **最外圈 / 内侧 ≤ 1.15**（`de_rim()`：削前 1.52× → 削后 1.08×）。
  削法**自适应**：最外 `r` 圈**只往下**拉向局部内侧 ×1.03（只削不补、色相不变），源域 `r=2` + 画布域 `r=4`；
  ⛔ **不改 alpha**（剪影 = 挂点基准，同 `bake_slots`）。⚠️ 与渲染层**无关** —— 那是另一层
  （挂载导轨已改**暗缝**；艏部探照灯白点/光锥在轮廓外 ⇒ 已删）。
- ★ **新基线：机体位图 = 侧视梭形 + 6 槽 + 不带硬 rim**（重出图时 `--derim-*` 默认开，⛔ 别关）。
- ⚠️ **归档必须跟真源走**（2026-10-15 踩）：根目录 `sub_hull_采用.png` 与 `_归档-…expose1.35.png`
  曾是**同一个文件**，而真源早已是 expose 2.0 那版 ⇒ 照 README 复现得到的**不是实机那张图**。
  换图后必须**同时**更新 `02_对齐成品/<新目录>/` 与根目录采用图，并记 md5。
- ⚠️ **交付对照图**用 `tools/ab_sub_rim.py`：**只有第 ① 行（原生 1.14× 躯干）的位图级差异看得出**，
  1× 实机合成几乎看不见（预览的 LANCZOS 把 1px 亮环抹平，实机是硬采样 ⇒ 实机比预览明显）。

### ★★ 世界层发射器：7 族硬件化（V6.79）

- 判据 =「**都是装在座上的零件**」，**不是**颜色好不好看。用户**两轮**说同一句话
  （V6.70「只有脉冲机关枪装在炮头上很适配」→ V6.79「为什么还有自己画的箭头这些」）。
  根因 = **生产方式的断层**：V6.70 只重做了 gun/torpedo 前端，V6.73 只补了全族共用机匣
  ⇒ **5 族前端一直是"线 + 实心圆"的符号**（机匣反而让断层更难看出）。
- **`metalTube()`**（`barrel` 的兄弟）= 唯一新增工具，唯一增强是**两端半径可不同**
  ⇒ 这才画得出**声呐的外扩喇叭**与**酸液的收细喷嘴**。⛔ `barrel` 别动（枪/雷/机匣三处共用）。
- 七族差别**全部落在剪影**：声呐 = **开口喇叭** / 回声 = **封死的厚盘**（这对曾经都是"一个圆"，
  正是必须靠剪影分开的一对）/ harpoon = **粗杆 + 亮箍 + 三根前张的齿** / arc = **两根收拢电极柱 + 球头**。
- ★★ **"只要前端收敛成一个尖，它就一定是箭头"** —— 鱼叉族**三版**才跳出这个字形
  （细线+V / 粗杆+实心三角 / 菱形叶+长倒须 全否）。解 = **前端分成多股**（叉），
  且**中央齿要伸得比两侧长**（否则 1× 外轮廓仍是 `—<`）。★ 同一条也解释了 arc 电极：
  `eR=s*0.075`（直径 3px）在 1× 下**没有受光带可读 ⇒ 全糊成黑条**，必须 `s*0.125`。
- ★ **验收尺度：结构看 6×，判据是 1×**（`EMITTER_SIZE=18` ⇒ 整台发射器约 36px）。
  1× 图才逮到"harpoon 仍是箭头"这个 6× 图上**看不出来**的问题。
  **这个尺寸下能读的只有剪影大形，任何"细"的语汇都是白写。**
- ⚠️ `draw_barrel` 的**默认值是旧样式**（`plain=False, no_ring=False`）⇒ 预览漏传就画出
  实机上**已删掉的黄口环**（"预览比实机差一层"的老坑，**V6.79 又踩**）⇒ 一律显式传
  `plain=True, no_ring=True`。⚠️ **对照图不许伪造历史**：BEFORE 行 gun/torpedo 必须画实机同款。
- 预览：`--emit7`（6× BEFORE/AFTER + 1×/2× 实机尺寸）· **`--combatmix`**（★ 6 炮位装 6 族，
  合成在真实背景上 —— 最直接验证"混装时还认不认得每门都是零件"）。

### 亮度判据（必须匹配"光怎么分布"）

| 光源类型 | 带 | 判据 |
|---|---|---|
| 面光源 | L1 / L2 | 全画面亮部占比 ≥40% / ≥12% |
| 局部点光源 | L3 / L4 | **峰值 + 面积双条件**：`p99 ≥130` **且** 亮部 ≥1.5% |
| 稀疏微光 | L5 | `p50 ≤42` **且** `p99 ≥55` |

⛔ 只判一项就会被"一个亮斑"或"一片灰亮"骗过。⛔ 强行提亮暗带 = 灰绿浑水 + 噪点，段感全丢。

### 图上减鱼 / 减物

**工具 = `tools/defish_env.py`（唯一真源，V6.82 重写）。** 旧 `thin_fish.py` 已废：
⚠️ `--keep 0` 什么都不做（`thin()` 里 `if len(drop)==len(comps): break`）⇒ **从不支持"全删"**。

- ⛔ **V6.81「减了跟没减」的根因 = 补洞半径，不在检出**：旧 `inpaint()` σ=8 的窗口里**仍全是鱼**
  （成片、间距 ~20px）⇒ 补出来还是鱼。★★ **通则：遮罩覆盖率与检出条数全"正常"时，问题往往在
  补洞半径，不在检出。**
- 正解 = **大半径归一化补洞**：`补色 = Blur(rgb·(1−M)) / Blur(1−M)`（σ=**18**、膨胀 **5px**、
  **只从未遮盖区取色** —— ⛔ 不许把鱼自身像素带进分母），多轮 `ROUNDS=4`。
- ⛔ **不要腐蚀 mask**：8 邻域腐蚀把 2~3px 鱼身**吃光**（目标区 2041px → 腐蚀后 **0**）。去噪靠
  **连通域特征**（面积 `AMIN..AMAX` / 长边 `≤SIDE_MAX` / 填充率 `≥FILL_MIN`），不靠形态学。
- **判定带按层给**：`BOTY={L1:.98,L2:.92,L3:.80,L4:.78,L5:.76}`、`TOPY=0.28` —— 旧版一刀切 72%，
  而 **L1 的鱼铺到 84%** ⇒ 底下那截从没进过判定。
- ⚠️ 三个坑：① **连通域统计必须向量化**（逐条 `np.where(lab==i)` 是 O(n·像素)，1.5MP 要几分钟 ⇒
  被超时杀；改 `bincount` + `np.minimum.at`/`maximum.at` 求 bbox，全五张 17.5s）；② **`thin_fish._label`
  的背景是 −1 不是 0** ⇒ `bincount` 前必须 `+1`，否则报 `list argument must have no negative elements`；
  ③ **一律从 `BACKUP` 原图跑**（否则二次去鱼 = 在已补过的图上再叠一层）。
- ⚠️ **判据单一真源**：`measure_fish.py` 复用 `thin_fish.detect()`；⚠️ **密度只能对 PNG 判**（webp 编码噪声会被当鱼）。
- ⛔ **`detect()` 严判的数字 ≠ 玩家感知**：L1 检出 169 条里 **135 条在 y<300**（丁达尔光柱碎斑），
  玩家看到的 40~90px 大鱼**长边≥30px 只有 5 个**。★ 这条解释了为什么 V6.69「减密到参照密度」
  没解决用户「底图有冻结的鱼」的报障。
- ★ **背景图不该有可辨认的生物**：位图里的鱼不能摆尾、不能分层 ⇒ V6.70 的整图慢漂
  （`stepBgDrift` ±26px / 周期 31s·47s ≈ 5.3px/s）只让**整群鱼同速同向**滑过，读作"照片在平移"。
  鱼只能有一个来源 = **会动的渲染层远景鱼群**（`LAYER_ECO.school`）。

### 出图两层判据

- **层一 · 背景图是"擂台"不是风景照**：中部必须**低对比空水**（⛔ 强对比 / 垂直边 / 密集高频），地形只放
  上/下边缘或远景（地平线压在下 1/3），背景鱼**必须比渲染层动态鱼更小 / 更淡 / 更少**。
  ⚠️ **"开阔"与"亮"天生矛盾** ⇒ 顺序「**定亮度目标 → 重出 → 补偿**」。
- **层二 · 这地方鱼会来吗**：① 有食物吗 ② 温度是危险还是舒适 ③ 画面里有生物吗。
- ⛔ **"发光"是极强的负向符号**（火 = 危险 + 高温 + 无生命）。
- ⛔ **热泉不发光，是矿物**：浑浊烟羽；"热"靠间接线索（不发光锈橙沉积 + 烟羽上翻 + 成排管虫）。

### 光照与生态（V6.51，推翻"越深越黑"）

- **光的主权转移**：L1 太阳 → L2 残光 + 探照灯 → L3 生物荧光 → L4 热泉 → L5 探照灯 + 呼吸点阵。
  ⚠️ **L4 比 L3 亮**；**提高对比度 ≠ 提高环境亮度**。
