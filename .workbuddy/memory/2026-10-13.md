### 真发现（本轮最值钱的几条）
- **`Camera` 没有 `zoom`**：Cocos 3.8 只有 `orthoHeight`，而它由 `Canvas` 组件托管。
  换成真 `cc.d.ts` 检查后立刻报 `TS2339: Property 'zoom' does not exist on type 'Camera'` ——
  之前手写桩里我自己写了 `Camera.zoom`，**检查通过的是我的假设而不是引擎**。
  改法：缩放 `WorldRoot` 节点（`setScale`）+ `setPosition(-z*camX, z*(camY-H))`，等价、不抢引擎状态。
  同步删掉 `Dive.scene` 与 `gen_cocos_scene.py` 里的 `cam` 序列化字段。
- **`node.angle` 逆时针为正**（引擎实现是 `Quat.fromAngleZ`），而 sim 角度是 y 向下顺时针为正
  → 必须写 `node.angle = -(aim*180/PI)`。符号搞反 = 潜航器朝反方向。
- **`col()` 被局部变量遮蔽**：`drawEnemies` 里写了 `const col = ...`，遮蔽了从 `Gfx` 导入的
  颜色构造函数 `col()`，报 `TS2349: Type 'Number' has no call signatures`。改名 `body`。
- **暗幕必须画在世界坐标**（web 铁律）：暗幕只压暗地形，敌人/气泡/玩家画在它之上，
  否则深渊层（可见度 10%）会把 gameplay 信息一起吃掉。用**18 环同心环带**
  `pow(1-i/18, 2.4)*strength`，每像素只画一次（径向渐变会反复叠加成死黑）。
- **`.webp` 的取舍**：`macro.SUPPORT_TEXTURE_FORMATS` 含 `.webp` 但那是**引擎运行时**格式，
  不等于**编辑器导入器**支持（沙箱无法验证）→ 统一转 PNG（0.37 MB → 3.6 MB，换零风险）。
- **web 版本本来就没有音效**：全仓无音频文件、无 `AudioContext` —— 音效不是移植缺口，是**新功能**。
  （更正了之前"未移植：音效"的错误记录。）

### 修掉的自己的坑：`cocos/.gitignore` 行内注释
上次写的 `/library/        # 资源数据库缓存……` **整行被当成一条规则**（**.gitignore 不支持行内
注释**），于是 `/library/`、`/temp/`、`/profiles/`、`/local/`、`/build/`、`/native/` 六条**全部失效**。
编辑器一打开工程，`library/`（36 MB）、`temp/`（3.6 MB）就成片进 `git status`。
（上一节写的"已 gitignore"是错的，此行纠正。）已改成注释独占行并逐条用
`git check-ignore -v --no-index` 验证命中。
**踩坑提示**：`git check-ignore -v <路径>/`（带尾斜杠）会返回 exit 0 且打印
`<file>:<空行号>:` —— 看似"已忽略"，实为空模式误报；**必须用 `git ls-files --others --exclude-standard`
或对不带斜杠的文件路径判定**。

## cocos 分支 · 修用户报的"启动黑屏" + "击杀处白三角"

用户报：「启动黑屏 启动失败了 之前体验 击杀之后的地方有三角形白框 并且没有击打 击杀特效」

### 黑屏根因：增量编译"解析失败不登记依赖边"的**死结**（本轮最大的一个）
证据链（全部来自磁盘上的产物，不靠猜）：
- `cocos/temp/logs/project.log`：`Module "../shared/dive/profile" not found for .../view/save.ts`
  → `Missing class: 7b3c90QTipPaJxRjS5qCxP0` → `Script ... attached to "Game" is missing or invalid`
  → 场景里的 `DiveGame` 组件挂不上 → **什么都跑不起来 → 全黑**。
- `packer-driver/targets/editor/resolution-detail-map.json` 里**只有 1 条** `__unresolved_1`：
  `save.ts → ../shared/dive/profile`。而 `import-map.json` 里 `profile.ts` **是有 chunk 的**。
- 时间戳对上了全部因果：`save.ts` 的 chunk 编译于 **12:44**，`profile.ts` 的 chunk 编译于 **12:45**
  —— 也就是说 12:44 编译 `save.ts` 时，`profile.ts` **还不存在于磁盘上**。

**机制（可复用的一条规律）**：Cocos 增量编译在"解析失败"时**不登记依赖边**。所以那个 importer
永远不会因为新模块出现而被重编译，它带着失败的 import 一直躺在缓存里。
**不对称性**：修改一个**已存在**的文件总会触发重编译（依赖边完整）；这个坑只出现在**新文件**上。
**解法**：改一下那个 importer 的**内容**（不是 `touch`），或删 `cocos/temp/programming` 全量重建。
**判据/留痕**：`resolution-detail-map.json` 里的 `__unresolved_*` —— 这是唯一的留痕。
（我改 `save.ts` 内容后，解析表从含 `__unresolved_1` 变成 `{}`，chunk 由 3701→4452 字节，
 时间戳 13:00 —— 修复在产物层面得到确认，这是本轮最好的一个反馈回路。）

**同时暴露的"假绿"缺口**：`verify_cocos.py` 当时报 **6/6 全绿**，因为它只看源码和 `.meta`。
→ 已补第 7 阶段「模块图自检」：① 静态扫 `assets/scripts/**/*.ts` 的相对 import 是否命中磁盘；
② 读编辑器解析表，**有 `__unresolved_*` 就红**。
扫描前必须**剥注释**——否则文档里做对照说明的示例代码（`import X from '...png'`）会被当成真 import
（itemArt.ts / subs.ts 各有一条，实测误报）。剥注释只剥块注释 + 整行 `//`，不动行尾（免得砍坏 `https://`）。

### 白三角：闪白时把贴图置空，掉进了矢量兜底
`drawEnemies` 原写法 `const sp = e.flash > 0 ? null : this.fishSprite(e)` —— 命中瞬间**藏掉鱼贴图**，
于是走 `else` 分支的 `fillTri` → **白色实心三角**。
（这条取舍是我自己写的，注释还写着"闪白这帧退回矢量白色剪影"——方向对、落点错：
 web 的矢量路径叠的是**白色椭圆**，贴图路径用 `setTintFill` **保留鱼形**。）

（与 Phaser `arc` 一致，y 向下、角度增=顺时针）。`cont=true` 时连线到弧起点，
用于"线+弧"复合图标（心形、回声弧）。

### 一、启动黑屏（真 bug，最贵的一个）
- 症状：编辑器里**全黑**，而 `verify_cocos.py` **7 阶段全绿**（假绿）。
- 根因：Cocos **增量编译在"解析失败时不登记依赖边"**。`view/save.ts` 于 **12:44** 编译，
  当时它 import 的 `shared/dive/profile.ts` **还没同步到磁盘**（12:45 才到）；
  解析失败 → 那条 import 边没登记 → `save.ts` 永远不会因"新模块出现"而重编译，
  带着失败的 import 留在缓存 → `DiveGame.ts` import 链断 → 场景组件 `Missing class` → 全黑。

- 修：改 `save.ts` 的**内容**（顺带加 `sys.localStorage` 不可用时的降级，`getItem` 也会抛）。
- **不对称性（关键）**：*修改*已存在的文件**总会**触发重编译（依赖边完整），
  所以这个坑**只出现在新文件上** → 顺序必须"**先落文件、再写引用**"。
- 堵漏：`verify_cocos.py` 新增**第 7 阶段「模块图自检」**（静态扫相对 import 是否命中磁盘
