## 1. 新增 `tools/dive_sim_bench.js`（本轮）

和 `dive_sim_smoke.js` 同一条链：`tsc` 编译 `shared/dive` → CJS → node 真跑。
每档 900 帧、预热 120 帧，世界状态钉死在 `wave` 相位。
含 6 场景对照 + 缩放曲线 + 尖刺归因 + 2 个热点单项 + 渲染耦合告警。

### 模拟层：离瓶颈还差两个数量级

| 场景 | 敌人 | 鱼骨 | 平均 | p95 | 占 60FPS 预算 |
|---|---|---|---|---|---|
| A0 空转 | 0 | 0 | 0.004 ms | 0.006 | 0.0% |
| **A3 ★ 红线** | **150** | **50** | **0.149 ms** | **0.243** | **1.5%** |
| **A4 ★ 红线 + 机制武器** | **150** | **50** | **0.093 ms** | **0.168** | **1.0%** |
| A5 超载 | **300** | 50 | 0.314 ms | 0.451 | 2.7% |

**严格线性**：每敌 **~1.0 µs** 恒定（25→300 敌全程不变），300 敌 ×6.67 vs 线性外推 ×6 —— **无超线性拐点**。

V6.46 新加的两条「按敌数伸缩」路径**实测无害**：`enemyAim()` 最坏（全员策反 k=n=150）= **0.053 ms/帧**
（实际通常 k ≤ 4，这是 40× 余量的上界）；`densestSpot()` O(n²) n=150 = **0.0034 ms/次**，且只在诱饵开火时调用。

尖刺（p95 0.14 → max 0.40 ms）**伴随实体数一点没涨** ⇒ 来自**分配 / GC**，不是子系统变重。**不必针对性优化。**

### ⚠️ 测到一个「假数」（必须记住的坑）

第一版在 0 敌人场景测出 **0.0005 ms**（快得离谱）。真因 = `updateWave` 的清波判定
（`spawnLeft===0 && enemies.length===0`）立刻成立 ⇒ phase 滑进 `shop`，而商店相位只跑 `updateBones`。
**压测必须把要测的那条分支钉住**（脚本里 `w.updateWave = () => {}`）。教训与铁规 #7 同源。

## 2. 真正的红线在渲染层

沙箱跑不了 Cocos，但**图元预算是静态可算的**（读码得出，非实测）。红线帧 ≈ **1100 个 `Graphics` 图元**：

| 渲染项 | 每单位 | 红线帧 | 出处 |
|---|---|---|---|
| **鱼骨** | **9**（3 圈辉光 + 脊柱 + 4 肋 + 头端亮核） | **450** ← **最大单项** | `DiveGame.ts:1772-1795` |
| 敌人（矢量兜底） | 2（fillTri + 2px 核心） | 300 | `DiveGame.ts:1944-1959` |
| 子弹 | 3–6 | ~100–180 | `DiveGame.ts:1824-1913` |
| 环境 / 波前 / 爆炸 / 玩家件 | — | ~150–250 | `gBack` / `gFx` / `gPlayer` |

⚠️ **150 敌恰好卡在两道阈值之上，是渲染最差的一档**：
`DiveGame.ts:954` `enemies.length > 120 → 返回 null`（全部关掉贴图、走矢量兜底）
＋ `DiveGame.ts:177` `FISH_CAP = 140`（鱼池都装不下 150 条）。
⇒ 只改一处没用，必须两个一起提。

**三条建议**（按性价比）：
1. **鱼骨辉光 3 圈 → 1 圈** —— 省 **100 图元/帧**，风险极低
2. **A/B 实测贴图 vs 矢量**（阈值 + FISH_CAP 一起提到 160）—— 方向**可能与直觉相反**：
   Cocos 同图集 Sprite 能合批，150 sprite 也许比 150 次 `fillTri`（各自建路径 + 全网格重建）更便宜
3. 深层 `lod` 再加一档 —— 若 ① 够用则不必

**没有代你动手**：`DiveGame.ts:1771` 注释写明「光晕不是装饰，是功能」——
它是"能捡"的唯一读法，改衰减 = 改设计，不是纯优化。**等你拍板。**
