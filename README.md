# 三国兵种幸存者 · 工程说明

一款**三国题材的幸存者类（Survivors-like / Bullet Heaven）**游戏：**Phaser 3 + TypeScript + Vite** 前端，**Go** 后端（云存档/排行榜/meta 解锁），为独立个人与跨设备协作设计，可上 Steam。

> 定位与市场判断、竞品矩阵、差异化路线见 **[docs/方向定位与差异化策略.md](docs/方向定位与差异化策略.md)**。
> 一句话：**不做"贴了三国名字的通用幸存者"，做"三国兵种战争"。**

## 三根差异化支柱

| 支柱 | 落地位置 | 说明 |
|---|---|---|
| **全冷兵器** | `gameData.ts` 的 `WEAPONS` | 短弓 / 连弩 / 铁蒺藜 / 强弩 / 亮银枪 / 回旋飞刀 / 青龙偃月 / 丈八蛇矛。**没有一件现代火器。** |
| **武将机制真的不同** | `gameData.ts` 的 `CHARS` + `GameScene.applyCharStats()` | 四个武将的**起始武器 / 生命 / 移速 / 被动**四项全不一样，不是"同一套数值换四个颜色"。 |
| **兵种相克** | `gameData.ts` 的 `Armor` + `WEAPONS[].vs` | 敌人带护甲（无甲/轻甲/重甲/骑甲），武器带克制倍率。玩家要**按敌潮换武器**，而不是无脑堆 dmg%。 |

### 武将

| 武将 | 定位 | 起始武器 | 生命 | 移速 | 被动 |
|---|---|---|---|---|---|
| 刘备 | 仁德 · 均衡 | 短弓 | 100 | 220 | 仁德：拾取范围 +70% |
| 关羽 | 武圣 · 重击 | 青龙偃月 | 120 | 195 | 武圣：每次击杀回复 3 生命 |
| 张飞 | 断喝 · 坦克 | 丈八蛇矛 | 150 | 185 | 咆哮：受击反弹 60% 伤害 |
| 赵云 | 龙胆 · 机动 | 亮银枪 | 90 | 265 | 龙胆：移速 +20%，无敌帧更长 |

### 兵种相克

```
短弓 / 连弩 / 强弩 / 回旋飞刀  →  克 轻甲
青龙偃月（重兵器）            →  克 重甲
铁蒺藜 / 亮银枪 / 丈八蛇矛     →  克 骑甲
```

克制的教学入口有两个，都不需要玩家读说明：
1. **敌潮播报**——每进入新阶段报出主威胁的兵种与护甲，并点名一件克制它的武器；
2. **伤害飘字**——克制时金色放大并标「克」，被克时灰色缩小标「被克」。

## 技术栈
- 前端：Phaser 3（游戏）、TypeScript、Vite（开发服务器 + 构建）
- 后端：Go 1.21+（标准库，零第三方依赖）
- 通信：前端 `/api/*` 由 Vite 代理到 Go（默认 `localhost:8099`）

## 环境要求
- **Go** 1.21 或更高（后端）
- **Node.js** 18 或更高（前端）
- 任意操作系统（Windows / macOS / Linux 均可，工程不含机器相关路径）

## 在两台电脑间迁移 / 共享
本工程是**独立 Git 仓库**，已规划可移植：
1. 在公司电脑：`git commit && git push`。
2. 在自己电脑：`git clone` 同一个仓库。
3. 两台电脑都执行下面"运行"步骤即可，进度通过后端云存档自动同步（同一 `playerId`）。

> 所有配置走环境变量，依赖锁在 `go.mod` / `package.json`，运行时数据不入库——clone 即跑。

## 运行（开发模式，前后端同时）
```bash
# 终端 1：后端
cd server
APP_PORT=8099 APP_DATA_DIR=data go run .

# 终端 2：前端
cd web
npm install         # 首次需要
npm run dev         # 打开 http://localhost:5173
```

## 如何改数值（策划向，不碰逻辑）
打开 `web/src/config/gameData.ts`：

| 表 | 作用 |
|---|---|
| `WEAPONS` | 冷兵器伤害/间隔/弹数/**相克倍率 `vs`** |
| `ENEMIES` | 敌人血量/速度/伤害/**护甲 `armor`**/势力 |
| `CHARS` | 武将定位/起始武器/生命/移速/被动 |
| `UPGRADES` | 升级池 |
| `WAVE_STAGES` | 波次节奏与敌潮构成（权重） |
| `BALANCE` | 兜底默认值（实际以 `CHARS` 为准）/经验曲线/单局时长 |

改完保存，Vite 热更新立即生效。详见 `docs/数值框架.md`。

## 美术说明

### 游戏内单位：程序化像素帧序列（主方案）
- 全部角色/敌人由 `tools/pixelgen.py` **程序化绘制**，不依赖外部素材。
- 每个单位画在同一张 **32x32 逻辑像素网格**上（硬边几何 + 1px 深色描边）；
  需要更大的单位（Boss）按**整数倍**放大整张网格，因此**所有单位像素块大小一致**。
- 帧规格：**3 方向（下 / 上 / 侧）× 3 动作（待机 2 帧 / 走路 4 帧 / 攻击 3 帧）**，合成 4 列 × 9 行。
- **武器是画进 sprite 的冷兵器**（`draw_weapon()` 的 `bow / guandao / spear / serpent / blade / club` 分支），
  不是外挂的图标。侧身攻击帧的武器前端坐标由生成器写入 `manifest.json`，子弹必定从武器口发出。
- ⚠️ 侧身攻击的**横向空间只有「握点 → 格子右缘」约 7px**。武器前端一旦超出就会被格子裁掉
  （历史事故：关羽/张飞/赵云的刀头齐刷刷被切平）。守卫脚本会断言枪口坐标落在格子内。
- 重新生成（改完配色/体型/武器后重跑）：
  ```bash
  python tools/pixelgen.py   # 产出 assets/pixel/*.png + manifest.json + docs/pixel-preview-*.png
  ```
- 配色、体型、武器类型集中在 `pixelgen.py` 顶部的 `HEROES` / `FOES` 两张表。
- 回归守卫：
  ```bash
  node tools/check_facing_applied.mjs
  ```
  断言「朝向/动作真的被 setFrame 贴到角色上」「sheet 尺寸与 manifest 帧布局一致」
  「`weaponById/enemyById` 的 id 真实存在」「相克系统真的接在伤害路径上」。

### AI 立绘：只用于静态展示
- 来源 `web/src/assets/portraits_raw/`（不入库），由 AI 生成的 chibi 立绘。
- 用途仅限**静态展示**：选人卡片、HUD 头像、Steam 商店页与宣传图。
- **为什么不用它做游戏内单位**：静态立绘不含动作信息，让它抬手/转身只能靠代码旋转缩放去猜，
  必然别扭（这是早期六轮返工的根因）。像素帧序列里朝向和抬手是**画出来的**，不存在推导误差。
- **Steam 发布要求**：商店页需勾选「AI 生成内容」披露。像素单位是程序生成、不涉及该披露。

### 表现层
- 玩家：走路 / 待机 / 施法三套帧动画 + 脚下扬尘 + 开火后坐（**整数像素位移**）。
- 敌人：朝玩家切换方向帧，按 `eid` 错开动画相位；**护甲不同的敌人剪影刻意拉开**。
- 打击感：伤害飘字（**同点连击自动错位**）、死亡碎片、击退、受伤红闪、枪口火光。
- HUD：武将名 + 被动、血条压数字、当前持有冷兵器、敌潮播报 toast。
