# 三国逐鹿 · 工程说明

一款**三国题材的幸存者类（Survivors-like / Bullet Heaven）**游戏：**Phaser 3 + TypeScript + Vite** 前端，**Go** 后端（云存档/排行榜/meta 解锁），为独立个人与跨设备协作设计，可上 Steam。

> 定位与市场判断、竞品矩阵、差异化路线见 **[docs/方向定位与差异化策略.md](docs/方向定位与差异化策略.md)**。
> 玩法与主线设计见 **[docs/核心玩法与主线规划.md](docs/核心玩法与主线规划.md)**，工程落地排期见 **[docs/项目计划书.md](docs/项目计划书.md)**。
> 一句话：**不做"贴了三国名字的通用幸存者"，做"三国兵种战争"。**

## 四根差异化支柱

一句话口径：**三国不是皮肤，是兵种、阵型、势力、计谋。**

| 支柱 | 落地位置 | 说明 |
|---|---|---|
| **势力**（谁在打你） | `gameData.ts` 的 `FACTIONS` | 6 势力：黄巾 / 西凉 / 河北 / 魏 / 吴 / 群雄。每个带 `countMul`/`hpMul`/`speedMul` **真实数值倍率** + `roles` 兵种映射 + `roster` 出阵权重 + `trait` 特性。黄巾人多而脆、西凉快而撞、魏硬得砍不动 —— **打三下就记住了，不用读说明**。 |
| **兵种**（用什么兵） | `EnemyDef.armor` + `EnemyDef.role` + `WEAPONS[].vs` | 双层：**护甲**（无甲/轻甲/重甲/骑甲，决定伤害倍率）+ **职能**（前排/中军/后排/侧翼，决定站位与行为）。12 个兵种，含顶盾减伤 30% 的**盾卫**。 |
| **阵型**（怎么摆） | `gameData.ts` 的 `FORMATIONS` + `spawnFormation()` + `driveEnemies()` | 6 种阵型，**五种真实行为**：`charge`（1.35 倍速冲脸）/ `advance` / `hold`·`fireline`（保持 230~280px 射程环并横向绕行）/ `encircle`（绕到玩家外侧 ±120px 包夹）。不是文案差异，是行为差异。 |
| **计谋**（你怎么破） | `gameData.ts` 的 `STRATAGEMS` + `castStratagem()` | 6 计，局内 **Q / E** 一键释放，20~28s 冷却 + 环形冷却指示：火计 / 空城计 / 缓兵计 / 十面埋伏 / 连环计 / 背水一战。**这是玩家唯一的主动操作**，也是"破阵"的正解。 |

### 关键设计：阵型是骨架，势力是填充

```
FormationDef.slots[].role   （骨架：front / mid / back / flank）
            ↓  由势力映射
FactionDef.roles[role]      （填充：具体兵种 id）
            ↓
spawnEnemy(def) + setData('behavior', 阵型行为)
```

同一套「锋矢阵」在**黄巾**是杂兵人海、在**西凉**是铁骑冲锋、在**魏**是盾甲精锐。
**6 势力 × 6 阵型 = 一张可组合的表，而不是 36 个手工关卡** —— 这是零美术成本的内容量乘法杠杆。

### 主线：6 章 × 3 关

| 章 | 势力 | 阵型池 | Boss |
|---|---|---|---|
| 一 · 黄巾之乱 | 黄巾 | 蜂拥 / 偃月 | — |
| 二 · 汜水关 | 西凉 | 蜂拥 / 锋矢 | 华雄 |
| 三 · 界桥之战 | 河北 | 鱼鳞 / 雁行 | 颜良 |
| 四 · 长坂坡 | 魏 | 方圆 / 鱼鳞 | 曹操 |
| 五 · 赤壁之战 | 吴 | 雁行 / 偃月 | 甘宁 |
| 六 · 白门楼 | 群雄 | 偃月 / 方圆 / 锋矢 | 吕布 |

- 三种关卡目标：`survive`（守时）/ `kill`（歼敌）/ `boss`（斩将）。
  超时未达成判「**未竟**」，与被打死的「**阵亡**」分开结算 —— 否则玩家会以为自己是被打死的。
- 每章一个**章节色调**（全屏低透明度色块，`chapterTint`，ADD 混合）：零美术成本制造"这一章不一样"的直觉。
- 首通奖励挂在「通关本章」上，由**后端权威解锁**（见下文 API），前端只做展示。
- 一屏式**备战界面**（帐前点将）：章节条 ◀▶ + 4 武将卡 + 6 计谋卡 + 出征。

内容量估算（详见 `docs/核心玩法与主线规划.md`）：主线一周目 ≈ 1.5h，4 武将全通 ≈ 6h，
6 计谋全通 ≈ 3h，meta 解锁 ≈ 2h，全成就 ≈ 4h —— **合计 ≈ 16 小时**。

### 兵种相克

```
短弓 / 连弩 / 强弩 / 回旋飞刀  →  克 轻甲
青龙偃月（重兵器）            →  克 重甲
铁蒺藜 / 亮银枪 / 丈八蛇矛     →  克 骑甲
```

克制的教学入口有两个，都不需要玩家读说明：
1. **章节报幕 + 变阵播报**——开局报出主威胁的兵种与护甲，并点名一件克制它的武器；进入新波次报出即将上阵的阵型与破法；
2. **伤害飘字**——克制时金色放大并标「克」，被克时灰色缩小标「被克」。

## 技术栈
- 前端：Phaser 3（游戏）、TypeScript、Vite（开发服务器 + 构建）
- 后端：Go 1.21+（标准库，零第三方依赖）
- 通信：前端 `/api/*` 由 Vite 代理到 Go（默认 `localhost:8099`）

## 环境要求
- **Go** 1.21 或更高（后端）
- **Node.js** 18 或更高（前端）
- 任意操作系统（Windows / macOS / Linux 均可，工程不含机器相关路径）

## 在两台电脑间迁移 / 共享
本工程是**独立 Git 仓库**，已规划可移植：
1. 在公司电脑：`git commit && git push`。
2. 在自己电脑：`git clone` 同一个仓库。
3. 两台电脑都执行下面"运行"步骤即可，进度通过后端云存档自动同步（同一 `playerId`）。

> 所有配置走环境变量，依赖锁在 `go.mod` / `package.json`，运行时数据不入库——clone 即跑。

## 运行（开发模式，前后端同时）
```bash
# 终端 1：后端
cd server
APP_PORT=8099 APP_DATA_DIR=data go run .

# 终端 2：前端
cd web
npm install         # 首次需要
npm run dev         # 打开 http://localhost:5173
```

## 如何改数值（策划向，不碰逻辑）
打开 `web/src/config/gameData.ts`：

| 表 | 作用 |
|---|---|
| `WEAPONS` | 冷兵器伤害/间隔/弹数/**相克倍率 `vs`** |
| `ENEMIES` | 兵种血量/速度/伤害/**护甲 `armor`**/**职能 `role`**/`guard`（盾卫顶盾） |
| `FACTIONS` | 势力标签 + **数值倍率**（`countMul`/`hpMul`/`speedMul`）+ `roles` 兵种映射 + `roster` 权重 |
| `FORMATIONS` | 阵型**骨架**：`slots`（dx/dy/role）+ `behavior` + `counter`（破法提示） |
| `STRATAGEMS` | 六计：`kind` / `cdSec` / 典故 |
| `CAMPAIGN` | 6 章 x 3 关：势力 / 阵型池 / 色调 / **首通奖励** / 每关目标与时长 |
| `CHARS` | 武将定位/起始武器/生命/移速/被动 |
| `UPGRADES` | 升级池 |
| `WAVE_RAMP` | 波次强度曲线（刷怪间隔 + 阵型出现概率） |
| `BALANCE` | 兜底默认值（实际以 `CHARS` 为准）/经验曲线 |

改完保存，Vite 热更新立即生效。详见 `docs/数值框架.md`。

> ⚠️ **改 `CAMPAIGN[].reward` 时必须同步改后端** `server/internal/handler/handler.go` 的
> `chapterRewards`（解锁判定必须在服务端才安全，前端改内存不能白嫖）。
> 守卫脚本会交叉比对这两张表，漂移就报错。

## 后端 API
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 健康检查 |
| GET | `/api/meta?pid=<id>` | 读取 meta：`unlockedWeapons` / `unlockedChars` / `unlockedStrats` / `clearedStages` / 统计 |
| POST | `/api/meta?pid=<id>` | 上报一局 `{score,kills,timeSurvived,won,stage}`，返回**同一形状**的 meta + `unlockedNow` |
| POST | `/api/leaderboard` | 提交成绩 `{playerId,name,score}` |
| GET | `/api/leaderboard` | 取 Top100 |

- 两个 meta 接口**返回形状一致**（都是扁平的 Meta 对象），前端不用记两套字段路径。
- `stage` 形如 `c2s3`（第 2 章第 3 关）。通关时上报，后端累加 `clearedStages` 并据此发放章节奖励。
- 所有切片字段都保证是 `[]` 而不是 `null` —— 否则前端 `for (const x of ...)` 会直接抛 TypeError（只在"新号第一次请求"时出现，本地难复现）。

## 美术说明

### 游戏内单位：程序化像素帧序列（主方案）
- 全部角色/敌人由 `tools/pixelgen.py` **程序化绘制**，不依赖外部素材。**这是刻意的低成本路线**：
  16 个单位（4 武将 + 7 兵种 + 5 Boss）全部由一张配置表驱动，加兵种 = 加一行配置。
- 每个单位画在同一张 **32x32 逻辑像素网格**上（硬边几何 + 1px 深色描边）；
  需要更大的单位（Boss）按**整数倍**放大整张网格，因此**所有单位像素块大小一致**。
- 帧规格：**3 方向（下 / 上 / 侧）× 3 动作（待机 2 帧 / 走路 4 帧 / 攻击 3 帧）**，合成 4 列 × 9 行。
- **武器是画进 sprite 的冷兵器**（`draw_weapon()` 的 `bow / guandao / spear / serpent / blade / club` 分支），
  不是外挂的图标。侧身攻击帧的武器前端坐标由生成器写入 `manifest.json`，子弹必定从武器口发出。
- 盾卫的**大盾**是独立绘制分支（`spec.get('shield')`），盾面/上沿高光/下沿压暗/盾心铆钉四层 ——
  让"硬骨头"这个势力特性有视觉载体，而不是只体现在数值上。
- ⚠️ 侧身攻击的**横向空间只有「握点 → 格子右缘」约 7px**。武器前端一旦超出就会被格子裁掉
  （历史事故：关羽/张飞/赵云的刀头齐刷刷被切平）。守卫脚本会断言枪口坐标落在格子内。
- 重新生成（改完配色/体型/武器后重跑）：
  ```bash
  python tools/pixelgen.py   # 产出 assets/pixel/*.png + manifest.json + docs/pixel-preview-*.png
  ```
- 配色、体型、武器类型集中在 `pixelgen.py` 顶部的 `HEROES` / `FOES` 两张表。

### AI 立绘：只用于静态展示
- 来源 `web/src/assets/portraits_raw/`（不入库），由 AI 生成的 chibi 立绘。
- 用途仅限**静态展示**：备战卡片、HUD 头像、Steam 商店页与宣传图。
- **为什么不用它做游戏内单位**：静态立绘不含动作信息，让它抬手/转身只能靠代码旋转缩放去猜，
  必然别扭（这是早期六轮返工的根因）。像素帧序列里朝向和抬手是**画出来的**，不存在推导误差。
- **Steam 发布要求**：商店页需勾选「AI 生成内容」披露。像素单位是程序生成、不涉及该披露。

### 表现层
- 玩家：走路 / 待机 / 施法三套帧动画 + 脚下扬尘 + 开火后坐（**整数像素位移**）。
- 敌人：朝玩家切换方向帧，按 `eid` 错开动画相位；**护甲不同的敌人剪影刻意拉开**。
- 打击感：伤害飘字（**同点连击自动错位**）、死亡碎片、击退、受伤红闪、枪口火光。
- HUD：右上角**关卡目标条**（章节·关卡 + 目标 + 「已 / 余」时间 + 进度条，右对齐避让左上角武将面板）、
  右下**计谋槽**（按类别区分形状的图标 + 环形成长冷却指示）、
  武将名 + 被动、血条压数字、当前持有冷兵器、章节/变阵播报 toast。
  **三档字号（F 键切换）下都有自动布局断言兜底**，见 `tools/check_objectives.py`。
- 计谋图标（`drawStratGlyph`）：火苗＝爆发 / 雪花＝控制 / 上箭＝增益 / 盾形＝格挡。
  备战界面的计谋卡用同一套形状，玩家在开打前就建立"形状 → 效果"的对应。
- 备战界面（帐前点将）：一屏完成章节 / 武将 / 计谋 / 出征；**整体按画布等比缩放**，
  小窗口下不会被裁；外层还有一层全屏压暗底，避免局内 HUD 从面板边缘漏出来。

## 开发工具

| 工具 | 用途 |
|---|---|
| `tools/verify_all.py` | **一条命令跑完全部验证**：静态守卫 → 类型检查 → 逻辑验证 → 真机截图。退出码 0 = 全绿。 |
| `tools/_devstack.py` | 前后端 dev server 的生命周期管理（**必须用它**，见下）。 |
| `tools/verify_shot.py` | 起前后端 → 跑 CDP 截图 → 收尾。 |
| `tools/shoot_game.py` | CDP 直驱无头浏览器：备战界面切章/选计谋 → 出征 → 走位 → 施计 → 截图，**并按秒采样血量/等级/同屏敌人数/阵型行为分布/计谋冷却**。调平衡靠读数，不靠眼睛。 |
| `tools/check_objectives.py` | 无头**逻辑**验证：三种关卡目标（通关/未竟/阵亡）、Boss 按时出场与斩将、阵型真的成形、六大计谋各自的效果与冷却、**HUD 三档字号下的布局自检**（目标条/进度条/计谋槽/底部提示是否互相压字或越界）。不用等满一局，一轮 50 秒。 |
| `tools/check_facing_applied.mjs` | 静态回归守卫：四支柱的**引用完整性**（势力 roles 指向真实兵种、阵型槽位 role 合法、章节奖励 id 真实）+ 真的接线（计谋有实现、阵型行为有分叉、buff 进伤害公式）+ 前后端奖励表一致。 |
| `tools/zoom_shot.py` | 放大截图局部（最近邻），用来核对像素单位细节 / UI 有没有压字。 |
| `tools/_console.py` | 抓浏览器控制台异常。画面"卡在初始态不渲染"时先跑它。 |

> **本机环境三个坑（都写进脚本了，换机器不影响）**
>
> 1. **沙箱会回收残留子进程**。`./server &`、`npx vite &`、`Start-Process`、`nohup`、
>    `CREATE_NEW_PROCESS_GROUP`、`DETACHED_PROCESS` **全都活不过一条命令** ——
>    表现是"探活返回 200，下一条命令就 502 / 连接被拒"。
>    所以服务必须由 `_devstack.py` 在**同一个进程周期**里起、用完就关。
>    （踩坑代价：曾因为"服务其实已经死了"跑出过一整轮假结论，26 条断言集体 FAIL。）
> 2. **`http_proxy` 把 localhost 也代理走**。`urllib` 连本地服务会被代理回 502，
>    看起来像"服务没起来"。脚本里显式清空了代理。
> 3. **无头 Chrome 的 `--window-size=960,800` 给的是「窗口」尺寸**，实际视口只有 944x649。
>    所以点击坐标**不能硬编码** —— `shoot_game.py` 改为按文字标签在场景里查控件位置。
>    （踩坑代价：十张截图内容完全相同、状态读数全是 t=0，因为点击全落在画布外。）
